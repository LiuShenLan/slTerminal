# slterm_terminal（core 层）

> 终端核心：网格、VT 解析、PTY 行为、输入编码、选择与回放、渲染快照；不依赖产品视图、窗口状态或 GPUI。

## 决策与红线

- **core 边界**：本目录只拥有 grid、VT、PTY、输入编码、回放和终端行为；不得依赖产品视图、窗口状态或 GPUI 组件。原因：终端语义必须能脱离 UI 独立测试。边界：不为 UI 需求在终端核心增加产品概念；确需新接口时公开最小命令/结果并保持状态私有。
- **bundled ConPTY 宿主**：优先加载 exe 旁 `runtime/` 或 exe 目录的完整 `conpty.dll` + `OpenConsole.exe` 文件对，不限操作系统版本；文件对缺失且 Windows build < 21376 时，才将内嵌文件对在首次 spawn 前提取到 `%LOCALAPPDATA%\slterm\conpty` 并动态加载（进程级单次解析）。原因：exe 旁显式部署在 Win11 同样有效；内嵌单文件形态则用于规避老 Win10 in-box conhost 不转发鼠标 VT 序列。边界：文件对不完整即不选该路径；内嵌提取幂等（大小一致复用）；提取/加载任一失败记录警告并静默回退系统 ConPTY。
- **ConPTY flags 能力矩阵**：捆绑宿主/Win11 系统走默认矩阵；Win10 系统回退走兼容矩阵。原因：不同 conhost 能力不同。边界：默认矩阵位翻转必须过真实 claude 全屏 TUI 滚轮与 Win10 build 阈值人工实测；非默认 flags 的自动化假阴性已登记豁免。
- **DA1 后端全量接管**：DA1 查询（`ESC[c`/`ESC[0c`）一律后端检测、剥离，永不透传前端；应用查询逐条代答统一身份。bundled OpenConsole 首条宿主 DA1 到达读循环后，回写会成为 shell 输入，故只剥离不迟答。原因：前端自动应答与迟到应答都会经输入通道回灌，造成蜂鸣、身份序列污染、首字符丢失与恢复注入竞争。边界：首条抑制只由实际 bundled 后端注入且只消费一次；检测在剥离前的原始字节上进行；跨块查询前缀必须扣留；DA2/XTVERSION 未观测受害场景，暂不接管。
- **DSR 按需代答与门控剥离**：启动窗口内检测到 `ESC[6n` 才代答；窗口外按 conhost 输入能力门控剥离，应答会被传输层损坏的主机只剥离不答。原因：Win10 键事件输入模式下任何 CPR 应答字节写入 stdin 都会变成杂散按键。边界：禁止盲注 CPR；禁止把应答会被损坏的查询透传前端。
- **握手原则**：握手应答一律按需，禁止盲注，也不得向已无等待者的输入通道迟答。原因：没有等待者的应答字节就是注入应用输入的杂散键。边界：bundled 首条宿主 DA1 按上条处理；其余查询处置按传输层能力分叉，不透传前端。
- **默认 Shell 真实探测**：仅默认链按 `pwsh.exe` → `powershell.exe` → `cmd.exe` 顺序真实创建候选，并要求 500 毫秒稳定窗内未退出；早退、创建或回收失败进入下一候选，全部失败明确报错。探测只使用不加载用户 profile 的专用参数、`CREATE_NO_WINDOW` 与空输出，稳定后 kill＋wait 回收。显式 Shell 不自动换 Shell。原因：存在性检查不能证明候选可用，探测也不得重复执行用户启动脚本或留下孤儿进程。边界：探测位于 GPUI 创建前的启动链；实际终端仍使用受管集成参数。
- **恢复注入边界**：core 只提供 PTY 输入通道；壳在恢复 pane 后立即写入 ConPTY 输入缓冲，由 shell 就绪后消费，不等待提示符、固定延迟或超时。原因：ConPTY 已提供输入排队，额外就绪探测会引入双源状态。边界：core 不返回或持有产品恢复状态。
- **输入兼容分别验证**：输入修复必须分别验证原生控制台读取方、翻译后字节流读取方和协商协议；不能用单一路径正常推断所有客户端兼容。原因：三类路径的行为分叉真实存在。边界：涉及 Win10 键事件模式的修复必须在该路径实测。
- **测试覆盖**：字节流、解析器和回放测试要覆盖分块边界、静默源、错误/EOF 和平台差异；间歇问题需要能稳定失败的判据。热路径变更提供代表性成本证据；分配、吞吐或内存结论限定到实际测量的内容、尺寸、平台和构建配置。
- **平台分支收敛**：Windows 适配收在 `tty/windows`；业务层不得散落平台条件编译。
- **会话容量**：应用级存活 PTY 上限为 64，只统计存活进程；创建在 `SPAWN_LOCK` 内原子检查并取得额度，观察到子进程退出即归还，PTY 销毁是兜底归还且同一额度不得释放两次。超限必须在创建前拒绝并给出上限值；已退出但仍保留最后画面的 PTY 不占额度。容量测试走串行执行。
- **有界命令端点**：每个 worker 的命令队列最多 64 条；输入与 resize 只经 `try_send` 非阻塞提交，`QueueFull` 与 `Disconnected` 必须返回调用方，不得静默丢命令。阻塞 `send` 只保留给后台关闭路径，保证 `Shutdown` 入队后再 join；GPUI 前台不得调用阻塞发送。
- **输出双重背压**：专用读取线程只读原始字节并转发块，单块最多 64 KiB；队列最多 64 块且总字节不超过 4 MiB。块数或字节任一满载即阻塞读取线程，由 OS 管道向 ConPTY 施加背压；解析 worker 消费后按 FIFO 继续，不丢输出，不阻塞 GPUI 前台。EOF／错误必须关闭队列并唤醒消费者，显式 teardown 的 drain 不得因满载卡死。
- **resize 输出水位**：每个已公布块携带单调水位；resize 接收时冻结当前水位，worker 只在旧几何下处理至该水位，再重排并通知 PTY。水位后的块保持 FIFO，留给新几何。原因：既不能让旧宽度输出落入新网格，也不能让持续输出使 resize 永久饥饿。边界：初始尺寸沿用创建时几何；不得在 GPUI 前台直接 resize `Term`。
- **重连保留逻辑网格**：手动重连只面向已退出进程；新 worker 共享原主屏回滚，替换 `Term` 事件代理并插入语言中立分隔，旧代次事件与命令目标全部失效。原因：逻辑终端历史与一次 PTY 生命必须分离。边界：启动失败不得修改旧画面或 Registry；重连不得恢复原进程，也不持久化输出。
- **不可变帧协议**：worker 在输出、resize、滚动、选区、配色与退出边界发布带单调 revision 的 `TerminalFrame`；消费方只读帧，不为绘制或坐标映射另锁实时 `Term`。原因：显示状态必须来自同一边界，避免前台读取与 PTY 解析竞态。边界：帧只携带展示与选区所需数据，不暴露网格可变引用。
- **退出后显示生命周期**：子进程退出只注销 PTY I/O，显示 worker 继续处理滚动与选区直到显式 `Shutdown`；退出边界仍发布最后帧。原因：shell 退出后最后画面仍须可阅读与复制。边界：退出后禁止向已结束进程写输入，但不得借此提前终止显示 worker。
- **真实进程身份**：Windows 进程身份由非零 PID 与同一有效进程句柄读取的创建时间组成；不得使用 PID 0 或单独 PID 表示存活身份。原因：PID 复用会把旧终端命令或退出事实错投给新进程。边界：身份必须在子进程句柄仍有效时捕获。
- **提示符回显快照**：完整 OSC 133;B 边界递增提示符代次；不可变帧携带边界到真实光标之间的回显文本，供应用层对账本地输入。原因：执行确认需要同一网格事实，不能另造命令正文通道。边界：备用屏、reflow/reset、失效边界或光标倒退不提供快照；core 不采集历史、不判断 Shell 是否受支持。

## 验收与测试

- 单元与集成：`cargo test -p slterm_terminal --test lib_tests <filter> -- --test-threads=1`；禁止 `--lib` 或裸 filter 直打默认 lib target。
- 真机：`cargo test -p slterm_terminal --test pty_integration_tests -- --test-threads=1`。
- 集成层覆盖 spawn/写入/读取/resize/关闭全链、默认 shell 解析与 OSC 语义、DA1 统一身份、捆绑资源归还、容量上限与并发抢占。
- Win10 真机人工验收点与不可自动化边界见 `.claude/docs/testing/exemptions.md`。

## 操作

- 捆绑 ConPTY 更新：替换 vendor 二进制与许可证/说明文件，保持提取幂等与回退路径不变。
- 新增平台输入路径：在 `tty/windows` 内实现，并分别补原生/翻译/协商路径的测试。
- 调试 ConPTY 握手：用集成 target 的真实进程链路，不用裸 PTY 直读输出。
