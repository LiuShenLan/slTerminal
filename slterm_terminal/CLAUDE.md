# slterm_terminal（core 层）

> 终端核心：网格、VT 解析、PTY 行为、输入编码、选择与回放、渲染快照；不依赖产品视图、窗口状态或 GPUI。

## 决策与红线

- **core 边界**：本目录只拥有 grid、VT、PTY、输入编码、回放和终端行为；不得依赖产品视图、窗口状态或 GPUI 组件。原因：终端语义必须能脱离 UI 独立测试。边界：不为 UI 需求在终端核心增加产品概念；确需新接口时公开最小命令/结果并保持状态私有。
- **Win10 捆绑 ConPTY 宿主**：`conpty.dll` + `OpenConsole.exe` 以 `include_bytes!` 嵌入库资源；仅 Windows build < 21376 在首次 spawn 前提取到 `%LOCALAPPDATA%\slterm\conpty` 并动态加载（进程级单次解析）。原因：老 Win10 in-box conhost 不转发鼠标 VT 序列，而部署形态必须保持单文件。边界：提取幂等（大小一致复用）；提取/加载任一失败记录警告并静默回退系统 ConPTY；Win11 恒走系统路径。
- **ConPTY flags 能力矩阵**：捆绑宿主/Win11 系统走默认矩阵；Win10 系统回退走兼容矩阵。原因：不同 conhost 能力不同。边界：默认矩阵位翻转必须过真实 claude 全屏 TUI 滚轮与 Win10 build 阈值人工实测；非默认 flags 的自动化假阴性已登记豁免。
- **DA1 后端全量接管**：DA1 查询（`ESC[c`/`ESC[0c`）一律后端检测、剥离，永不透传前端；应用查询逐条代答统一身份。bundled OpenConsole 首条宿主 DA1 到达读循环后，回写会成为 shell 输入，故只剥离不迟答。原因：前端自动应答与迟到应答都会经输入通道回灌，造成蜂鸣、身份序列污染、首字符丢失与恢复注入竞争。边界：首条抑制只由实际 bundled 后端注入且只消费一次；检测在剥离前的原始字节上进行；跨块查询前缀必须扣留；DA2/XTVERSION 未观测受害场景，暂不接管。
- **DSR 按需代答与门控剥离**：启动窗口内检测到 `ESC[6n` 才代答；窗口外按 conhost 输入能力门控剥离，应答会被传输层损坏的主机只剥离不答。原因：Win10 键事件输入模式下任何 CPR 应答字节写入 stdin 都会变成杂散按键。边界：禁止盲注 CPR；禁止把应答会被损坏的查询透传前端。
- **握手原则**：握手应答一律按需，禁止盲注，也不得向已无等待者的输入通道迟答。原因：没有等待者的应答字节就是注入应用输入的杂散键。边界：bundled 首条宿主 DA1 按上条处理；其余查询处置按传输层能力分叉，不透传前端。
- **恢复注入边界**：core 只提供 PTY 输入通道；壳在恢复 pane 后立即写入 ConPTY 输入缓冲，由 shell 就绪后消费，不等待提示符、固定延迟或超时。原因：ConPTY 已提供输入排队，额外就绪探测会引入双源状态。边界：core 不返回或持有产品恢复状态。
- **输入兼容分别验证**：输入修复必须分别验证原生控制台读取方、翻译后字节流读取方和协商协议；不能用单一路径正常推断所有客户端兼容。原因：三类路径的行为分叉真实存在。边界：涉及 Win10 键事件模式的修复必须在该路径实测。
- **测试覆盖**：字节流、解析器和回放测试要覆盖分块边界、静默源、错误/EOF 和平台差异；间歇问题需要能稳定失败的判据。热路径变更提供代表性成本证据；分配、吞吐或内存结论限定到实际测量的内容、尺寸、平台和构建配置。
- **平台分支收敛**：Windows 适配收在 `tty/windows`；业务层不得散落平台条件编译。
- **会话容量**：PTY 会话上限是外部可依赖契约，超限必须拒绝并给出上限值；容量测试走串行执行。

## 验收与测试

- 单元与集成：`cargo test -p slterm_terminal --test lib_tests <filter> -- --test-threads=1`；禁止 `--lib` 或裸 filter 直打默认 lib target。
- 真机：`cargo test -p slterm_terminal --test pty_integration_tests -- --test-threads=1`。
- 集成层覆盖 spawn/写入/读取/resize/关闭全链、默认 shell 解析与 OSC 语义、DA1 统一身份、捆绑资源归还、容量上限与并发抢占。
- Win10 真机人工验收点与不可自动化边界见 `.claude/docs/testing/exemptions.md`。

## 操作

- 捆绑 ConPTY 更新：替换 vendor 二进制与许可证/说明文件，保持提取幂等与回退路径不变。
- 新增平台输入路径：在 `tty/windows` 内实现，并分别补原生/翻译/协商路径的测试。
- 调试 ConPTY 握手：用集成 target 的真实进程链路，不用裸 PTY 直读输出。
