# 验证方法

## 工具×场景矩阵

| 工具 | 适用场景 | 限制 |
|------|---------|------|
| WebSearch | 确认通用事实、找官方文档入口 | 不返回具体页面内容 |
| WebFetch | 抓取页面全文、核实话语是否在页面中 | 被某些站点拦截（Cloudflare、企业网络） |
| GitHub API | 获取 issue 状态/标签/关闭日期（结构化数据）；**正文与评论经 `/issues/{n}` 与 `/issues/{n}/comments` 分别核查**——collaborator 的修复声明（"fixed in vX.Y.Z"）常藏在评论中且早于检索日；其他用户补充的数值/建议也与报告者建议区分 | 限速，不返回页面渲染内容 |
| HN Firebase API | 获取帖子时间戳/分数/评论数 | 仅 Hacker News |
| npm Registry API | 确认包存在、版本号、发布时间 | 不返回 README 全文（需 raw.githubusercontent） |
| chrome-devtools MCP | 完整浏览器环境——快照、执行 JS、网络请求 | 需要真实浏览器进程 |
| raw.githubusercontent.com | 获取仓库文件原始文本（README、配置） | GitHub 主站被墙时的替代路径 |
| Context7 (结构化文档) | 官方文档的精确字段/类型查询 | 配额有限，仅索引特定库 |

## 5 级证据层级

从上到下可信度递减。冲突时高优先级的证据覆盖低优先级。

| 层级 | 描述 | 示例 | 冲突裁决权重 |
|------|------|------|------------|
| L1 权威 | 官方文档 API 响应、SDK 类型定义、机器可读结构化数据 | Context7 返回的官方字段列表、GitHub API 的 `state` 字段、npm registry 版本号 | 最高——不能被低层证据推翻 |
| L2 直接 | 原始源码/配置文件内容、raw.githubusercontent README、浏览器页面快照 | 仓库 README 原文、chrome-devtools 截图 | 高——除非与 L1 矛盾 |
| L3 交叉 | 项目内其他文件的一致性验证 | "文件 A 和文件 B 对同一声称一致" | 中——只能发现矛盾，不能确认正确 |
| L4 间接 | 逻辑推断、社区讨论、非官方博客 | "从设计原则推断应该是 X" | 低——可参考但不足以下结论 |
| L5 不可验证 | 网络受限、配额耗尽、需要认证 | 被 Cloudflare 拦截的页面 | 不参与裁决——标记待第二轮 |

## 信息来源优先级（裁决用）

当两个方向对同一声称给出不同结论时，按此优先级裁决:

1. **官方一手来源**（厂商文档、API 响应、SDK 类型定义）
2. **裁决文件已有裁定**（ADJUDICATION.md 的先前裁决）
3. **直接机器可读证据**（API JSON、raw 文件内容、npm 元数据、浏览器页面快照）
4. **项目内部一致性**（两个文件矛盾 → 至少一个错误 → 需外部解决）
5. **审阅者引用的证据**——仅在能独立确认时接受；当来源不包含审阅者声称的内容时拒绝
6. **逻辑/技术推断**——最弱，仅在其他来源都不可达时使用

## 多轮重验证触发条件

一轮验证后若存在以下情况，触发第二轮:

1. 标记为"无法验证"的条目数 > 0
2. 使用替代访问方法可以验证（API 端点替代 HTML 页面、raw 文件替代渲染页面）
3. 替代方法优先顺序:
   - 第 1 轮: WebSearch + WebFetch（通用路径）
   - 第 2 轮: API 端点 + raw 文件 + chrome-devtools MCP（绕过拦截）
   - 第 3+ 轮: 仅对遗留的极少数条目手工处理

## 子代理验证方法规范

每个验证子代理必须:

1. 对每条声称执行: `WebFetch(来源URL) → 提取关键段落 → 对比声称 → 判定支撑/不支撑`
2. 对数字/N-ary 声称执行: `WebSearch → 找官方定义 → 提取精确值 → 对比`
3. 对内部一致性执行: `逐文件读取 → 对同一声称在多文件间比对`
4. 每条判定必须附: `反证URL + 具体行/段落引用`
5. 无法验证时标注: `原因（网络限制/配额/认证）+ 建议替代方法`
