# Review 输出格式规范

## 目录结构

```
{baseDir}/review/
├── ADJUDICATION.md           # 阶段 2：跨方向矛盾裁决
├── D1/                        # 方向 1 的 review 文件
│   ├── {source-file-1}-review.md
│   └── {source-file-2}-review.md
├── D2/                        # 方向 2
├── verify/                    # 阶段 3：逐条核实
│   ├── D1-verify.md
│   └── D2-verify.md
└── (后续多轮目录按需创建)
```

## 错误条目模板 (阶段 1 子代理输出)

每条错误严格按此模板:

```markdown
## 错误 N: [一句话概括]

- **文件+行号**: `源文件路径` (行号范围)
- **原声称**: 文档中的原文表述（直接引用）
- **错误类型**: 事实错误 | 来源不支撑 | 过时信息 | 内部矛盾
- **正确信息**: 修正后的正确内容
- **反证来源**: 支撑修正的 URL + 关键引用
```

规则:
- 只输出不正确的信息——全部正确的文件写"未发现错误（已验证 N 项声称）"
- 内部矛盾需注明矛盾双方的文件路径
- 纯索引文件（如 README.md）跳过不审
- 反证来源必须可复现: URL + 具体行/段落引用

## Review 文件头部模板

> 由 `scripts/review-template.mjs` 生成：`node <skill目录>/scripts/review-template.mjs <源文件路径> <组名>`

```markdown
# {source-file-name} 事实核查报告

> 核查日期: {date}
> 核查方式: {methods used}
> 核查范围: {N claims verified}, {tools used}
```

## 汇总表模板 (阶段 3 verify 输出)

```markdown
## 验证结果汇总

| 类别 | 数量 |
|------|------|
| Review 正确，已修正源文件 | N |
| Review 部分正确，部分修正 | N |
| Review 不正确，未修改 | N |
| 无法验证 | N |
| 总计 | N |
```

## 裁决文件模板 (阶段 2 输出)

```markdown
# 跨方向矛盾裁决

> 裁决日期: {date}
> 依据: [verification-methods.md 的证据层级]

## 冲突 N: [描述]

| 方向 | 声称 |
|------|------|
| D{X} | ... |
| D{Y} | ... |

**裁决**: [哪方正确 / 双方都错]
**正确信息**: [修正后的内容]
**依据**: [URL + 证据引用]
**严重程度**: P0/P1/P2
```

## 严重程度定义

| 级别 | 定义 | 示例 |
|------|------|------|
| P0 | 影响架构决策/安全 | 虚构的环境变量名、不存在的 API |
| P1 | 影响信息可信度 | 数据严重过时、来源完全不符 |
| P2 | 轻微不准确 | 遗漏次要信息、措辞不精确 |
