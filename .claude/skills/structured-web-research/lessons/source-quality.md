# 源头质量：常见错误类型与预防

## 错误类型 1: 虚构术语

**症状**: 文中出现的术语/函数名/变量名，在声称的来源页面中完全不存在。

**典型案例**:
- 声称某终端模拟器支持 `SourcedRcFileForWarp` 函数 → GitHub 仓库是 issues-only，源码未开源
- 声称某工具的 `OSC 777` 序列存在 → 引用的三个来源页面均不提及此序列
- 声称 WezTerm 通过 `ZDOTDIR`/`BASH_ENV` 注入脚本 → 官方文档零出现

**根因**: 子代理在 WebSearch 过程中自行推测/生成术语，而非从来源页面逐字提取。

**预防规则**:
1. 每个术语必须在来源页面中逐词搜索确认存在，才能写入
2. 无法确认的术语 → 删除，或标注"来源待验证"
3. 禁止子代理从相关但不同的概念"类推"出术语

## 错误类型 2: 过时信息

**症状**: 声称的数字/状态/版本在检索时已不准确。

**典型案例**:
- 声称某 GitHub 仓库 "Stars ~14.5k" → 实际已到 ~25k（4 个月前的数据）
- 声称某 Issue 为 "Open" → 实际已被关闭
- 声称某功能 "2026年5月 Warp 开源（AGPL-3.0）" → 实际未开源

**根因**: 搜索结果返回了旧页面（博客、旧文档），或搜索引擎缓存了过时片段。

**预防规则**:
1. 每个数字/状态标注检索日期
2. 关键数据点（GitHub stars、issue status）通过直接访问页面确认
3. 用"截至 YYYY-MM-DD"前缀

## 错误类型 3: 字段混淆

**症状**: 将不同字段、不同层级的取值空间互换。

**典型案例**:
- `permission_mode`（session 级输入，"default"/"plan"）↔ `permissionDecision`（工具级输出，"allow"/"deny"）——两个独立字段
- `CLAUDE_SESSION_ID` 被列为环境变量 → 实际仅存在于 stdin JSON，不是环境变量

**根因**: 子代理在汇总时合并了相似名称的字段，忽略了"不同上下文"。

**预防规则**:
1. 同名/近名字段必须确认属于同一层级、同一上下文才能合并
2. 环境变量名和 JSON 字段名不要混淆（前者全大写，后者 snake_case）
3. 交叉验证时按字段名→定义→取值空间三层比对

## 错误类型 4: 内部矛盾

**症状**: 同一方向内不同子文件对同一概念给出不一致的说法。

**典型案例**:
- D2-main 说 PreCompact 可阻止，D2-schema 说否
- D2-main 说配置优先级 `user > project > local`，D2-detail 说 `project > user`

**根因**: 子代理各自独立检索，没有相互交叉验证。

**预防规则**:
1. 汇总阶段必须执行 `cross-validate.ts` 算法
2. 发现内部矛盾 → 标记为冲突 → 人工裁决
3. 裁决依据：官方文档 > 源代码 > 社区
