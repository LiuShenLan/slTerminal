# 修改规范

## 核心规则

1. **用 Edit 不用 Write** — 精确替换，避免全量覆盖引入意外变更
2. **修改后检查 markdown 语法** — 表格连续性、代码块闭合、链接有效性
3. **修改前后各看 3 行上下文** — 确认替换位置准确
4. **标题/列表项不可孤立** — 确保归属关系正确

## 常见修改引入的错误

### 错误 1: 标题丢失

**症状**: Edit 替换时意外吞掉了前后的标题行或列表项归属。

**案例**: 修改 Issue #44093 的状态时，`#17139` 的 `####` 标题行被一起删除，导致状态行孤立悬挂在两个条目之间。

**预防**:
```typescript
// 修改前检查（伪代码）
function beforeEdit(oldString: string, newString: string) {
  // 1. oldString 中是否有 `####` / `###` / `- ` 等标题/列表标记？
  //    有 → newString 中必须保留（除非刻意删除）
  // 2. oldString 是否是某标题的子元素？
  //    是 → newString 不能丢失其父级归属
}
```

### 错误 2: Markdown 表格断裂

**症状**: 插入/移动 blockquote、空行等元素时截断表格。

**案例**: 把 Gemini CLI 弃用说明从 AI 工具表格中间移到表后，blockquote 截断了终端工具表格——6 行变成无表头孤立行。

**预防**:
```typescript
// 表格完整性检查（伪代码）
function checkTableContinuity(text: string) {
  // 1. 找到所有 `|---|---|` 分隔行
  // 2. 每个分隔行之后的所有管道行 `|...|...|` 属于同一表格
  // 3. 确认分隔行和管道行之间没有 blockquote、空行、代码块等截断元素
  // 4. 如果有 → 修复：把截断元素移到表格完全结束之后
}
```

### 错误 3: 内部矛盾

**症状**: 同一次修改中，A 文件更新了但 B 文件遗漏，导致相互矛盾。

**案例**: D5c 行 244 标注 Warp "尚未开源"，行 290 却写 "2026年5月 Warp 开源（AGPL-3.0）"——同文件内直接矛盾。

**预防**:
```typescript
// 全局搜索（伪代码）
function checkGlobalConsistency(editedFiles: string[], keywords: string[]) {
  // 对每个关键词：
  //   1. 在本次所有修改文件中搜索
  //   2. 确认同一关键词在所有位置的值一致
  //   3. 不一致 → 标记，人工确认哪个是正确的
}
```

## 修改执行流程（确定性）

```
1. Read 源文件 → 确认 old_string 唯一匹配
2. 检查 old_string 前后 3 行 → 确认上下文
3. 构造 new_string → 与 old_string 逐字节比对
4. 执行 Edit
5. Read 修改后的文件（前后 10 行）→ 确认:
   a) 替换成功且未影响无关内容
   b) 没有标题/列表项孤立
   c) 表格连续（如有）
   d) 链接未断裂
6. 全局搜索修改涉及的关键词 → 确认无内部矛盾
```
