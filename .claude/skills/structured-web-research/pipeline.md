# 核心流程

## 5 阶段流水线

```
阶段1: 澄清需求
  → 阶段2: 方向分解（脚本）
    → 阶段3: 并行检索 (spawn 子代理，单层级)
      → 阶段4: 汇总产出
        → 阶段5: 验证修正（委托 verify-research-output skill）
```

## 阶段 1: 澄清需求

**目标**: 确认检索范围。一次性，不深入。

向用户确认 4 个参数：
1. 检索主题的边界（什么算/不算）
2. 时间范围（默认不限）
3. 语言范围（默认不限，英文优先）
4. 预期输出深度（简单/中等/复杂，影响概念提取数量）

## 阶段 2: 方向分解

**输入**: 阶段 1 确认的主题和范围
**输出**: 方向列表（含标题、搜索关键词）+ 深度配置

### 步骤

1. **AI**：从主题提取核心概念（1-N 个），每个概念标注特殊关注面（facets，可为空）
2. **确定性**：concepts JSON 经 stdin 传给 `decompose.mjs`：

   ```bash
   echo '[{"name":"概念A","facets":["关注面1"]},{"name":"概念B","facets":[]}]' | node <skill目录>/scripts/decompose.mjs
   ```

   输出 `Direction[]`（title / nestable / outputSlug）。
3. **确定性**：方向数传给 `depth-tier.mjs`：

   ```bash
   node <skill目录>/scripts/depth-tier.mjs <方向数>
   ```

   输出 `{ minSources, fetchTopN }`。
4. **AI**：对每个方向生成搜索关键词列表（语义工作，脚本不做）。

### 概念数参考

```
主题包含几个独立概念？
  ├── 1 个 → 简单（1-2 方向，取决于 facets）
  ├── 2-3 个 → 中等（3-5 方向）
  └── 4+ 个 → 复杂（5-8 方向，decompose.mjs 自动合并超限方向）
```

方向数量由 concepts JSON 直接决定：`facets` 非空的概念每 facet 产生 1 方向；`facets` 为空的概念产生 4 方向（维度矩阵）。要 2 个方向 → 1 概念 + 2 facets；要 4 方向 → 1 概念空 facets。

## 阶段 3: 并行检索（单层级）

**输入**: 方向列表 + 关键词 + 深度配置
**输出**: 每方向 1 个汇总 md 文件

### 步骤

1. 对每条方向，实例化 prompt 模板（见 `agent-prompt-template.md`）
2. 并行 spawn 子代理（全部 `run_in_background: true`）
3. 子代理内部：
   - 对每个搜索关键词做 WebSearch
   - 对搜索结果中排名前 `fetchTopN` 的 URL 做 WebFetch
   - 收集至少 `minSources` 个独立来源
   - 写入前逐条执行模板中的自检清单
4. **第二波（可选）**：首轮结果回来后，若某方向信息量明显超预期（独立来源 > 2×minSources），主代理可针对其中的子话题追加 spawn 第二波子代理，同样走模板。

### 子代理 spawn 约束

- **单层级**：只有主代理 spawn 子代理；子代理不得再 spawn 孙代理（harness 不支持）
- 并行上限：min(方向数, 5)。超过 5 个方向时分批
- 每个子代理必须写入一个汇总 md 文件到指定路径

### 等待纪律（防止 fallback 污染）

- 网络检索是慢操作：单方向子代理典型耗时 **10-20 分钟**。后台 spawn 后耐心等完成通知；**60 秒无响应不代表失败**。
- **主代理禁止代写方向文件**。即使主代理自己的网络工具不可用/被拦截，也不得凭训练知识手写 fallback 内容——子代理失败就重 spawn，方向文件内容必须来自真实检索。主代写一次，产物可信度即归零。
- 子代理真实失败（报错退出/超时被杀）时：重 spawn 同方向，不修补旧文件。

## 阶段 4: 汇总产出

**输入**: 阶段 3 产出的所有 md 文件
**输出**: README.md 索引 + 各方向汇总文件

### 步骤

1. 按 `output-spec.md` 的目录结构组织文件
2. 生成 README.md 索引（固定模板）
3. 跨方向关键发现汇总（跨文件交叉引用）

## 阶段 5: 验证修正

调用 `verify-research-output` skill 对阶段 4 产出做事实核查。该 skill 定义了完整的 4 阶段验证流程（并行验证 → 交叉裁决 → 逐条核实 → 修改源文件），以及错误体系、证据层级、修改规范。
