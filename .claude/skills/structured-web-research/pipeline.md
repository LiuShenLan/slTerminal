# 核心流程

## 5 阶段流水线

```
阶段1: 澄清需求
  → 阶段2: 方向分解
    → 阶段3: 并行检索 (spawn 子代理)
      → 阶段4: 汇总产出
        → 阶段5: 验证修正
```

## 阶段 1: 澄清需求

**目标**: 确认检索范围。一次性，不深入。

向用户确认 4 个参数：
1. 检索主题的边界（什么算/不算）
2. 时间范围（默认不限）
3. 语言范围（默认不限，英文优先）
4. 预期输出深度（简单/中等/复杂，影响后续分层）

## 阶段 2: 方向分解

**输入**: 阶段 1 确认的主题和范围
**输出**: `Direction[]` — 每个方向含：标题、搜索关键词列表、预期子方向

### 决策树

```
主题包含几个独立概念？
  ├── 1 个 → 简单（1-2 方向）
  ├── 2-3 个 → 中等（3-5 方向）
  └── 4+ 个 → 复杂（5-8 方向）

每个方向是否可进一步拆分？
  ├── 是 → 标记为"复杂方向"，允许 spawn 孙代理
  └── 否 → 子代理自行搜索即可
```

### 执行步骤

1. AI 提取核心概念（1-N 个）
2. 确定性：`decompose(concepts, dimensions)` → 返回方向列表（见 `scripts/decompose.ts`）
3. 确定性：`depthTier(directions.length)` → 返回嵌套深度和来源下限（见 `scripts/depth-tier.ts`）

## 阶段 3: 并行检索

**输入**: 方向列表 + 深度配置
**输出**: 每方向 1-N 个 markdown 文件

### 步骤

1. 对每条方向，实例化 prompt 模板（见 `agent-prompt-template.md`）
2. 并行 spawn 子代理（全部 `run_in_background: true`）
3. 子代理内部：
   - 对每个搜索关键词做 WebSearch
   - 对搜索结果中 top N 个 URL 做 WebFetch
   - 若该方向标记为"复杂"且某子方向信息量 > 阈值 → spawn 孙代理
   - 写入前执行 `output-checklist.ts` 自检

### 子代理 spawn 约束

- 并行上限：min(方向数, 5)。超过 5 个方向时分两批
- 嵌套深度上限：`depthTier()` 返回的值
- 每个子代理必须写入一个汇总 md 文件到指定路径

## 阶段 4: 汇总产出

**输入**: 阶段 3 产出的所有 md 文件
**输出**: README.md 索引 + 各方向汇总文件

### 步骤

1. 按 `output-spec.md` 的目录结构组织文件
2. 生成 README.md 索引（固定模板）
3. 跨方向关键发现汇总（跨文件交叉引用）

## 阶段 5: 验证修正

**输入**: 阶段 4 产出的所有文件
**输出**: 验证报告 + 源文件修正

### 步骤

1. 确定性：执行 `cross-validate.ts` 算法识别冲突
2. AI 判断：对冲突进行裁决
3. 确定性：按 `lessons/source-quality.md` 的检查项逐条复核
4. 若需修改源文件 → 遵守 `lessons/edit-discipline.md` 的规则
5. 输出验证报告

### 何时 spawn 验证子代理

```
错误数 ≥ 10 → spawn 5 个并行验证子代理（每方向 1 个）
错误数 < 10 → AI 直接验证并修改
```
