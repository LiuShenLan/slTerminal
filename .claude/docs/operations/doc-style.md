# 文档风格与维护规则

> 全仓文档只使用这一套结构；产品文档保留自身体裁，但同样遵守内容规则。

## 决策与红线

- **统一三段式**：项目文档使用固定骨架——一级标题 + 一句话职责 blockquote + `## 决策与红线` + `## 验收与测试` + 按需的 `## 操作`。原因：AI 读取与维护需要稳定锚点，减少风格漂移。边界：术语表与豁免登记表使用各自的固定表结构，不强行套三段式；技能文档保留 frontmatter 与流程结构。
- **决策条目格式**：每条决策写成「**决策名**：当前有效规则。原因：为什么这样做。边界：禁止事项/失效条件。」。原因：把「是什么、为什么、不能做什么」压在一处，避免只记结论。边界：不写实现步骤、文件清单、接口签名等代码可自证内容。
- **短标识符禁令**：禁止阶段号、批次/条目号、决策号、规则号、文档编号与测试分层编号进入文档、注释或代码符号名。原因：这些编号是过程性临时标识，阶段结束后失去语义并持续腐化。边界：commit hash、日期/状态锚、契约数值、外部 URL 锚点、领域术语与代码符号不在此列。
- **代码自证原则**：凡能通过阅读代码直接理解的信息（模块职责、文件清单、入口路径、接口签名、数据流、技术栈、现状描述）一律不写入文档。原因：这类内容必然腐化为失真文档。边界：文档只记录设计决策与原因、外部依赖的坑与红线、操作指令、约定与豁免登记。
- **快照数字禁令**：代码可自证的条目计数（文件数、行数、测试数、主题数、agent 数等）禁止入文档。原因：代码即真值，计数必腐化且无决策价值。边界：契约数值（超时/容量/阈值/尺寸）与结构性概念名不在此列。
- **行号引用禁令**：本仓源码/测试行号禁止引用。原因：插行即腐。边界：源码引符号名、测试引用例名；外部 URL 的锁定行锚点允许。
- **渐进式披露**：规则按目录分层，遵守目标文件路径上最近的 `CLAUDE.md`；读取某目录代码时自动加载该路径文档。跨模块且非常驻的内容放 `.claude/docs/<子域>/`，不平铺在 `.claude/` 根下。原因：常驻上下文只保留每次会话必需信息。边界：不为按需文档建立全局索引，根文件只留路径指针。
- **决策就近记录**：当前有效的决策写入目标代码路径最近的 `CLAUDE.md`；跨模块决策写入 `.claude/docs/` 对应子域。原因：决策与适用代码同路径，避免集中式 ADR 与代码脱节。边界：不集中维护 ADR 或因果档案；完整历史从 git log 查。
- **事实文档防腐**：只记经核验的当前事实；计划、待办、临时记录不入文档；表达演进必须带版本/日期/状态锚。原因：无锚点的「以前/现在/不再」无法审计。边界：证据锚点（实测日期、commit hash、上游版本号）保留。
- **子文件维护**：新建模块目录时同步创建该路径 `CLAUDE.md`；改动约定/决策/红线时同步对应文档。只改实现不改约定时无需动文档。

## 验收与测试

- 文档策略门禁 `python scripts/check_doc_policy.py full` 检查过程编号、行号引用与失效文档路径。
- 文档链接检查：Markdown 相对路径必须指向存在的目标。
- 文档内容以代码、测试与实测为真值源，不以文档反推实现。

## 操作

- 新建文档：复制本文件的三段式骨架，替换标题与职责边界。
- 新建模块：在模块目录创建 `CLAUDE.md`，只写该模块的决策、红线与验收方式。
- 产品文档（README、CHANGELOG、release-notes）：保留面向用户的体裁，遵守短标识符禁令、快照数字禁令与事实防腐规则。
