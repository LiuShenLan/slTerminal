# persistence（application 持久化适配）

> 独占 SQLite 连接、物理 schema、损坏分流与灾难副本；不承载 GPUI 状态或领域 JSON 第二通道。

## 决策与红线

- **后台 I/O**：数据库打开、事务、完整性检查与备份不得在 GPUI 前台执行；生产只由启动协调器与各库专用写线程调用。原因：磁盘与锁等待不能冻结窗口。边界：core 不得依赖本模块，测试只使用临时数据根。
- **当前 schema**：工作区库与学习库分别固定 `application_id` 与 `user_version`（工作区 2、学习 1），仅接受当前物理 schema，不建立旧库升级链。原因：持久结构必须有单一权威。边界：更高版本 query-only，不隔离、不降级、不覆盖；结构损坏、非本应用库与存储合同失败分别报告。
- **文本主键非空**：SQLite rowid 表的 `TEXT PRIMARY KEY` 不隐含 `NOT NULL`，所有文本身份键必须显式声明非空。原因：否则空身份可绕过主键唯一性并形成无法寻址的记录。边界：复合主键各列同样逐项非空；测试必须真实插入 `NULL`，不能只检查 schema 文本。
- **灾难副本**：Online Backup 只写入由本模块独占保留的新临时库，完成 application、版本、完整性与外键复核后才算成功。正常关闭在最终冲刷成功后、启动维护成功后都生成新临时库并原子替换正式副本，旧副本不得由 SQLite 直接覆盖。主库物理损坏时先校验有效副本；有效副本同样经 Online Backup 恢复，双损才隔离原件并以空工作区继续，所有分支均保留原现场并发出显式通知。原因：任何失败都不得留下可被误认为有效的副本或覆盖唯一诊断材料。边界：原子替换与 ACL 保留由统一文件写所有者完成；高版本、异库与存储合同错误不隔离。
- **数据边界**：正文、终端输出、AI 会话正文与凭据不进入 SQLite；错误展示不得回显路径、SQL、正文或底层 SQLite 消息。旧 JSON 与历史材料不读取、不迁移、不删除。
- **学习写线程与代次**：学习写运行时独占学习库写连接；客户端只经有界非阻塞提交命令与目录事实，写失败只暴露封闭状态与脱敏错误。清空请求只有在成功入队后才递增共享学习代次，使旧待写失效；每个入队的清空由写线程按 FIFO 真实执行并返回自己的回执，不做“被更新代次取代”的伪成功。队列拒收时保留内存数据、代次与既有待写，返回可见错误；事务失败不得报告已清空。原因：学习写不得阻塞 GPUI，清空失败不能伪装成功，迟到的旧命令也不得在清空后复活。边界：高版本与损坏库不覆盖；更高版本仅允许内存学习，显式清空返回不可用；runtime 只在 GPUI 外启动与 shutdown／join。
- **Workspace 写线程**：工作区写线程独占工作区库写连接；ViewState、侧栏组织状态与窗口几何按 500 毫秒去抖且同键只保留最新副本，项目列表、布局、逻辑终端与活跃项按 2 秒去抖且只保留最新项目快照；保存请求经有界队列非阻塞提交。Runtime 写操作的项目快照提交跳过去抖，在同一 Immediate 事务立即提交并回传真实结果，成功后清除旧去抖副本。写失败取消定时重试但保留副本，后续修改、flush 与 shutdown 均重试；容量 1 的失败信号只负责提示，待写副本才是重试事实。UI 只持共享命令队列与独立终态队列的 client，普通队列满时最终状态仍可经终态队列非阻塞移交；writer owner 与失败转发线程由 GPUI 外的全局关闭所有者独占，正常退出在窗口销毁前 shutdown 并回执，异常断连由应用返回后的 join 兜底；终态接收端由写线程独占，Flush 与 Shutdown 均先排空终态再写同一待写集合，最后终态覆盖普通队列旧副本。shutdown 先在后台排空终态再最终冲刷，失败必须记录脱敏诊断；启动维护或初始化失败不得回退无 client 窗口，运行写失败只经壳事件投递不含路径、SQL、键或状态正文的泛化提示；flush／shutdown 会等待结果，只在后台执行体调用，Drop 复用退出冲刷路径。原因：前台不得等待磁盘。边界：连续修改不得放大写盘或排队副本。
- **窗口几何单通道**：窗口几何只按本机标识读写单行；DTO 版本超前与损坏 JSON 一律按无记录处理，不覆盖用户行、不阻断启动。原因：几何是纯展示偏好，跨机共享数据库各机器互不覆盖。边界：本机标识只取启动缓存，测试构建固定占位；几何随加密备份的工作区类别按来源机器标识导出，目标机恢复时不直接应用，开窗链仍夹回可见工作区；备份不复制 SQLite 物理行，只携带同一规范几何 DTO。
- **侧栏组织状态单通道**：侧栏状态只在应用状态单行保存 core 规范 DTO；侧栏 upsert 与项目快照写分别只更新所属列，互不覆盖。原因：组织状态与私有 ViewState、项目布局是不同持久事实，不能形成第二序列化或整行重写。边界：无记录与整体损坏分流，字段级修复保留警告；启动未发生显式编辑时不回写默认态，普通队列拒收的最新状态经独立终态通道在 shutdown 前补交。
- **项目聚合单通道**：保存前先经事务外纯预检完成项目快照领域校验、全部项目／终端／Document 无损编码、活跃项与 DTO 版本转换，再于同一 Immediate 事务内保存完整项目快照：项目顺序、活跃项、稳定组身份、规范布局、被布局引用的逻辑终端记录及 Document 位置元数据；事务内只读取数据库并消费预检数据，不重复编码，写锁占用不得令非法输入等待 busy_timeout 或改报数据库错误。不得另建 Terminal 或 Document 写队列或跨表半提交。原因：项目、布局与恢复元数据只有一致提交才能作为重启事实，保留终端也不能因快照重写而重建。边界：布局内容不变不推进 revision，变化时单调递增且耗尽拒写；保留项目在事务内先腾空根唯一约束，允许项目间交换根且不重建终端；终端身份不得改绑项目或编号，项目计数器不得回退，新终端编号不得低于该项目已存计数器高水位，仅 cwd、Shell、自定义标题、AgentSession 与运行意图可更新；公共加载在同一 Immediate 事务读取完整快照，避免混合并发提交世代；保存与加载均须复核新旧快照的项目关系、布局 DTO、组身份、Terminal 与 Document 引用、终端归属与编号；普通加载对损坏、孤儿或不支持版本分别报错，启动恢复入口只对缺失／错项目视图与孤儿终端或 Document 记录按 core 同一规则归一，其他损坏仍拒绝；后续显式保存复用该归一基线，不回写仅由解析产生的布局；任何失败整体回滚，非 Unicode 路径拒绝有损编码。
- **ViewState 单通道**：视图状态端口独占视图状态读写；记录保存完整规范 ViewKey 与 ViewState DTO，版本列必须与 DTO 一致，任一版本来源超前均拒写且不覆盖，作用域只由匹配 ViewKey 推导，revision 从零单调递增且耗尽拒写。原因：关闭重开与重启必须共享一份状态，损坏与缺失不能混淆。边界：项目清理将项目作用域删除与 Nav／Explorer 分区更新放在同一 Immediate 事务，AgentRoot 清理只更新 AgentFiles 对应根分区；任一步失败整体回滚并保留已提交记录供重试，缺失身份不产生新 revision，不得清空整个应用级 SideView 或影响无关视图。
- **恢复材料显式清理**：Journal 步骤不得随父记录或 Document 隐式级联删除。原因：外部文件仍需按指纹、状态与维护流程处理，数据库级联会提前丢失定位事实。边界：项目布局等纯数据库记录可按项目删除契约级联；文件支撑的材料只能由对应所有者显式清理；不为尚无写入点的材料保留空表。
- **历史隔离记录**：`quarantine_batches` 只存批次状态、进度、期限与清单文件名，`quarantine_items` 只按批次与顺序存逐项状态与失败阶段；来源/副本路径、顺序与指纹仍以不可变清单为唯一权威。删除批次记录按外键级联逐项事实；运行期只经工作区写线程整体替换批次行，启动维护先读清单对账再补登孤儿清单，文件失败只落待处理事实而不升格为启动阻断，已过期限的完成/已撤销批次才允许清理。原因：批次状态必须跨重启一致，不能从来源存在性或第二份路径副本推断。边界：清单文件名必须是隔离根内单个文件名；旧物理 schema 不建立隐式迁移。
- **维护请求与恢复点**：维护请求只经专用端口读写；登记要求当前 `store_epoch` 且初始状态为 Prepared，重复 id 冲突零改写；状态机只允许 `Prepared → Applying → Applied`、`Prepared/Applying → RolledBack`、`Prepared/Applying → NeedsAttention`、`NeedsAttention → RolledBack`，终态冻结。应用成功的世代轮换与 `Applying → Applied` 只经同一 Immediate 事务提交，任一步不成立都不改写世代。恢复点只按请求 id 作用域读写，对象键为「类别前缀＋根内相对名」，多行可指向同一 DPAPI 文件但路径必须与登记一致。原因：维护材料的应用与回滚必须由唯一持久事实驱动，未知状态不得猜测。边界：请求状态转换不附加世代闸门（由启动维护期在刷新世代后调用），行解码失败或未知状态值返回损坏分类并阻断；已 Applied 请求的恢复点保留为可撤回材料并由撤回请求消费，其余恢复点遗留仍为阻断事实。
- **运行与世代单点**：正常重启只更换运行身份并保留 `store_epoch`，上一运行的正常退出事实必须可供启动恢复读取；只有显式维护提交才能同时按当前运行身份与预期旧世代更换 `store_epoch`。原因：普通重启不得使 Runtime 幂等命名空间失效，迟到的旧运行关闭或维护写也不得改写新事实。边界：首次初始化才采用调用方给定的初始世代；更高版本只读，同值更换与空身份拒绝，旧运行记录不因轮换删除。
- **启动维护先于写线程**：主实例在 OS 单实例锁后按工作区库恢复打开 → 开始运行 → 领域恢复器对账 → writer 与失败转发器 → 领域恢复（布局归一先于快照端口）→ 服务 → 全局关闭所有者 → GPUI 窗口组合；只有维护就绪才创建 writer，并沿用同一次运行登记的当前元数据与上一运行事实。维护需人工处理或执行失败经独立封闭错误分类上抛，展示脱敏；已登记运行保持未正常退出，组合根不得创建正常工作区窗口，仅进入独立只读诊断分支，不启动领域恢复、服务或普通后台任务。领域恢复（布局或快照）失败同样保留原记录，由组合根显式回收 writer 与转发线程后进入同一只读诊断与重试链，不以空工作区开窗。维护阻断材料只由诊断窗的显式放弃动作解除：先整库归档到本地诊断目录，归档失败零删除，再按阶段删除未完成事实并审计。原因：写线程与运行副作用必须建立在全部持久事实安全之后。边界：失败只开放不创建 writer、服务、PTY 或普通后台任务的只读诊断与重试窗口；重试关闭诊断后重新执行同一启动链，禁止回到无 client 的正常工作区降级启动。
- **世代写闸门**：Operation 与 Journal 的登记、状态转换和步骤事实写入必须在同一 Immediate 事务内匹配工作区元数据当前 `store_epoch`。原因：恢复或撤回轮换后，迟到的旧 Runtime 不得借幂等重试或恢复写重新产生副作用。边界：无运行元数据同样拒写；读取、结果重查与未完成 Journal 枚举不受限，旧记录保留，轮换只为新世代重开幂等命名空间。
- **关闭意图持久合同**：关闭意图头表独占 scope、可选项目身份、世代、提交指纹与状态，对象表只保存对象键、代次与决定；空关闭集合同样完整登记，对象身份由 application 以带类型前缀的关闭目标构造，本端口不接收裸 UUID 或猜测对象领域。登记与读取均在 Immediate 事务内完成，登记先在事务外完成全部字段校验与编码，再进入事务核对当前世代与 close_id 冲突；写锁占用不得令非法登记等待 busy_timeout 或改报数据库错误，冲突不改写；读取顺序确定，未知枚举、作用域项目不一致、空身份、错误指纹长度与负代次均为损坏，不静默修复。提交状态只允许 `Collected → StateCommitted → PtyStopped → CleanupCommitted → Completed` 顺序推进，并在同一事务核对预期旧状态、指纹与当前世代，冲突与失败不改写；Completed 保留历史但不进入未完成枚举。项目快照与关闭意图的组合提交只经工作区 writer 的非阻塞封闭命令，由唯一 writer 在同一 Immediate 事务完成快照保存、关闭登记与首次推进；调用方只等待独立回执，队列满或断连立即报错且不另开 SQLite 连接。组合提交前必须完成快照预检与关闭登记编码两侧校验，任一步失败整体回滚，外部不能观察中间态；组合提交前先将终态排入同一待写集合，仅成功后清除旧项目待写，失败保留供重试。后续状态推进同样只经唯一 writer 的非阻塞封闭命令与独立回执，调用方不得另开连接或直接写库。通用组合提交拒绝 Project scope；项目关闭初始提交只保存候选中的其他项目与新活跃项，目标项目、布局、终端与 Document 记录保留到 PtyStopped 后的专用清理；清理在同一 Immediate 事务精确清理项目 ViewState 与 Nav／Explorer 分区、删除目标项目独占 Document 并保留其他项目共享引用、恰好删除一条项目记录并经外键级联删除纯数据库布局与终端，再推进 CleanupCommitted，任一步失败整体回滚并允许同一当前状态重试；Project 的 `PtyStopped → CleanupCommitted` 只能经专用清理，通用推进拒绝该边。writer 执行清理前先将终态并入待写集合并预先完成待写侧栏视图转换，仅成功后同步清除旧项目快照、目标项目待写视图与待写 Nav／Explorer 目标分区，保留无关字段修改；失败保留待写副本，禁止只清快照而让旧侧栏状态复活项目分区。局部关闭所需当前 `store_epoch` 由启动恢复连接读取并移交 AppRoot，不新增第二读取通道；writer 存在但世代缺失或无效时关闭必须明确失败，不能以无 writer 的内存降级绕过启动硬闸门。项目快照恢复失败时，新局部关闭必须在调用组合提交前拒绝，不得借 writer 原子事务绕过项目写屏障；既有失败关闭只按原持久阶段重试。原因：关闭恢复必须读取一份规范事实，项目删除与共享正文清理必须同事务闭合。边界：组合提交不接收裸身份或分领域猜测。
- **Operation 幂等派发**：登记结果必须区分首次登记与已存在，调用方只能派发首次登记；同 `store_epoch＋client_id＋mutation_id` 且方法、参数 DTO 版本、参数散列一致时返回原记录，任一不同即冲突。显式保存与文件操作结果仍由原 Operation 记录持有，前台经 writer 的封闭查询命令与容量 1 回执重查，队列满或断连明确失败；视图显隐不得删除结果或另建内存权威。Runtime 写派发经同一 writer 的封闭登记与推进命令完成，本模块不判断方法语义或执行副作用。原因：断线重试不得重复产生副作用，也不得用重试输入覆盖原操作；所有 Runtime 写必须共用唯一写线程与当前世代闸门。启动维护在 Journal 与维护请求终结后把当前世代未终态 Operation 收敛为可查询终态（Queued→Failed、Running→OutcomeUnknown），旧世代与终态不改写。边界：`operation_id` 另作唯一身份；`OutcomeUnknown` 只可重查，不得自动重发；登记与状态转换的世代冲突原样上抛，由服务层映射封闭错误。
- **Journal 专门恢复**：Journal 与全部步骤、Operation 关联必须在同一事务登记；通用存储只提供未完成事实与显式状态边，不解释恢复类型、不自动重放或删除材料。原因：只有所属类型的恢复器能根据目标 DTO、前后指纹与真实文件状态判定提交、回滚或继续。边界：状态不明进入 `NeedsAttention` 并保留全部事实；终态步骤与指纹不可改写，清理另走显式审计流程。
- **Journal writer 端口**：领域后台执行体只经工作区 writer 的封闭登记、状态推进和步骤结果命令写 Journal，并以容量 1 回执等待真实提交；不得在文件服务中直开 SQLite。原因：文件副作用与持久事实必须共用唯一写线程和当前世代闸门。边界：命令发送保持非阻塞，只有后台端口可等待回执；队列满、断连或存储失败上抛，调用方不得据此重放文件副作用。
