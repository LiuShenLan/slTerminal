# LocalControlServer

> 仅监听 loopback 的本机控制面；OS 单实例锁、GPUI 前台与凭据门面分别归各自所有者。

## 决策与红线

- **首包认证与双作用域**：连接首条请求必须是 `runtime.hello`，协议版本、client_id 与作用域凭据全部有效才完成握手；`runtime` 与 `handover` 使用两项独立凭据，同一连接只接受自身作用域的方法，作用域不匹配或方法不属于该作用域直接断开。认证失败不返回协议预言机，不记录请求行或凭据。原因：两个作用域的安全边界不同，凭据混用会把移交意图提升为 Runtime 能力。边界：Runtime 作用域当前只开放握手，后续方法由注册表与对应服务切片逐个接入，不为未实现方法保留路由。
- **有界传输**：请求上限 128 KiB，握手读取限时 5 秒，后续读取限时 600 秒；单连接顺序处理，连接上限 64。超限或无效请求不得进入应用回调。
- **线程所有权**：accept 与连接 worker 均有显式句柄和 shutdown 路径；关闭拒绝新请求，唤醒 accept、断开活跃连接并 join，不留孤儿线程。首个 join 终止错误必须由 server 保存并在后续 shutdown/Drop 重放，正常重复关闭仍返回成功。不得在 GPUI 前台执行监听、读取、写入或 join。
- **客户端前台禁令**：同步 handover 客户端只在 `run()` 创建 GPUI 前的第二实例启动路径调用；更晚的调用点必须改用后台执行体，禁止 GPUI 前台阻塞。原因：客户端包含有界但阻塞的连接、写入与读取。边界：发现、只读凭据加载与客户端移交依次完成，任一失败均终止第二实例，不得返回可创建窗口的实例 guard。
- **启动意图映射**：封闭 `InstanceStartup` 只允许持锁 `Primary` 与已接受 `HandedOver`；显式工作目录仅在锁冲突时校验并转为绝对 UTF-8 OpenProject，缺省为 Focus。原因：首实例的坏目录回退与第二实例的明确移交语义不同，失败分支不能携带窗口创建所有权。边界：Primary 不预校验移交目录；仅锁原语的 `Ok(None)` 进入移交，普通 I/O 错误直接上抛，`ErrorKind::AlreadyExists` 不是冲突判据。
- **凭据写入所有权**：仅已持 OS 单实例锁的首实例可加载或创建 Runtime/handover 凭据，客户端只读加载，缺失返回 NotFound，绝不生成或写入。原因：以单写入者避免首次创建竞态，不另设互斥锁。边界：空值、长度或编码非法的持久凭据明确失败，不自动覆盖或轮换；唯一写入例外是 `runtime rotate` 维护子命令，它先取得同一实例锁、冲突即明确失败，且只轮换 Runtime 作用域，handover 凭据与目标保持不变。
- **首实例服务组合**：控制面服务只能在已持 OS 单实例锁时启动，绑定顺序固定为 handover 凭据、loopback listener；此时保留本次发现记录但不发布，只有窗口可服务后的显式开放才原子发布。发布幂等；发布失败必须立即回收监听，保留发布根因与错误 kind，同时聚合 listener 回收错误，不得静默丢弃或重发死端点。原因：第二实例只能在首帧可服务后观察到完整可用的本次服务。边界：绑定、开放、显式关闭与 Drop join 都只能在 GPUI 外执行，后续接线不得把这组阻塞生命周期放到前台。
- **真实运行合同**：hello 的持久世代取工作区元数据，流世代取本次 `run_id`，新事件流 revision 从零开始；发现记录使用同一 `RunMarker` 与实际绑定端点，散列按外部合同从随包 schema 原始字节推导。原因：客户端必须核对真实运行与合同版本，占位值会伪造世代或兼容性。边界：不得另造运行身份、读取第二份元数据或修改 schema 字段。
- **回执有界等待**：server 回调只经 `app_shell::try_send_handover` 投递，worker 等待回执的生产上限为 4 秒；超时映射 NotReady，回执发送端断开映射 Closing，helper 错误原样返回。原因：客户端总 deadline 为 5 秒，服务端必须更早给出结构化终态且不能无界占用 worker。边界：不在回执等待后追加无界 join。
- **统一关闭**：服务显式 shutdown 必须依次尝试 server shutdown 与发现撤销，前者失败不得跳过后者，汇总首个错误；重复调用保持安全，Drop 仅尽力。原因：监听与发现记录是同一服务的两个可观察资源，不能只回收一半。边界：正常退出必须显式调用并处理错误，不能依赖 Drop。
- **发现记录无凭据**：端点发现只使用 Runtime v2 封闭 DTO，读取预算 4 KiB；发布经原子写收敛为仅当前用户的受保护 DACL，guard 绑定文件身份与内容，撤销排除所有其他读写句柄并把最终组件按 reparse 点自身打开，显式撤销上抛错误，Drop 只尽力清理。原因：端点可供本机客户端发现，但 token 不得进入普通文件，旧实例不得误删替代记录或链接目标，delete-pending 不得伪装为目录项已撤销。边界：客户端只读；损坏、未知字段、非 loopback、零端口与超限记录一律失败，正常关闭必须先显式撤销。`slterm runtime discover --json` 是唯一输出 Runtime token 的入口：端点记录与凭据域只读加载在 CLI 层合成输出，不带 `--json` 只打印非敏感元数据；CLI 不接受 token 参数、环境变量或命令行注入。
- **Operation 派发与查询**：写操作的参数散列只经协议 crate 的 `params_sha256`；派发顺序固定为登记 → Running → 执行 → 终态，登记与推进只经唯一工作区写线程的封闭命令，本模块与 server 不直开 SQLite。相同幂等键与参数散列返回原 Operation 且执行体不重跑；同键不同参数映射 `mutation_conflict`；`expected_revision` 在登记前复核，失配映射 `revision_conflict` 且不消耗 mutation_id。无法证明副作用的执行体必须返回 OutcomeUnknown，该终态可查询、禁止自动重发。`runtime.operation_get` 与 `runtime.operation_wait` 只读持久记录；wait 在 worker 内 100 毫秒轮询、受 600 秒上限与关闭状态约束，超时 NotReady、关闭 Closing，不存在映射 `unknown_operation`。原因：断线重查与幂等命名空间必须只由一份持久事实裁定。边界：派发器只在后台 worker 同步等待有界回执；前台与 GPUI 线程禁止调用；写方法族接入时只负责构造请求与执行体，不另建写通道。
- **有界读取**：终端、Git diff 与 Agent 读取共用 `reads` 模块的分页语义：单页正文预算 384 KiB（低于 1 MiB 响应上限，为 JSON 封装与转义留裕度）、切分点保持在完整 UTF-8 字符边界、预算内优先收束在行尾、超预算单行也必须前进。游标是服务端生成的 `v1` 文本，绑定资源代次与输出 revision；任一变化、非法文本或越界都返回 `StaleCursor`，客户端必须重新读取而不是拼接旧页。尾部仍有内容时必须返回续读游标，禁止把截断内容伪装成完整结果。原因：三种读取共享同一响应预算与失效规则，第二套分页会造成游标语义漂移。边界：本模块只做纯切分，不读取文件、PTY 或网络；真实读取与快照捕获由各方法族在后台完成；终端读取游标绑定 worker 最近发布的帧 revision，任何网格或显示边界都保守地使旧页失效。
- **事件环与订阅**：`EventHub` 线程独占事件环（容量 1,024）与订阅表；发布与订阅都经容量 64 的命令通道进入，AppRoot 只持有 `RuntimeEventPublisher` 非阻塞发布，队列满丢弃事件而不反压前台。每订阅客户端队列容量 64，滞后客户端只移除自身订阅并使接收端断开，不影响其他订阅、UI 或 PTY。续传必须同时匹配 `store_epoch + stream_epoch + since_revision`，积压超过客户端队列同样返回 `resync_required`。订阅连接只承载事件：独立写线程推送 `events.event` 通知，worker 只等待取消订阅或断开；取消确认与事件写共用写锁，连接结束时先关闭流再 join 事件线程。关闭顺序为 server → 发现撤销 → 事件环 join，任一失败不跳过后续。原因：事件发布、订阅与回收必须有单一所有者，过期事件不得回填。边界：事件负载只含 revision、类型名、资源身份与代次；正文、正文长度与凭据禁止进入事件；发布点在 AppRoot 前台状态提交成功之后。
- **写意图单点**：Runtime 写方法只构造封闭 `RuntimeMutation`（稳定身份与已校验输入），server 解析稳定 UUID、ViewKey JSON 或组身份失败即 InvalidRequest；执行体把意图经壳事件交给 AppRoot，复用项目命令与 `SplitView`／`MergeGroups`／`ResizeSplit`／`MoveView`／`activate_view` 同一命令目录，不另建项目、布局或关闭通道。每次写都先经派发器登记 Operation 再执行；相同幂等键与参数返回原记录，执行体不重跑；执行回执超时或断开记为 OutcomeUnknown，等待方只得到可查询结果。原因：控制面不得形成第二套写路径或伪成功入口。边界：`RuntimeMutation` 只服务当前已登记方法；新增方法必须先有真实命令与 AppRoot 接线；参数散列只使用 `params_value` 的规范字段，视图身份必须可无损编码；面板身份不暴露运行期 `PanelId`；终端输入直接复用 `TerminalView` 的 worker 命令，不在控制面另建 PTY 写通道。
- **能力边界**：Runtime 作用域当前实现 `runtime.hello`、`runtime.describe`、`runtime.snapshot`、`runtime.operation_get`、`runtime.operation_wait`、`events.subscribe`、`events.unsubscribe`、`project.list`、`project.activate`、`project.rename`、`project.reorder`、`project.remove`、`panel_group.split`、`panel_group.merge`、`panel_group.resize`、`panel.activate`、`panel.move`、`panel.open_settings`、`terminal.create`、`terminal.input`、`terminal.execute`、`terminal.read`、`terminal.wait`、`terminal.close`、`terminal.reconnect`、`terminal.rename`、`agent.list`、`agent.get`、`agent.input`、`agent.close`、`agent.read`、`agent.wait`、`agent.start`、`agent.resume`、`agent.fork`、`git.status`、`git.diff`、`git.rollback` 与 `git.delete`；不添加占位方法，方法注册表登记真实可用方法，服务器只在对应作用域存活时接受其凭据。describe 由 server 直接用注册表与握手同一散列回答，不回调前台；snapshot 经壳事件在 AppRoot 前台按请求时刻生成资源，worker 只做有界等待（2 秒），超时映射 NotReady、断连映射 Closing。事件环接入前 snapshot 的 revision 固定取握手起点，Hub 切片接管实时代次。OpenProject 在 AppRoot 先纯校验规范路径，再复用项目打开命令；仅成功后前置窗口，新增根不自动创建终端，重复根只激活既有项目。NewTerminal 在 AppRoot 纯校验可选 project_root/cwd 后复用同一 CommandRegistry，只选择既有项目，不在传输层或前台做文件系统解析；非法路径为 InvalidRequest，未知根、无覆盖 cwd、跨根 cwd 与模态为 Unauthorized，其他启动或未就绪失败为 NotReady，Closing 优先，错误脱敏。`terminal.input` 把 `data` 原样写入 PTY（不追加回车、不模拟键盘事件），`terminal.execute` 只接受不含 `\0\r\n` 的单行命令并由服务端追加一次回车；两者都按稳定 `terminal_id` 与 PTY 代次定位，终端身份非法为 InvalidRequest，记录非 Launch、Registry 无目标、代次不匹配或面板缺失均为 NotReady，不猜测重连后的新进程。`terminal.read` 复用同一身份与代次校验，只读允许已退出但保留画面的终端；前台只把 `ReadText` 命令入队并把应答端交还连接线程，文本捕获与分页都在后台完成，游标失效映射 `stale_cursor`。`terminal.wait` 在连接线程内 100 毫秒轮询前台最近帧 revision，超过 `since_revision` 即返回；超时映射 NotReady、关闭映射 Closing，默认与上限均为 600 秒。`terminal.close` 经写派发器复用既有终端关闭协调器，请求代次必须等于快照中的当前 PTY 代次（无 worker 为零），失配映射 `revision_conflict`；未知终端为 InvalidRequest。`terminal.reconnect` 复用同一焦点重连实现分发到稳定身份，只接受已退出终端；运行中映射 NotReady，成功分配新代次。`terminal.rename` 在候选快照更新自定义标题并复用同一持久提交，空白、超过 128 字符与未知终端均为 InvalidRequest，`null` 标题表示清除。`agent.list` 与 `agent.get` 经同一前台资源端口派生活跃关联，`agent.get` 按对外身份过滤，无匹配映射 `unknown_agent`。`agent.input` 与 `agent.close` 同时携带对外身份、稳定终端与 PTY 代次，AppRoot 必须重新派生该终端的当前身份并比对，失配映射 `unknown_agent`；close 的代次失配映射 `revision_conflict`，写入与关闭分别复用终端输入与终端关闭链。`agent.read` 与 `agent.wait` 复用终端分页读取与等待端口，但读取目标与等待目标携带 `agent_id`，由 AppRoot 在同一处校验身份后才访问 worker；结果形状与 `terminal.read`／`terminal.wait` 相同。`agent.start`、`agent.resume` 与 `agent.fork` 先经 AgentCatalog 解析 CLI 或校验会话身份构造命令，再复用新终端创建链并在首个真实提示符注入一次；未知 CLI、不支持的恢复／分支能力与非法会话身份均为 InvalidRequest，路径授权与终端创建错误沿用既有映射。`git.status` 前台只解析项目与仓库入口，仓库命令由连接线程在 GitFacade 后台执行；porcelain v2 快照映射为封闭条目，Git 访问拒绝映射 Unauthorized、其他读取失败映射 NotReady，错误不携带命令输出或路径。`git.diff` 只接受无 `..` 的仓库相对路径，前台只解析目标，后台以 `head_file` 与有界工作区读取构造同一 `compute_diff` 输入并渲染为仅含变更行的文本；revision 取正文 SHA-256 前 8 字节，旧游标在内容变化后返回 `stale_cursor`，二进制、非法编码与超限明确失败。`git.rollback` 与 `git.delete` 是破坏写：前台只解析项目与写授权并返回目标，状态重检与写盘在连接线程的 Operation 派发内执行，成功后尽力通知前台刷新同一项目的 Commit 视图；声明形态不再成立映射 `revision_conflict` 且不写盘，项目根外路径映射 Unauthorized，回收站不可用映射 NotReady 且不隐式升级为永久删除。OpenFile 仍返回 InvalidRequest。原因：控制面只转发封闭意图，项目选择、原子启动、授权与窗口行为必须由 AppRoot 单点复核。边界：仅成功后前置窗口并返回 accepted，不得隐式创建项目或改投活跃项目；snapshot 不得返回 PTY、输出、正文、凭据或非 Unicode 路径的有损替代。

## 验收与测试

- 定向测试：`cargo test -p slterm --test lib_tests local_control -- --test-threads=1`。
- 使用临时实例锁与 loopback 端点、内存凭据库和 `sk-test` 假凭据，覆盖 Primary 不评估移交目录、Focus/OpenProject 真实移交、缺失发现、陈旧端点、错误凭据、Closing、移交拒绝、非冲突锁错误与无效目录；断言真实线程退出，不访问真实用户数据根或凭据。另覆盖有效握手、真实运行世代与随包散列、结构化事件与回执断连、短超时注入、QueueFull、发布失败回收与回收错误聚合、重复终止错误、在途回执关闭、双失败关闭与端点撤销；另覆盖错误凭据、首包越序、超限请求与活跃连接 shutdown。
- 发现记录覆盖发布读取、损坏与超限、所有权撤销及写失败保旧；用真实 Win32 ACL 查询断言禁止继承、唯一当前用户 ACE 与宽 ACL 替换收敛，用真实 NTFS junction 覆盖 reparse 点防护，不得跳过。文件符号链接的权限边界与兜底见测试豁免表。
