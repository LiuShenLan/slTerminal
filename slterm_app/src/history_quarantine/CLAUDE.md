# history_quarantine（历史删除隔离）

> 用户明确删除的历史材料：不可变批次清单、持久逐项状态、导航执行面、启动对账与 ZIP 导出。

## 决策与红线

- **清单权威**：不可变清单保存来源/副本路径、顺序与确认指纹，路径按 UTF-16 无损；工作区 `quarantine_batches`/`quarantine_items` 只保存状态、进度、期限与逐项结果，不保存第二份路径。原因：状态与条目身份必须各有单一权威，不能从来源存在性推断完成状态。边界：清单必须先于副本与来源删除落盘；清单缺失或损坏进入待处理，不自动删除未知材料。
- **执行面单源**：导航删除、撤销、到期清理、ZIP 导出与永久删除都消费同一持久记录与清单；删除在后台先哈希来源再形成批次，逐项状态跨重启保留。原因：任何第二套内存或路径推断都会让隐藏集合与恢复集合漂移。边界：前台只做展示与派发，文件 I/O 与写线程回执都在后台。
- **永久化闸门**：永久删除必须持有显式确认值；完成批次只在撤销窗口之后可确认，待处理批次允许显式删除，未完成批次拒绝。到期清理只在启动维护期执行，排除待处理与未过期批次。原因：期限与用户确认必须同时约束物理删除。边界：删除失败保留清单与逐项失败事实供重试，不把导出当删除。
- **导出有界安全**：ZIP 只写清单原文与隔离副本，条目名由顺序号与白名单扩展名生成；总字节与条目数有界，临时文件原子替换目标，副本必须是隔离根的直接普通文件，拒绝 `..` 与 reparse 父链。原因：导出是外发材料，不能成为越界读取通道。边界：导出不清除任何隔离材料。
- **审计**：删除、撤销、导出、永久删除与清理逐项经 `audit` target 记录 operation/path/source/result；不记文件内容或凭据。边界：审计 helper 只接受封闭操作枚举。

## 验收与测试

- 定向测试：`cargo test -p slterm --test lib_tests --features gpui-test-support quarantine -- --test-threads=1`。
- 必测面：真实文件批次与部分失败、清单先落盘、ZIP 字节与 UTF-16 清单、大小上限、越界/reparse 拒绝、显式确认窗口、逐项删除失败重试、启动对账与过期清理、导航删除/撤销/导出/永久删除的真实入口。
