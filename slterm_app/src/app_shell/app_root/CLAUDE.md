# AppRoot 运行根

> 以唯一项目快照协调全部项目的运行面板、瞬时焦点与终端生命周期。

## 决策与红线

- **学习服务单源**：`AppRoot` 持有唯一 `LearningService`，每个补全 `Session` 共享其不可变快照；终端只经 Session 采集已确认命令与受管 cwd。原因：全局静态历史会形成第二写入与清空事实源。边界：不得在 TerminalView 或补全引擎另持历史文件、SQLite 连接或学习写队列。
- **项目与布局单源**：`AppRoot` 直持 `ProjectSnapshot`；`projects` 只是全部 `ProjectView` 的强实体引用表，不复制项目注册、布局、逻辑终端或 Document 元数据记录。原因：运行实例不得成为第二项目或布局事实源。边界：`ProjectView` 只持 `PanelHost`、项目焦点容器与项目内瞬时焦点，`PanelHost` 以封闭 `PanelContent` 绑定 `TerminalView`、`DocumentTextView`、`MarkdownView` 或 `PagedTextView`，不得为编辑器伪造终端字段。
- **渲染只读单源**：画面只沿活跃项目的 `ProjectLayout` 树、组内 active `ViewKey` 与既有 `PanelHost` 组装；隐藏项目不挂载但继续保活，空项目不创建占位终端。原因：渲染不得派生第二布局或触发终端生命周期。边界：组内非激活视图与隐藏项目均不进入当前画面，激活与切换只复用既有实体。
- **候选原子提交**：新增与拆分先由快照产生候选，再执行一次可失败启动并登记实例，最后提交候选。原因：布局、逻辑终端记录与 PTY 不得出现半提交。边界：启动失败不保留无 worker 的占位面板，正式快照与实例表不变；PanelId 失败消耗后也不复用。
- **Document 真实打开**：`open_document` 以 FIFO 在后台仅执行路径解析与真实读取，前台在读取前后查重并独占注册；`DocumentRegistry` 始终留在 AppRoot，不得在打开或保存期间移出形成前台空窗。回执基于最新快照构造 `with_opened_document` 候选，编辑器实体、焦点注册与还焦全部成功后才提交布局并发布同一快照。同项目重复打开按完整 ViewKey 只还焦，并复用同项目既有 Editor／Markdown；Diff／GitShow 不参与普通视图去重。跨项目打开复用全局 DocumentId 与既有正文；普通源码只安装 `DocumentTextView`，编辑经来源 EntityId 标记的同步端口写唯一 Registry，并按原事务向其余视图广播权威快照，历史移动广播无增量快照。`Ctrl+S` 只产生保存事件，由 AppRoot 按 DocumentId 持有后台保存任务并提交 core 回执；在途期间的新保存请求只保留一个待保存标记，回执后接续最新快照，失败经既有 Notification/i18n 回投原因并释放保存闸门，禁止视图另存 String 或直接写盘。快照提交同步回收失去全部项目引用的运行聚合、分页 reader 与对应页缓存；缓存清理前先显式关闭仍被关闭流程保活的 `PagedTextView`，取消任务并屏蔽迟到回执。超限文件直接注册完整 `PagedSource` 并安装 `PagedTextView`，跨项目视图复用同一真实读取端口和全应用页缓存，禁止以前缀 Rope 代替正文；重新打开命中恢复占位时按真实文件重读分页正文并用同一内容构造器替换占位，占位不是死端。HTML 编辑器悬浮按钮只发事件，AppRoot 经有所有权的后台任务调用系统默认程序，不保存脏正文；按钮可见性按自动语言而非手动覆盖。读取、落点、焦点、项目代次失败或关闭开始均不留下空 Panel，新建聚合随失败回收，共享聚合不得误删；关闭开始同时排空未开始请求并丢弃在途回执。原因：真实 I/O、身份与布局必须一次闭合，前台不得阻塞或出现半打开状态。边界：当前入口只支持代码与 Markdown 文本，不为图片构造占位面板；启动正文恢复只经真实快照恢复器与同一 Registry。
- **多项目 watcher 与外部变化**：AppRoot 持有唯一 `FsWatchHandle`，前台只经有界信号提交存活 Document 与瞬态改名别名，普通文件事件与改名都进入同一后台读取；目录树只由实际目录消费者登记。专用工作线程承担 notify 创建及 watch／unwatch 的同步 ACK，回调只分类并按因果顺序配对 From／To，隐藏项目继续监听。连续改名由当前、在途、待处理及最近目标别名路由到同一 Document，每个改名事件原子移除 source 并登记 target，折返不得保留失效中间目标；旧 revision、位置或已被更新目标取代的回执只重试最新目标，保存与改名按 Document 双向排队，批量 Save／Discard 同样等待并在改名完成后唤醒。后台经 `DocumentExternalService` 重新解析、授权与读取，回投再按最新快照复核 grant 并集；`Relocated` 只重绑位置，`Reload` 更新干净正文和元数据，脏或在途保存进入共享冲突，Deleted 保留正文，ReadRevoked 携带原请求与尝试位置并停止监听。位置候选先经 `with_relocated_document` 校验再提交 Registry 与同一快照；Paged 回执携带同批真实 reader，纯改名保留源代次与待续移动，内容变化推进代次，正文形态转换复用既有内容构造器且保持 PanelId 与 ViewKey；转换涉及的语言选择器先关闭并还焦到新面板，任一构造或焦点失败恢复 Registry 原事实、重新签发存活旧视图租约且不提交位置候选。原因：文件身份、持久元数据、正文和运行视图必须闭合，前台不得等待 OS watcher。边界：普通文件修改与 Explorer 目录刷新不因改名入口另建执行体。
- **局部终端关闭**：每个终端由独立 core `CloseCoordinator<String>` 管理 `CloseScope::Panels`、阶段与 attempt；close_id 使用 UUIDv7，`store_epoch` 只取 `AppRootPersistence` 启动恢复时同一工作区库读取的当前元数据，writer 存在而世代无效即拒绝，SHA-256 指纹只绑定关闭身份、作用域、世代、对象身份／代次／决定。生产顺序固定为单终端候选收集 → 快照与关闭意图原子提交 → 按完整目标从 `TerminalRegistry` 退休 worker → 后台 `TerminalSession::shutdown` 真实 join → `PtyStopped` → `CleanupCommitted` → `Completed` → Panel 销毁。初始 `CommitState` 在途或结果未知时，显式快照命令与任何新局部关闭都在 `sync_focus`、候选构造和写请求前拒绝，同一终端 Running 拒绝与 Failed 重试仍走原语义；无 Failed 关闭时，`CloseActiveTerminal` 先只读实际 GPUI 焦点以保留同终端 Running 语义，完成允许新关闭的纯预检后同步真实焦点并解析目标，writer 的有效 `store_epoch` 与目标存在性也必须在 `sync_focus` 和候选构造前验证，任何拒绝均不得改变焦点投影、代次、普通写或待写快照。项目快照恢复失败时，局部关闭的组合提交与普通／终态项目写共享恢复屏障，新关闭必须在任何 `sync_focus`、候选和写请求前以独立错误拒绝；显式目录继续打开与既有 Failed 重试不借此屏障改写语义。Exited 等内存更新延期普通写，`AppRoot::drop` 也复用同一 Running／Failed `CommitState` 屏障，禁止补交终态快照。`StateCommitted` 成功后从最新内存快照重算关闭候选，再摘除渲染、还焦、注销焦点与订阅，Panel 实体保留到 Completed。明确初始提交失败清除本次关闭并恢复延期写，后续明确推进失败保留 Panel 并从当前持久阶段显式重试；回执断连或重复任务导致结果未知时 fail-closed，禁止盲目重登记。join Err 不推进持久状态，只有用户显式重试才可消费已观察到的异常终止事实，不得二次 join、重开 PTY 或记录 panic payload；commit／advance 回执须先核对 close 存在、attempt、目标 next 与当前持久前序，并完整比对 close_id、scope、store_epoch、对象与指纹，全部通过后才可收割任务或改态，close 缺失、stale、错身份、错 next、错前序一律忽略且不触碰任务。还焦失败不得裸送 workspace 焦点绕过模态，只能 blur 原聚焦终端并经 FocusManager 同步实际焦点。局部关闭不停止全局服务、不写 `clean_shutdown`，任一局部关闭存活时 `request_close` 返回 false，全局 `close_in_progress` 拒绝新局部关闭；无 writer 仅允许既有内存测试根走无持久化同序降级。
- **局部关闭用户重试**：`CloseActiveTerminal` 对曾失败且未 Completed 的局部关闭按单调发起序号选择最早项；已知 Failed 经原目标显式重试，未知结果仍明确拒绝，初次 Running 不进入失败重试，重试后的 Running 仍返回 Running 并阻断后续目标。全部曾失败关闭 Completed 前不得解析或关闭新的焦点终端，CommandRegistry 不得因当前无 focused terminal 或无活跃项目提前阻断这条重试；全部解决后才恢复正常 focused close。原因：StateCommitted 后真实焦点可能已还到其他终端或项目容器，焦点目标不能再代表失败关闭身份。边界：重试只推进原持久阶段，不复活已摘除的渲染，不提前销毁 Panel；多个失败按发起顺序逐一处理，不按 TerminalId 或同毫秒 UUID 的隐含顺序选择。
- **组内批量关闭**：完整页签列表的关闭其他／全部只构造统一命令；关闭其他保留组内 active，关闭全部移除组内全部目标视图。全部目标在同一 `ProjectSnapshot` 候选、同一 `CloseCoordinator` 与完整 `CloseIntent` 中提交；含 Save 决定时先在前台捕获不可变保存请求，后台仅执行条件写盘，前台再按代次结算全部回执；任一失败保持 Failed(Save) 且不得提交候选、摘除 Panel 或停止 PTY，全部成功才进入 CommitState。目标已有在途保存或外部变化时，Save 保持 Running(Save)，Discard 保留待提交标记，均待原回执结算后再推进；实际提交前再次检查在途外部工作，等待后的关闭候选从最新 `ProjectSnapshot` 重算，不得提交等待前的位置副本；Save 在全部回执结算后、`save_succeeded` 前再次核对全部待关闭 Document 的当前 revision，任一 Document 在写入期间的新编辑必须转为 Failed(Save) 并保留面板；Discard 恢复提交前同样核对代次。代次失配的显式重试经 core `recollect` 复用 `collect_document_close` 按当前快照与 Registry 重算代次和关闭决定，仍适用的原 Save／Discard 决定保留，新变脏的最后引用必须取得新决定，普通 I/O 失败仍按原阶段 retry；等待与恢复调度按 TaskId 幂等，重复回执不得把正常关闭打成 outcome-unknown；原子提交成功前不得停止任何 PTY 或摘除面板；StateCommitted 后统一还焦并复用局部关闭的持久推进，按成员保存停止观察事实，停止回执须先证明成员集与批次完全相等且无重复，缺失、重复或未知身份一律标为结果未知且不得留下部分观察；后续失败只能显式重试原批次且不得二次 join。批量与单终端共享单调发起序号和较早失败优先闸门，关窗与项目移除必须等待存活批次。原因：逐条关闭会形成半批快照与不可恢复的失败顺序。边界：空组由 core 布局转换塌缩；没有真实 PanelHost 的视图明确失败，Document 经 `collect_document_close` 去重并执行最后引用与集合外引用守卫，无 Session 的授权或替换占位只随布局关闭、不伪造保存对象，终端与编辑器 Panel 共用还焦、注销和销毁链，不伪造终端或编辑器运行状态。
- **项目移除关闭**：`RemoveProject` 以稳定 ProjectId 为封闭命令目标，同一入口负责发起与明确失败重试；每个项目由独立 core `CloseCoordinator<String>` 管理 `CloseScope::Project`，同时最多一个项目关闭，目标存在局部终端关闭或全局关闭在途时拒绝。初始原子提交保存其他项目与新活跃项、登记删除意图，但保留目标项目、布局与终端到后续清理；StateCommitted 后从最新内存快照移除项目、摘除渲染与焦点注册，同步封锁该项目 Editor ViewState 的旧实例写入，移除活跃项时按既有恢复语义补齐下一项目隐藏 Launch，全部普通项目写延期到 Completed，Drop 同样受屏障。所属全部 session 在后台逐一显式 join，任一 panic 只记录观察事实并由同一命令显式重试后消费，不二次 join；PTY 停止后的专用事务原子删除项目、纯数据库布局／终端、目标项目独占 Document、项目 ViewState 与 Nav／Explorer 分区，并保留其他项目共享 Document，内存 SideView 同步清理，Completed 才释放 ProjectView 并恢复延期写。回执先校验完整身份、attempt、阶段与持久前序再收割 `TaskId::ProjectClose`；断连或重复登记导致结果未知时 fail-closed，禁止盲目重试。项目关闭存活阻止关窗，不停止全局服务、不写 `clean_shutdown`。单终端、批量与项目移除三条面板销毁链统一经 `forget_panel_runtime` 清理 AgentHub 关联与 pane 级任务栏进度。
- **项目快照持久提交**：项目、布局、激活关系与 RunIntent 的候选提交统一经 `commit_project_snapshot` 进入 WorkspaceWriter 的既有去抖队列，不在各命令另建 Terminal 写通道。普通队列拒收时保留最新待终态，后续成功入队作废旧副本，AppRoot 析构只在 `CommitState` 屏障解除后补交仍未解决的快照。原因：运行快照与持久事实必须同源，且前台不得等待 SQLite。边界：只有已提交候选才入队；恢复失败期间普通与终态项目写均受屏障保护，只有成功重载对账或用户显式破坏性重置才能解除；显式启动失败保持原快照与原实例，终态移交不阻塞 GPUI 前台。
- **无项目设置浮层**：`Ctrl+,` 经统一命令目录创建由 AppRoot 直接持有的应用级 `SettingsView`，使用 `ViewKey::AppSettingsOverlay`，不挂靠任何 ProjectView；浮层为非模态全局焦点节点，项目激活或切换只改变项目作用域，不销毁或重置浮层，重复入口只还焦既有实体。Escape 与“返回工作区”共用显式关闭链，先还焦再注销注册并释放实体。原因：浮层草稿与页内状态的生命周期不能误绑当前项目。边界：没有既有浮层且已有活跃项目时，本切片明确拒绝创建伪装的项目 Settings；项目面板、独立 ViewState 和 Hooks 草稿归后续设置与 Hooks 切片。
- **设置中心字段控件**：字段行的唯一来源是 `settings_controls` 的静态字段表（页面、分区、标签、说明、控件形态与选项），键集合与 `slterm_settings::SettingsRegistry` 双向强等；主题编辑器专属键由宿主管理并显式排除。控件提交只调用 `AppRoot::apply_settings_field`：注册表校验是唯一闸门，非法值只显示瞬态提示；合法值进入 `SettingsStore`（自动字段去抖、显式字段立即到期），随后 AppRoot 重建全局设置快照并热应用主题、语言、托盘与后台任务配置。写盘只经 `TaskId::SettingsSave` 后台批量：前台提交快照，回执清除与已写值一致的待写项并保留期间的新编辑，失败保留待写并退避一个延迟窗口。原因：控件、运行值、持久值与副作用不得各自维护第二份事实。边界：视图渲染只读取字段值快照，不借用 store 内部引用；文本控件初始值在构造时注入，不在 AppRoot lease 内回读。
- **Hooks 编辑页**：Hooks 页只编辑 Claude 的 JSON 子树；User 层路径来自 Claude 配置目录，Project／Local 层固定为项目根的 `.claude/settings.json` 与 `.claude/settings.local.json`。载入、保存、丢弃全部是后台任务：载入产出 `HooksDocument`（含根文件基线与安装器认领组），保存经 `save_editable` 在锁内重读基线并原子写，外部修改或删除零写入并保留草稿；丢弃只移除草稿与文档后重新载入。前台持有草稿文本与解析诊断，编辑器内容由草稿代次在帧间回填（`defer_in`），不参与持久状态。原因：真实配置写入不得阻塞前台，且认领组与外部修改守卫只能由唯一文档事实保证。边界：面板稳定身份安装后绑定；应用级浮层没有项目身份时只提供 User 层，并以 `HooksDraftOwner::Overlay` 持有独立草稿键，浮层关闭即释放该草稿；项目移除与根重定位守卫只看存在未提交编辑的 Project／Local 草稿，与磁盘一致的干净草稿不阻塞（打开页面产生的干净草稿不承载用户数据）；层读写前必须证明真实根目录存在，缺失时禁用 Project／Local 并拒绝保存，绝不在缺失根下重建配置；保存成功后清除草稿并提示重启对应 CLI 会话，继续编辑从磁盘基线重建草稿；User 层保存前显示任意命令执行警告，页面提供显式重新加载入口；面板销毁与项目专属清理必须同时释放草稿、文档与诊断，不留指向失效 PanelId 的孤儿键；测试注入 Claude 配置目录，不触碰真实 home。
- **授权代次单源**：文件授权代次由进程级 `app_shell::authorization` 提供；项目移除、项目重定位、Agent 根增删改路径必须推进代次。创建计划、开始保存与执行写盘分别读取最新代次，旧代次计划或在途保存一律失败。原因：恒零代次会让撤销后的旧授权继续生效。边界：测试用代次必须与请求一致，不得回到硬编码 0。
- **Agent 根身份**：Agent Files 的持久分区身份是「根 id + 路径」；同 id 改路径按撤销旧身份处理，运行态、展开目录、当前行与授权代次一起清理，新根按新身份登记。原因：路径变化后旧目录状态不得套用到无关目录。边界：只由根同步入口裁定，测试不得绕过同步直接调 remove。
- **AgentHooks 页端口**：AgentHooks 页的安装状态探测与 hook 安装/卸载只在后台执行体运行，前台只读快照、提交显式设置值并展示脱敏状态（失败只留封闭标记，不携带命令或配置正文）。探测只在进入页面或恢复面板停在该页时触发一次，重复请求复用同一任务；安装/卸载成功后才重新探测，失败保留开关值以便重试。原因：探测与安装是阻塞 I/O，且真实用户配置写入路径只能在后台。边界：测试经注入端口运行，不读写真实 home。
- **生产快照恢复**：`AppRootPersistence` 在首帧前经工作区库恢复唯一 `ProjectSnapshot` 与侧栏状态，AppRoot 据此创建全部项目实体并初始化 FocusManager 的活跃项目作用域，再按已归一布局安装恢复 Document 的 Editor／Markdown／Diff，或共享的专用授权、Paged、身份替换占位，重复恢复只复用既有 Panel，启动不送焦、不回写解析结果；恢复编辑器与启动读取共享全部 Ready 项目根的能力并集。常规启动有恢复项目时不额外打开 cwd，空工作区才走初始项目链，显式目录仍走既有打开链。Editor、Markdown 与 Diff 阅读状态在 GPUI 前按恢复快照中的完整 ViewKey 经同一 ViewStateStore 预载，Diff 同时从专属状态恢复固定 DiffBinding，不随项目根重定位改绑且保持 HEAD 旧路径；新固定绑定只在面板真实安装后发布，失败重试不得继承未生效请求，新打开同样遵守项目快照命令屏障；未知或损坏记录不回写默认态。文件缺失或不可解码的干净 Document 同样保留明确的不可用占位（可由页签关闭入口移除），不得静默丢面板。原因：首帧不得闪现默认布局，恢复也不得复制持久事实或制造新项目。边界：常规启动恢复失败不得按空工作区打开 cwd；显式目录可继续打开，但项目写屏障不得解除；后续损坏诊断与只读维护界面由 Startup 协调承接。
- **Diff HEAD 可见性复核**：Diff 只在所属项目可见且所在组 active 时读取 HEAD；隐藏立即取消任务并使旧票据失效，多次隐藏事件只保留合并位，重新可见只复核一次，可见时至多一个在途任务，stale 回执不得结算新任务。原因：不可见面板不得累积后台读取，也不能让旧结果覆盖新绑定。边界：只在原 `RepositoryBinding` 仍证明同一仓库时经 `DiffBinding::refresh_head` 推进提交，HEAD 旧路径不变；根重定位或读取失败保留最后一次已验证快照与绑定，Panel 销毁同时取消任务并删除刷新代次。
- **Editor Git 行标**：每个 Editor Panel 以同一 `GitFacade` 捕获当前 `DiffBinding` 与固定 HEAD，再以共享 Document 的最新 Rope 调用 core `compute_diff`；不读取工作区副本，不接 `file_hunks` 或另一套 LCS。编辑广播期间不得重入读取来源 Entity，捕获延迟到广播结束；同一 Panel 至多一个在途计算，连续编辑只采纳最新 TextStateId，已验证 HEAD 可供下一次计算复用。行标点击经既有 `open_diff` 打开同一 Document 并定位目标差异，HEAD 或新差分在途时目标行保持挂起，直到可映射到真实差异块；关闭与内容形态转换同时取消任务并清除状态。原因：行标、Diff 与保存必须共享正文、差分语义和生命周期。边界：非仓库或读取失败不产生伪行标，旧代次结果不得回投。
- **终端恢复运行态**：恢复按 `ProjectLayout::view_keys()` 顺序创建活跃项目实例；可见 Launch 只启动一次，隐藏项目先保留记录并在首次激活时懒启动，Exited 只恢复退出状态而不创建 PTY；无旧 worker 的持久化 Exited 可在原 Panel 内经 Registry 启动新代次，已有旧 worker 则继续走保留回滚的重连链。启动或元数据失败保留错误面板且不重复记录。默认焦点从布局首个目标组的 active 面板解析，激活与重复打开必须在懒启动和焦点可见性同步前完成默认焦点解析及模态、token、项目作用域纯预检，失败不得产生 PTY；恢复后无失败重算实际 default 并经同一纯预检，无法采用时回退已预检 token，激活自身错误不得吞没。原因：持久运行意图决定恢复副作用，显式新建的原子失败与送焦语义不能直接复用，恢复前原子预检也不能把首次激活焦点固定在项目容器。边界：终端输出、回滚与未知退出码不伪造恢复；已有实例再次激活不重建并保留运行期焦点记忆，隐藏项目的存活实例继续保活，恢复错误面板不新增激活失败语义。恢复与重连只在真实 CreateProcess 目录错误后回退所属项目根并发出脱敏提示，不为 Shell 缺失或其他错误重试；AgentSession 随同一 ProjectSnapshot 原子提交，命令边界只更新 AgentHub 与该候选，不建立第二身份或状态写通道。
- **单实例项目与终端移交**：`HandoverParams::OpenProject` 先经 `CanonicalPath::new` 纯校验，再经 FIFO `ProjectPathResolver` 后台解析并复用候选 `add_project`；只有实际完成后才前置窗口并回执 accepted，解析或提交失败不改变原项目关系；新增根只打开空项目，重复根激活既有项目，均不得隐式创建 Terminal/Panel；OpenProject 仅非法路径映射 InvalidRequest、模态映射 Unauthorized、其他失败映射 NotReady，失败保持快照、实体、Panel/PTY 与焦点事实不变。`HandoverParams::NewTerminal` 同样先纯校验路径并复用 `CommandRegistry`：显式根只精确匹配既有项目，仅有 cwd 时选择根覆盖 cwd 的最深项目，两者同时提供时 cwd 必须位于显式根内，两者皆无才使用活跃项目；未知根、无覆盖 cwd、跨根 cwd 与模态均为 Unauthorized，非法路径为 InvalidRequest，其他未就绪失败为 NotReady，错误脱敏且不得改投或隐式创建项目。所有 NewTerminal 请求先同步真实焦点，再解析目标与克隆候选。隐藏目标的候选快照同时包含项目激活与新终端，目标组先复用焦点记忆，无可用面板焦点时按布局顺序选择既有组，空项目生成首组；launcher、实例登记、FocusManager 项目激活与新终端聚焦全部成功后才提交，失败须清理 launch、恢复原 active 与实际焦点，成功后按既有恢复语义补齐其余隐藏实例。原因：第二实例必须共享项目、授权、目录和焦点语义，前台不得执行路径文件系统 I/O，隐藏恢复不得破坏原子提交。边界：仅成功后才前置窗口并返回 accepted，Closing 优先；OpenFile 的独立目标、回执与错误边界见下条。
- **窗口几何观察**：`AppRoot::observe_window_geometry` 订阅窗口边界变化，前台只覆盖最新 `WindowGeometry` 并经 500 毫秒去抖任务提交 writer；替换任务即取消上一次去抖，AppRoot 销毁后任务随实体取消。无 writer 的内存测试根只观察不写盘。原因：拖动与缩放不得放大写盘，几何必须与真实窗口状态同源。边界：几何只在开窗链恢复（夹回可见工作区），运行期不回写窗口 bounds。
- **Runtime 快照端口**：`runtime.snapshot` 的只读资源只由 `AppRoot::runtime_snapshot_resources` 在 GPUI 前台按请求时刻从唯一 `ProjectSnapshot` 派生；项目、面板组、终端与 Document 身份及元数据一次成稿，视图身份使用规范 ViewKey JSON 文本；终端资源携带 Registry 当前 PTY 代次（无存活 worker 为零），供写方法定位。请求经 `SltermShellEvent::RuntimeSnapshot` 有界通道进入，回执容量 1 非阻塞；关闭中、关闭完成或存在 application close 时返回结构化 Closing，事件泵排空同批请求时同样回执 Closing。原因：快照必须与前台同一状态时刻一致，跨线程读共享可变状态会绕过单源。边界：快照不含 PTY、输出、正文、Agent 运行态或凭据；非 Unicode 路径与规范编码失败明确报错，不返回截断快照；事件环接入前 revision 由服务端按握手起点填写。
- **Runtime 写意图**：`handle_runtime_mutation` 只接收已解析的封闭意图（项目激活/重命名/排序/移除；组拆分/合并/比例；面板激活/移动/设置；终端新建/输入/执行/关闭/重连/重命名），全部复用 `activate_project`、`RenameProject`、`MoveProject`、`RemoveProject`、`SplitView`、`MergeGroups`、`ResizeSplit`、`MoveView`、`activate_view`、`open_settings_from_request`、`new_terminal_from_request` 与同一 `CommandRegistry`；关闭中、关闭完成或存在 application close 时在命令前返回结构化 Closing。`terminal.input`／`terminal.execute` 只经 `runtime_terminal_view` 按稳定身份与 PTY 代次定位运行中视图，再调用 `TerminalView::runtime_input` 写唯一 worker；input 原样写入，execute 追加一次回车；记录非 Launch、目标或面板缺失、代次不匹配一律 NotReady，不猜测重连后的新进程。`terminal.close` 先要求快照记录存在，再要求请求代次等于 Registry 当前代次（无 worker 为零），失配返回结构化 RevisionConflict，匹配后复用 `close_terminal` 的既有持久关闭链；`terminal.reconnect` 走同一代次预检后调用按稳定身份抽取的 `reconnect_terminal`，与焦点重连共享实现，只接受 Exited 记录；`terminal.rename` 经 `with_terminal_custom_title` 候选更新标题并复用同一持久提交，布局、焦点与 PTY 保持不变。原因：Runtime 不得形成第二套项目写路径，授权、事务、焦点与关闭策略必须由既有命令单点裁定。边界：意图只含稳定身份与已校验输入，路径与授权解析不在本层；错误只映射为封闭领域码，不携带路径、SQL、正文或命令细节；新增写方法必须先接入真实命令再接事件。

- **Runtime Git 目标**：`runtime_git_target` 只在前台解析项目（缺省取活跃项目）与仓库根，返回项目身份、根与 `Arc<GitFacade>`；仓库读取、授权并集与 porcelain 解析全部在连接线程内后台执行，前台不 spawn git 子进程。原因：Git 读取是阻塞 I/O，且项目根解析与授权必须复用同一 GitFacade。`runtime_git_diff_target` 复用同一项目解析并校验仓库相对路径（非空、不以分隔符开头、不含 `.`/`..` 或反斜杠），把已校验路径与仓库入口交后台。边界：未知项目与非法路径为 InvalidRequest，无活跃项目为 NotReady，仓库状态错误映射不改写持久状态。

- **Runtime Git 破坏写**：`git.rollback` 与 `git.delete` 经写意图进入 AppRoot，但只在前台校验路径形状并解析项目与写授权，回执返回 `GitWriteTarget`（项目、项目根、`GitFacade` 与 `FileOperationService`），阻塞的状态重检与写盘由连接线程在 Operation 派发内调用 `git_changes` 的同一执行体完成；成功后经 `RuntimeGitRefresh` 尽力刷新同一项目的 Commit 视图。`git_changes` 同时服务 Commit 面板回滚/删除，破坏写进程内串行，写前重读状态复核调用方声明形态，前置不成立返回结构化 RevisionConflict 且不写盘，项目根外路径为 Unauthorized，结果只经 audit 通道记 operation/path/source/result。原因：Runtime 与面板不得形成两套回滚/删除语义，GPUI 前台也不得等待 git 子进程。边界：状态重检使用独立 `GitFacade` 避免命中共享缓存，成功后使共享状态缓存失效；回收站不可用只失败，不隐式永久删除；刷新事件尽力投递，丢失不影响已完成的写。
- **Runtime 应用聚焦与关闭**：`app.focus` 只调用窗口前台聚焦与重绘；`app.close` 先把封闭策略翻译为每文档 `CloseDecision`，Hooks 草稿只支持显式丢弃（`discard_all_hooks_drafts_for_close` 只清内存并递增代次），缺决定返回 `decision_required` 且不触发任何交互通知。`start_application_close_with_decisions` 返回 `Completed｜Started｜Deferred｜Rejected`：决定齐备性先于无 writer 的完成路径；需要保存而无 writer 时明确 Rejected；在途文档工作期间 UI 路径保留决定并在恢复时继续，Runtime 路径明确 NotReady，不在无法稳定判定决定时接受关闭。原因：非交互关闭不得用 best-effort 丢弃正文，也不能把未开始的关闭伪装成成功。边界：`app.close` 的成回执表示关闭已开始推进，进程退出与连接断开仍可能发生。`panel.close` 只关闭目标视图并复用批量关闭链：先探测最后引用的脏 Document，缺策略返回 `decision_required`，策略齐备后以单视图集合登记关闭。`panel.close` 与 `project.remove` 的显式 Save／Discard 只覆盖关闭集合内最后引用的脏 Document；集合外仍有引用的共享 Document 不产生决定，避免核心判为外部引用而拒绝整单。
- **项目移除保存阶段**：项目关闭现在按 `CloseCoordinator` 的 Save 阶段执行：收集项目视图最后引用的 Document 决定，`requires_save` 时先真实写盘与代次校验，成功后才提交删除意图，失败停在 Save 并保留项目；Runtime `project.remove` 把封闭策略翻译为每文档决定，Hooks 草稿只支持显式丢弃，缺决定返回 `decision_required`。原因：项目移除不得静默丢弃脏正文，也不得把未开始的关闭伪装成成功。边界：清理阶段失败沿用既有重试与失败态；无 writer 时移除明确失败。
- **Runtime 面板打开与保存**：`panel.open_file` 复用 `prepare_document_handover` 与 `queue_document_open`，回执经 `RuntimeMutationCompletion` 在打开完成后发送，回调未兑现即由守卫回执 Closing；`panel.save` 只解析 `editor｜markdown` 视图的 Document，把回执登记进 `runtime_save_waiters` 并调用同一 `save_document`，唯一保存链在写盘落定后结算等待者，仍有排队保存时不提前成功。原因：打开与保存不得出现第二执行路径，Operation 结果必须对应真实副作用。边界：非文本视图、布局外视图与未知 Document 为 InvalidRequest；保存错误只映射封闭 NotReady，不携带路径或底层文本。
- **Runtime Git 打开**：`git.open_diff` 与 `git.open_deleted` 只在前台解析项目并返回 `GitOpenTarget`；连接线程复核状态映射并捕获仓库绑定后，经 `RuntimeGitOpen` 事件把已捕获绑定交回前台，`open_commit_diff_path`／`open_commit_gitshow_path` 与 Commit 行激活共用同一打开链、落点与 Document 等待队列。原因：Runtime 不得复制打开映射或另建文档/面板打开路径。边界：事件携带装箱绑定以保持枚举紧凑；映射不一致在投递前拒绝，前台只执行已接受的打开；关闭中拒绝。
- **Runtime Agent 资源**：`runtime_agents` 只在前台按请求时刻派生：遍历唯一快照的终端记录，运行期会话身份优先、持久 AgentSession 回退，状态取 `AgentHub` 仲裁器；纯 Shell 不产生关联行，同一原生会话 ID 可出现在多个终端关联中。对外身份有原生会话时用 `kind:native_session_id`，否则用 `kind@terminal_id`。写方法必须同时提供对外身份、稳定终端与 PTY 代次，`ensure_runtime_agent` 重新派生目标终端当前身份并比对，失配返回 UnknownAgent；`agent.input` 复用终端输入通道，`agent.close` 复用终端关闭协调器，`agent.read`／`agent.wait` 复用终端读取与等待端口并在同一校验点比对身份，不另建 Agent 专属执行路径；`agent.start`／`agent.resume`／`agent.fork` 先由 `AgentKind` 与会话身份构造并校验命令，再复用 `new_terminal_from_request` 建终端并通过 `schedule_agent_command` 在首个真实提示符或超时后注入一次，未知 CLI 与不支持的动作返回 InvalidRequest。原因：活跃关联必须由同一 PTY 映射与会话事实派生，不能另存持久活跃映射。边界：不返回正文、历史记录或凭据；终端的持久会话身份与运行期 hook 状态都缺失时不猜测。

- **Runtime 读取端口**：`handle_runtime_read` 与写意图共用 `runtime_terminal_view` 的稳定身份与 PTY 代次校验，写输入要求 Launch 意图、只读画面允许已退出终端；校验通过只向唯一 worker 发送 `ReadText` 并把应答端交还调用方，前台不等待文本、不锁实时网格。`handle_runtime_wait` 复用同一校验，只返回视图最近帧 revision，不等待变化。关闭中、关闭完成或存在 application close 时在命令前返回结构化 Closing。原因：读取必须与绘制同源且不得在前台阻塞。边界：不缓存正文、不提供增量输出流；代次不匹配、目标或面板缺失一律 NotReady。

- **Runtime 事件发布**：轻量事件只在后台状态提交成功后由 `publish_runtime_event` 发布（当前含项目激活；面板与终端事件随各方法族接入），负载只含类型名、资源身份与 `snapshot_generation`，revision 由事件环分配。发布经 `RuntimeEventPublisher` 非阻塞提交，队列满丢弃事件；关闭中、关闭完成或存在 application close 时不发布，避免销毁后回填过期事件。原因：事件必须与前台状态同源、同序，且不得反压 UI 或 PTY。边界：事件不含正文、路径内容、凭据或终端输出；隐藏项目的状态变更同样发布；不提供补发或内存重放通道。

- **单实例文件移交**：`HandoverParams::OpenFile` 先纯校验 `CanonicalPath`，选择覆盖目标的最深既有项目根，不隐式创建项目；复用 Document FIFO 后台解析与读取，活跃项目使用聚焦组，隐藏项目复用焦点记忆或布局首组，空项目的首组延迟到请求完成时按最新布局解析，排队请求不得持有过期组 ID。项目激活、视图去重或安装、Editor 落点和真实焦点全部成功后才提交候选并前置窗口；失败恢复原 active 与实际焦点，不留下新 Document 或空 Panel，共享 Document 不误删。全部可失败准备完成后才移交 completion，活动、排队与在途请求在关闭时恰好结算一次 Closing；非法路径与不支持类型映射 InvalidRequest，无覆盖根、解析越权与模态映射 Unauthorized，其他读取与未就绪失败映射 NotReady，回执不得携带路径或正文。原因：第二实例必须与应用内打开共享身份、授权、布局和焦点事实，且不能出现半激活或丢失回执。边界：不为 OpenFile 创建第二套读取、落点或占位面板通道。
- **生产身份与落点**：打开项目、新建与拆分命令由 application 以 UUIDv7 生成稳定身份；固定身份入口只供恢复协调与测试。普通新建进入活跃项目当前聚焦组，空项目生成首组；handover 新终端按移交规则选择目标项目与组；拆分必须已有聚焦组，关闭聚焦终端复用同一显式关闭链。原因：调用方不得自行拼身份或另判布局落点。边界：无活跃项目或应有聚焦组而缺失时明确失败，不隐式选择隐藏项目。
- **终端 cwd 授权**：未提供 cwd 时只使用目标项目根；显式 cwd 必须位于该项目根内，并在调用 launcher 前完成校验。原因：新终端不得继承另一终端目录，也不能因越权路径消耗 PTY 或 Panel 身份。边界：非法或越界 cwd 保持快照、实例和启动次数不变；Shell 内后续 `cd` 不改变既有授权来源。
- **项目元数据与真实路径打开**：重命名与排序经 `CommandTarget::Project` 和统一候选提交，只改名称或导航顺序，不改变活跃项目、布局、Panel 或 PTY；空白、超长与越界输入保持原快照。OpenProject／OpenDirectories／初始打开共用 FIFO 解析队列，系统 canonicalize 与目录校验只在 background executor，任务归 TaskService，完成回前台后仍经同一 `add_project` 候选链；后一请求不得先于前一请求提交，失败不得新增项目、改投活跃项或伪造 handover 成功；completion 统一结算且只允许一个活动任务，关闭入口立即取消并排空队列，handover guard 在窗口或实体销毁时兜底 Closing。原因：项目关系与焦点必须确定，且真实路径 I/O 不得阻塞前台。边界：固定身份与假解析器只用于内存测试；生产不得绕过真实路径端口直接打开外部根。
- **可失败启动接缝**：终端先经 `TerminalView::launch` 冻结配置并启动 PTY，成功后才经 `from_launched` 构造实体。原因：GPUI 实体构造不能直接返回启动 `Result`，失败不得先挂实体再补救。边界：成功启动只执行一次；非 Unicode Shell 路径在参数组装前拒绝，不做有损转换。
- **项目切换保活**：`TerminalView` 强持于各自 `ProjectView`，全部 PTY worker 由 AppRoot 的 `TerminalRegistry` 统一强持；切换只调整 `output_visible` 与焦点，隐藏项目的既有会话泵、输出解析和回滚继续运行，重新可见时主动补帧。原因：项目导航不得重建终端或丢失后台输出，View 也不得成为第二 worker 所有者。边界：普通显式新建只面向活跃项目；handover 仅按单实例移交规则选择既有项目，隐藏项目 Launch 的其余懒启动由恢复协调负责，不在普通显式命令中暗中 spawn。
- **退出与关闭分离**：TerminalView 的 Exited 只把逻辑记录改为 `RunIntent::Exited`，保留面板、实体、显示订阅与最后画面；显式 close 才从 Registry 退休 worker 并释放实例。`ReconnectTerminal` 只允许已退出终端，预检快照候选后才启动新 PTY；成功切换代次、提交 `RunIntent::Launch` 并按旧目标后台回收，失败保留原 Panel、旧 worker 与可见错误。原因：进程退出不是用户关闭面板，退出后仍须允许滚动与复制，重连不得形成第二生命周期通道。边界：重复或迟到的退出事件不得关闭其他面板或终止显示订阅；未知运行身份不猜快照目标。
- **应用退出局部关闭**：OS 关窗与 `TrayQuit` 统一经 `request_close` 创建 `CloseScope::ApplicationExit`，先等待在途 Document 保存／外部工作，再对全部视图统一收集 Document；自动保存只给合格文档提供 Save，其余脏文档未取得显式决定时取消退出并保留窗口，保存期 revision 变化后的重试必须重收集；随后收集全部逻辑终端，先移交 SideView 终态，再原子提交 ProjectSnapshot 与关闭意图；全部 session 在后台逐一显式 join，随后依次提交 `PtyStopped`、`CleanupCommitted`、`Completed`，只有 Completed 才进入 `StopServices` 并复用最终 flush。初始明确提交失败清除本次关闭并恢复编辑；停止后的明确写失败保留窗口，从原持久前序显式重试；join panic 只有显式重试才消费观察事实，不二次 join。断连或重复任务登记导致结果未知时 fail-closed，禁止盲目重登记；回执须先核对完整身份、attempt、next 与持久前序，再收割 `TaskId::CloseFlush`。`application_close` 存活即冻结命令与 handover，即使失败已清除 `close_in_progress` 也不得解冻。原因：窗口销毁不得掩盖持久提交、PTY 回收或回执身份错误。边界：局部段不写 `clean_shutdown`；生产最终 flush 成功后经全局 client 请求 GPUI 外所有者，只有收到服务停止与正常退出提交完成或知情放弃回执，才推进 core 全局阶段并销毁窗口；恢复失败只冲刷既有写屏障且不登记关闭意图，但同样经 `recovery_global_close` 等待全局回执，不得绕过全局段直接销毁窗口；其回执以独立 close_id 与单调 attempt 隔离重试，Disconnected 同样 fail-closed；无 writer 仅允许内存测试根直接关窗降级，包括恢复失败组合。
- **关闭冲刷与冻结**：正常 ApplicationExit 的局部段 Completed 后，以及恢复失败屏障路径，均由 `submit_final_states` 移交项目、侧栏组织与 SideView 私有终态，再由 `WorkspaceWriterClient` 在后台执行可重试 flush；flush 失败保留窗口并允许重试，已停止的 PTY 不得因此重开。每次快照提交推进代次，Flush 返回时若代次已变化则重新移交并再次 Flush，只有最新代次零失败才进入后续退出。生产全局 client 存在时，flush 成功只发起全局段，Completed 或 Abandoned 回执才允许移除窗口；`AppRootServices` 以非可选全局 client 保证生产开窗注入；无全局 client 的虚拟窗口测试根沿用 flush 后直接关窗。`close_in_progress` 拒绝新命令、项目切换、鼠标激活与几何拖动，关闭时取消既有手势；`close_completed` 终止当前壳事件批的领域处理，同批剩余 Handover 仍逐一非阻塞回复 Closing、其他事件丢弃，关窗回调只弱持 AppRoot。原因：最终持久提交失败或过期不得被窗口销毁掩盖，也不得形成第二退出通道。边界：GPUI 前台不等待数据库、控制面或 writer shutdown；正常退出标记由 GPUI 外的全局关闭所有者提交。
- **任务所有权**：`TaskService` 集中登记封闭 `TaskId`、GPUI `Task` 与显式取消令牌，禁止 `detach`；局部关闭按 `TaskId::TerminalClose` 分终端持有，组内批量按 `TaskId::TerminalCloseBatch` 持有一个任务，重复身份拒绝且不得构造或丢弃替代资源；已发请求的重复登记只把本次结果标为未知并保持写屏障，原任务身份必须保留，未知结果处理不得顺带收割原任务；Running `StopPty` 的重复调度则保持幂等，不构造替代任务、不转 Failed、不标未知，保留原 attempt 与任务并等待原回执收割推进。shutdown 先标记全部取消再释放句柄并清除视图代次，AppRoot 析构复用同一路径。可见性复核以 `ViewTaskOwner` 与单调代次票据归属：可见时至多一个在途任务，其余事件只置合并位；隐藏立即使旧票据失效，重新可见只启动一次合并复核，当前完成后再启动已合并请求，stale 回执不得结算新任务。显式保存与文件操作结果不随视图显隐清除，也不另建内存结果副本。原因：周期与关闭任务必须有确定所有者与取消边界，不能留下游离循环或让 stale 回执取消新 attempt。边界：壳事件泵只经该服务注册，后台只定时唤醒，通道排水和状态变更仍在窗口前台；新后台任务先声明身份与取消语义。
- **命令目录单点**：终端与侧栏命令统一由 `CommandRegistry` 消费包含封闭 `CommandId`、来源、目标、上下文快照和可选参数的 `CommandRequest`；键盘、鼠标、菜单与 application 调用只构造请求，默认键位与 GPUI action 在同一目录登记，固定身份构造仅保留为恢复与测试接缝。原因：键盘、菜单和后续 Runtime 不得形成不同领域执行路径。边界：项目与模态校验只作用于终端命令，侧栏组织菜单允许自身模态上下文；Shell、视口与比例沿请求传递，未携带对应参数即报错；`Ctrl+C` 不进入终端命令绑定，继续保留中断语义；连续拖动仍按手势处理，不伪造成离散命令。
- **布局操作与分隔线焦点**：移动、合并、既有视图拆分和比例调整统一经 CommandRegistry 在候选 ProjectLayout 上转换；不新建或销毁 Panel、逻辑终端或 PTY。移动与拆分聚焦被移动视图，合并聚焦目标组实际 active；候选验证后先完成送焦再提交，焦点失败不得改变正式快照。Shift+F10 仅在 ProjectLayout 内容上下文打开当前聚焦组菜单，SideView 与活动栏不得触发；菜单先收合还焦再执行命令，单视图组不提供必然失败的移动拆分项，无可用动作时不创建空菜单；终端内容的右键复制／粘贴合同不得被布局菜单覆盖。分隔线以当前分割路径持有运行期 FocusHandle，快照提交时按全部项目布局 reconcile，项目切换同步可见性；关闭候选提交前记录将被删除且实际聚焦的分隔线，并复用关闭还焦链到剩余 active 面板；路径不是持久身份，不产生第二布局事实源。原因：非拖拽入口必须复用同一布局与焦点权威，不能在菜单或渲染层另写转换。边界：真实桌面焦点仍按既有豁免验收。
- **页签与完整列表**：页签严格按当前组 `views()` 的顺序生成，激活索引从同一组 `active` 派生；点击与完整列表共用 `ProjectSnapshot::with_active_view` 候选与既有面板送焦链，不重建 Panel 或 PTY；没有真实运行面板的视图明确失败，不用占位实例伪造激活。页签从面板实体投影共享 Document 脏标记与 AgentHub CLI 状态（形状＋颜色双区分），每个页签带关闭入口；`CloseActivePanel`（`ctrl-w`）复用同一单面板关闭链，关闭当前聚焦视图而不要求终端。横向滚动句柄以 `(ProjectId, PanelGroupId)` 为运行期键并随快照 reconcile，组内顺序或激活项变化时将 active 滚入视野；完整列表由 AppRoot 持有并注册为 FocusManager 模态节点，取消只还焦，选择先收合再激活目标。原因：溢出只改变展示，不得丢失 ViewKey 或让未注册弹层与焦点权威争抢。边界：滚动位置不是布局事实，不进入持久 DTO；标题不是身份；终端自定义标题始终优先，否则使用运行视图的最新 CLI/OSC 标题，无实例或空标题才回退逻辑编号。非终端标题与操作随对应视图阶段接入同一组模型。
- **焦点弱所有权**：`FocusManager` 只弱引用 FocusHandle 与 owner 凭证，以不复用的代次 token、逻辑父链和项目焦点记忆协调还焦；控件销毁或隐藏后不得因渲染帧仍强持句柄而继续可聚焦。实际焦点经 pending-input 与 focus-lost 订阅同步，项目切换先快照真实焦点。边界：Manager 不延长视图生命周期，模态层仍须自行遮罩背景指针命中。
- **面板循环与关闭落点**：`Ctrl+Tab`／`Ctrl+Shift+Tab` 以活跃项目 `ProjectLayout::view_keys()` 的树顺序与组内顺序循环，全局绑定复用真实 PanelHost 与激活链，终端补全和编辑器不得截获或写入 PTY。关闭聚焦面板时由 core 候选的同组 active 提供下一个／上一个落点；组塌缩后按原组索引选择相邻组候选 active，再回退项目容器与工作区。原因：PanelId 字典序不是用户布局顺序，局部控件也不能形成第二套路由。边界：无真实面板的视图明确失败，真实桌面焦点仍按既有豁免验收。
- **侧栏快捷键与焦点所有权**：视图快捷键的打开、恢复、显示、聚焦与关闭只经 core `activate_shortcut` 转换，AppRoot 统一协调焦点注册、可见性和还焦，不在 GPUI 层复制开关规则。SideView 与活动栏按钮均为全局非项目节点；按钮焦点生命周期独立于 SideView 实例，启动只注册不送焦，显式关闭注销节点，隐藏只撤销视图焦点资格。原因：实例代次与按钮持久身份不同，隐藏或销毁后不得残留可聚焦路径。边界：聚焦判定包含视图后代；关闭或隐藏聚焦视图后还焦其可见按钮，无可用按钮时回 workspace。
- **按钮菜单组织单源**：`Shift+F10` 与右键共用 AppRoot 持有的同一菜单入口；菜单注册为 FocusManager 模态节点，收合经既有还焦链返回触发按钮。排序、换区、隐藏与重置顺序只调用 core 组织转换，并复用统一实例效果、焦点可见性与实际变化才落盘协调。原因：菜单是拖拽的键盘等价物，不得形成第二套布局或焦点规则。边界：隐藏按钮保留已打开实例并还焦相邻可见按钮，无按钮时回 workspace；跨槽交换保留双方实例；重置顺序不改变分组、显隐、槽位或几何。
- **SideView 实例与私有状态**：`SideViewHost` 独占侧栏组织状态与全部存活实例，按 core 转换效果创建、替换、保留或关闭实例；`SideView` 独占强类型私有状态，关闭与 Drop 共用一次 checkpoint，写盘只经 WorkspaceWriter。原因：组织状态、GPUI 生命周期与持久事实不得形成双源。边界：隐藏不销毁实例；私有状态在进入 GPUI 前完成预载，无记录才允许默认态回写，读取或解码失败按视图设置写屏障，显式编辑才可解除；普通队列拒收的关闭快照保留为待终态，新一代次成功提交即作废旧待终态，持久化 owner 析构时只补交仍未解决的最新代次。
- **侧栏组织状态恢复**：启动在 GPUI 前从工作区库恢复唯一 `SidebarState` 并移交给 SideViewHost；按钮与显隐等显式组织编辑统一经 WorkspaceWriter 保存。原因：首帧不得先显示默认组织再跳变，启动恢复失败也不得被默认态静默覆盖。边界：无记录或字段级修复不自动回写，只有显式编辑产生写请求；普通队列拒收时保留最新待终态，后续成功入队作废旧副本，持久化 owner 退出时经独立终态通道补交。
- **侧栏几何与手势**：`SidebarState` 只保存用户显式宽度与比例；窗口压缩只夹紧实际绘制和无障碍数值，主区与双槽保留各自最小尺寸，高度不足时侧栏整体纵向滚动，不回写临时几何。键盘与拖动从当前可见值起算，分隔线焦点资格、双击复位、全窗拖动覆盖层及组织变化时的手势取消由 AppRoot 统一协调。原因：临时视口约束不得污染持久偏好，不可见手势层不得截获输入。边界：可见值调整一旦成为显式编辑，仍按 core 几何范围夹紧并保存。
- **分屏空间边界**：拆分动作以窗口尺寸扣除活动栏与实际可见侧栏后的项目内容区校验最小组尺寸，渲染与动作共用同一占宽判定。原因：整窗宽度会让侧栏挤占后的过密分屏错误通过 core 校验。边界：隐藏整个侧栏才释放其宽度，隐藏单个按钮不改变内容区。
- **无旧恢复旁路**：本模块不读取、迁移或清理旧 session 与磁盘历史材料，不与旧 tabs/SplitTree 同步双写。原因：新根必须只有一条布局与生命周期通道。边界：生产恢复只能由启动协调显式注入一致快照，实体层不得自行读盘。
