# AppRoot 运行根

> 以唯一项目快照协调全部项目的运行面板、瞬时焦点与终端生命周期。

## 决策与红线

- **项目与布局单源**：`AppRoot` 直持 `ProjectSnapshot`；`projects` 只是全部 `ProjectView` 的强实体引用表，不复制项目注册、布局或逻辑终端记录。原因：运行实例不得成为第二项目或布局事实源。边界：`ProjectView` 只持 `PanelHost`、项目焦点容器与项目内瞬时焦点，`PanelHost` 只持 `PanelId`、`ViewKey` 与 `TerminalView`。
- **渲染只读单源**：画面只沿活跃项目的 `ProjectLayout` 树、组内 active `ViewKey` 与既有 `PanelHost` 组装；隐藏项目不挂载但继续保活，空项目不创建占位终端。原因：渲染不得派生第二布局或触发终端生命周期。边界：组内非激活视图与隐藏项目均不进入当前画面，激活与切换只复用既有实体。
- **候选原子提交**：新增与拆分先由快照产生候选，再执行一次可失败启动并登记实例，最后提交候选。原因：布局、逻辑终端记录与 PTY 不得出现半提交。边界：启动失败不保留 `session=None` 的占位面板，正式快照与实例表不变；PanelId 失败消耗后也不复用。
- **局部终端关闭**：每个终端由独立 core `CloseCoordinator<String>` 管理 `CloseScope::Panels`、阶段与 attempt；close_id 使用 UUIDv7，`store_epoch` 只取 `AppRootPersistence` 启动恢复时同一工作区库读取的当前元数据，writer 存在而世代无效即拒绝，SHA-256 指纹只绑定关闭身份、作用域、世代、对象身份／代次／决定。生产顺序固定为单终端候选收集 → 快照与关闭意图原子提交 → 后台 `TerminalSession::shutdown` 真实 join → `PtyStopped` → `CleanupCommitted` → `Completed` → Panel 销毁。初始 `CommitState` 在途或结果未知时，显式快照命令与任何新局部关闭都在 `sync_focus`、候选构造和写请求前拒绝，同一终端 Running 拒绝与 Failed 重试仍走原语义；无 Failed 关闭时，`CloseActiveTerminal` 先只读实际 GPUI 焦点以保留同终端 Running 语义，完成允许新关闭的纯预检后同步真实焦点并解析目标，writer 的有效 `store_epoch` 与目标存在性也必须在 `sync_focus` 和候选构造前验证，任何拒绝均不得改变焦点投影、代次、普通写或待写快照。项目快照恢复失败时，局部关闭的组合提交与普通／终态项目写共享恢复屏障，新关闭必须在任何 `sync_focus`、候选和写请求前以独立错误拒绝；显式目录继续打开与既有 Failed 重试不借此屏障改写语义。Exited 等内存更新延期普通写，`AppRoot::drop` 也复用同一 Running／Failed `CommitState` 屏障，禁止补交终态快照。`StateCommitted` 成功后从最新内存快照重算关闭候选，再摘除渲染、还焦、注销焦点与订阅，Panel 实体保留到 Completed。明确初始提交失败清除本次关闭并恢复延期写，后续明确推进失败保留 Panel 并从当前持久阶段显式重试；回执断连或重复任务导致结果未知时 fail-closed，禁止盲目重登记。join Err 不推进持久状态，只有用户显式重试才可消费已观察到的异常终止事实，不得二次 join、重开 PTY 或记录 panic payload；commit／advance 回执须先核对 close 存在、attempt、目标 next 与当前持久前序，并完整比对 close_id、scope、store_epoch、对象与指纹，全部通过后才可收割任务或改态，close 缺失、stale、错身份、错 next、错前序一律忽略且不触碰任务。还焦失败不得裸送 workspace 焦点绕过模态，只能 blur 原聚焦终端并经 FocusManager 同步实际焦点。局部关闭不停止全局服务、不写 `clean_shutdown`，任一局部关闭存活时 `request_close` 返回 false，全局 `close_in_progress` 拒绝新局部关闭；无 writer 仅允许既有内存测试根走无持久化同序降级。
- **局部关闭用户重试**：`CloseActiveTerminal` 对曾失败且未 Completed 的局部关闭按单调发起序号选择最早项；已知 Failed 经原目标显式重试，未知结果仍明确拒绝，初次 Running 不进入失败重试，重试后的 Running 仍返回 Running 并阻断后续目标。全部曾失败关闭 Completed 前不得解析或关闭新的焦点终端，CommandRegistry 不得因当前无 focused terminal 或无活跃项目提前阻断这条重试；全部解决后才恢复正常 focused close。原因：StateCommitted 后真实焦点可能已还到其他终端或项目容器，焦点目标不能再代表失败关闭身份。边界：重试只推进原持久阶段，不复活已摘除的渲染，不提前销毁 Panel；多个失败按发起顺序逐一处理，不按 TerminalId 或同毫秒 UUID 的隐含顺序选择。
- **组内批量关闭**：完整页签列表的关闭其他／全部只构造统一命令；关闭其他保留组内 active，关闭全部移除组内全部真实终端。全部目标在同一 `ProjectSnapshot` 候选、同一 `CloseCoordinator` 与完整 `CloseIntent` 中提交，原子提交成功前不得停止任何 PTY 或摘除面板；StateCommitted 后统一还焦并复用局部关闭的持久推进，按成员保存停止观察事实，后续失败只能显式重试原批次且不得二次 join。批量与单终端共享单调发起序号和较早失败优先闸门，关窗与项目移除必须等待存活批次。原因：逐条关闭会形成半批快照与不可恢复的失败顺序。边界：空组由 core 布局转换塌缩；没有真实 PanelHost 的视图明确失败，Document 内容决定与共享引用守卫在 Document 阶段扩展同一协调器，不构造占位面板。
- **项目移除关闭**：`RemoveProject` 以稳定 ProjectId 为封闭命令目标，同一入口负责发起与明确失败重试；每个项目由独立 core `CloseCoordinator<String>` 管理 `CloseScope::Project`，同时最多一个项目关闭，目标存在局部终端关闭或全局关闭在途时拒绝。初始原子提交保存其他项目与新活跃项、登记删除意图，但保留目标项目、布局与终端到后续清理；StateCommitted 后从最新内存快照移除项目、摘除渲染与焦点注册，移除活跃项时按既有恢复语义补齐下一项目隐藏 Launch，全部普通项目写延期到 Completed，Drop 同样受屏障。所属全部 session 在后台逐一显式 join，任一 panic 只记录观察事实并由同一命令显式重试后消费，不二次 join；PTY 停止后的专用事务原子删除项目、纯数据库布局／终端、项目 ViewState 与 Nav／Explorer 分区，内存 SideView 同步清理，Completed 才释放 ProjectView 并恢复延期写。回执先校验完整身份、attempt、阶段与持久前序再收割 `TaskId::ProjectClose`；断连或重复登记导致结果未知时 fail-closed，禁止盲目重试。项目关闭存活阻止关窗，不停止全局服务、不写 `clean_shutdown`。
- **项目快照持久提交**：项目、布局、激活关系与 RunIntent 的候选提交统一经 `commit_project_snapshot` 进入 WorkspaceWriter 的既有去抖队列，不在各命令另建 Terminal 写通道。普通队列拒收时保留最新待终态，后续成功入队作废旧副本，AppRoot 析构只在 `CommitState` 屏障解除后补交仍未解决的快照。原因：运行快照与持久事实必须同源，且前台不得等待 SQLite。边界：只有已提交候选才入队；恢复失败期间普通与终态项目写均受屏障保护，只有成功重载对账或用户显式破坏性重置才能解除；显式启动失败保持原快照与原实例，终态移交不阻塞 GPUI 前台。
- **生产快照恢复**：`AppRootPersistence` 在首帧前经工作区库恢复唯一 `ProjectSnapshot` 与侧栏状态，AppRoot 据此创建全部项目实体并初始化 FocusManager 的活跃项目作用域，启动不送焦、不回写解析结果。常规启动有恢复项目时不额外打开 cwd，空工作区才走初始项目链，显式目录仍走既有打开链。原因：首帧不得闪现默认布局，恢复也不得复制持久事实或制造新项目。边界：常规启动恢复失败不得按空工作区打开 cwd；显式目录可继续打开，但项目写屏障不得解除；后续损坏诊断与只读维护界面由 Startup 协调承接。
- **终端恢复运行态**：恢复按 `ProjectLayout::view_keys()` 顺序创建活跃项目实例；可见 Launch 只启动一次，隐藏项目先保留记录并在首次激活时懒启动，Exited 只恢复退出状态而不创建 PTY，启动或元数据失败保留错误面板且不重复记录。默认焦点从布局首个目标组的 active 面板解析，激活与重复打开必须在懒启动和焦点可见性同步前完成默认焦点解析及模态、token、项目作用域纯预检，失败不得产生 PTY；恢复后无失败重算实际 default 并经同一纯预检，无法采用时回退已预检 token，激活自身错误不得吞没。原因：持久运行意图决定恢复副作用，显式新建的原子失败与送焦语义不能直接复用，恢复前原子预检也不能把首次激活焦点固定在项目容器。边界：终端输出、回滚与未知退出码不伪造恢复；已有实例再次激活不重建并保留运行期焦点记忆，隐藏项目的存活实例继续保活，恢复错误面板不新增激活失败语义。
- **单实例项目与终端移交**：`HandoverParams::OpenProject` 先经 `CanonicalPath::new` 纯校验，再经 FIFO `ProjectPathResolver` 后台解析并复用候选 `add_project`；只有实际完成后才前置窗口并回执 accepted，解析或提交失败不改变原项目关系；新增根只打开空项目，重复根激活既有项目，均不得隐式创建 Terminal/Panel；OpenProject 仅非法路径映射 InvalidRequest、模态映射 Unauthorized、其他失败映射 NotReady，失败保持快照、实体、Panel/PTY 与焦点事实不变。`HandoverParams::NewTerminal` 同样先纯校验路径并复用 `CommandRegistry`：显式根只精确匹配既有项目，仅有 cwd 时选择根覆盖 cwd 的最深项目，两者同时提供时 cwd 必须位于显式根内，两者皆无才使用活跃项目；未知根、无覆盖 cwd、跨根 cwd 与模态均为 Unauthorized，非法路径为 InvalidRequest，其他未就绪失败为 NotReady，错误脱敏且不得改投或隐式创建项目。所有 NewTerminal 请求先同步真实焦点，再解析目标与克隆候选。隐藏目标的候选快照同时包含项目激活与新终端，目标组先复用焦点记忆，无可用面板焦点时按布局顺序选择既有组，空项目生成首组；launcher、实例登记、FocusManager 项目激活与新终端聚焦全部成功后才提交，失败须清理 launch、恢复原 active 与实际焦点，成功后按既有恢复语义补齐其余隐藏实例。原因：第二实例必须共享项目、授权、目录和焦点语义，前台不得执行路径文件系统 I/O，隐藏恢复不得破坏原子提交。边界：仅成功后才前置窗口并返回 accepted，Closing 优先；OpenFile 保持 InvalidRequest。
- **生产身份与落点**：打开项目、新建与拆分命令由 application 以 UUIDv7 生成稳定身份；固定身份入口只供恢复协调与测试。普通新建进入活跃项目当前聚焦组，空项目生成首组；handover 新终端按移交规则选择目标项目与组；拆分必须已有聚焦组，关闭聚焦终端复用同一显式关闭链。原因：调用方不得自行拼身份或另判布局落点。边界：无活跃项目或应有聚焦组而缺失时明确失败，不隐式选择隐藏项目。
- **项目元数据与真实路径打开**：重命名与排序经 `CommandTarget::Project` 和统一候选提交，只改名称或导航顺序，不改变活跃项目、布局、Panel 或 PTY；空白、超长与越界输入保持原快照。OpenProject／OpenDirectories／初始打开共用 FIFO 解析队列，系统 canonicalize 与目录校验只在 background executor，任务归 TaskService，完成回前台后仍经同一 `add_project` 候选链；后一请求不得先于前一请求提交，失败不得新增项目、改投活跃项或伪造 handover 成功；completion 统一结算且只允许一个活动任务，关闭入口立即取消并排空队列，handover guard 在窗口或实体销毁时兜底 Closing。原因：项目关系与焦点必须确定，且真实路径 I/O 不得阻塞前台。边界：固定身份与假解析器只用于内存测试；生产不得绕过真实路径端口直接打开外部根。
- **可失败启动接缝**：终端先经 `TerminalView::launch` 冻结配置并启动 PTY，成功后才经 `from_launched` 构造实体。原因：GPUI 实体构造不能直接返回启动 `Result`，失败不得先挂实体再补救。边界：成功启动只执行一次；非 Unicode Shell 路径在参数组装前拒绝，不做有损转换。
- **项目切换保活**：已恢复的 TerminalView 与存活 PTY 强持于各自 ProjectView；切换只调整 `output_visible` 与焦点，隐藏项目的既有会话泵、输出解析和回滚继续运行，重新可见时主动补帧。原因：项目导航不得重建终端或丢失后台输出。边界：普通显式新建只面向活跃项目；handover 仅按单实例移交规则选择既有项目，隐藏项目 Launch 的其余懒启动由恢复协调负责，不在普通显式命令中暗中 spawn。
- **退出与关闭分离**：TerminalView 的 Exited 只把逻辑记录改为 `RunIntent::Exited`，保留面板、实体与最后画面；显式 close 才释放实例。原因：进程退出不是用户关闭面板。边界：重复或迟到的退出事件不得关闭其他面板；未知运行身份不猜快照目标。
- **应用退出局部关闭**：OS 关窗与 `TrayQuit` 统一经 `request_close` 创建 `CloseScope::ApplicationExit`，收集全部逻辑终端，先移交 SideView 终态，再原子提交 ProjectSnapshot 与关闭意图；全部 session 在后台逐一显式 join，随后依次提交 `PtyStopped`、`CleanupCommitted`、`Completed`，只有 Completed 才进入 `StopServices` 并复用最终 flush。初始明确提交失败清除本次关闭并恢复编辑；停止后的明确写失败保留窗口，从原持久前序显式重试；join panic 只有显式重试才消费观察事实，不二次 join。断连或重复任务登记导致结果未知时 fail-closed，禁止盲目重登记；回执须先核对完整身份、attempt、next 与持久前序，再收割 `TaskId::CloseFlush`。`application_close` 存活即冻结命令与 handover，即使失败已清除 `close_in_progress` 也不得解冻。原因：窗口销毁不得掩盖持久提交、PTY 回收或回执身份错误。边界：局部段不写 `clean_shutdown`；生产最终 flush 成功后经全局 client 请求 GPUI 外所有者，只有收到服务停止与正常退出提交完成或知情放弃回执，才推进 core 全局阶段并销毁窗口；恢复失败只冲刷既有写屏障且不登记关闭意图，但同样经 `recovery_global_close` 等待全局回执，不得绕过全局段直接销毁窗口；其回执以独立 close_id 与单调 attempt 隔离重试，Disconnected 同样 fail-closed；无 writer 仅允许内存测试根直接关窗降级，包括恢复失败组合。
- **关闭冲刷与冻结**：正常 ApplicationExit 的局部段 Completed 后，以及恢复失败屏障路径，均由 `submit_final_states` 移交项目、侧栏组织与 SideView 私有终态，再由 `WorkspaceWriterClient` 在后台执行可重试 flush；flush 失败保留窗口并允许重试，已停止的 PTY 不得因此重开。每次快照提交推进代次，Flush 返回时若代次已变化则重新移交并再次 Flush，只有最新代次零失败才进入后续退出。生产全局 client 存在时，flush 成功只发起全局段，Completed 或 Abandoned 回执才允许移除窗口；`AppRootServices` 以非可选全局 client 保证生产开窗注入；无全局 client 的虚拟窗口测试根沿用 flush 后直接关窗。`close_in_progress` 拒绝新命令、项目切换、鼠标激活与几何拖动，关闭时取消既有手势；`close_completed` 终止当前壳事件批的领域处理，同批剩余 Handover 仍逐一非阻塞回复 Closing、其他事件丢弃，关窗回调只弱持 AppRoot。原因：最终持久提交失败或过期不得被窗口销毁掩盖，也不得形成第二退出通道。边界：GPUI 前台不等待数据库、控制面或 writer shutdown；正常退出标记由 GPUI 外的全局关闭所有者提交。
- **任务所有权**：`TaskService` 集中登记封闭 `TaskId`、GPUI `Task` 与显式取消令牌，禁止 `detach`；局部关闭按 `TaskId::TerminalClose` 分终端持有，组内批量按 `TaskId::TerminalCloseBatch` 持有一个任务，重复身份拒绝且不得构造或丢弃替代资源；已发请求的重复登记只把本次结果标为未知并保持写屏障，原任务身份必须保留，未知结果处理不得顺带收割原任务；Running `StopPty` 的重复调度则保持幂等，不构造替代任务、不转 Failed、不标未知，保留原 attempt 与任务并等待原回执收割推进。shutdown 先标记全部取消再释放句柄，AppRoot 析构复用同一路径。原因：周期与关闭任务必须有确定所有者与取消边界，不能留下游离循环或让 stale 回执取消新 attempt。边界：壳事件泵只经该服务注册，后台只定时唤醒，通道排水和状态变更仍在窗口前台；新后台任务先声明身份与取消语义。
- **命令目录单点**：终端与侧栏命令统一由 `CommandRegistry` 消费包含封闭 `CommandId`、来源、目标、上下文快照和可选参数的 `CommandRequest`；键盘、鼠标、菜单与 application 调用只构造请求，默认键位与 GPUI action 在同一目录登记，固定身份构造仅保留为恢复与测试接缝。原因：键盘、菜单和后续 Runtime 不得形成不同领域执行路径。边界：项目与模态校验只作用于终端命令，侧栏组织菜单允许自身模态上下文；Shell、视口与比例沿请求传递，未携带对应参数即报错；`Ctrl+C` 不进入终端命令绑定，继续保留中断语义；连续拖动仍按手势处理，不伪造成离散命令。
- **布局操作与分隔线焦点**：移动、合并、既有视图拆分和比例调整统一经 CommandRegistry 在候选 ProjectLayout 上转换；不新建或销毁 Panel、逻辑终端或 PTY。移动与拆分聚焦被移动视图，合并聚焦目标组实际 active；候选验证后先完成送焦再提交，焦点失败不得改变正式快照。Shift+F10 仅在 ProjectLayout 内容上下文打开当前聚焦组菜单，SideView 与活动栏不得触发；菜单先收合还焦再执行命令，单视图组不提供必然失败的移动拆分项，无可用动作时不创建空菜单；终端内容的右键复制／粘贴合同不得被布局菜单覆盖。分隔线以当前分割路径持有运行期 FocusHandle，快照提交时按全部项目布局 reconcile，项目切换同步可见性；关闭候选提交前记录将被删除且实际聚焦的分隔线，并复用关闭还焦链到剩余 active 面板；路径不是持久身份，不产生第二布局事实源。原因：非拖拽入口必须复用同一布局与焦点权威，不能在菜单或渲染层另写转换。边界：真实桌面焦点仍按既有豁免验收。
- **页签与完整列表**：页签严格按当前组 `views()` 的顺序生成，激活索引从同一组 `active` 派生；点击与完整列表共用 `ProjectSnapshot::with_active_view` 候选与既有面板送焦链，不重建 Panel 或 PTY；没有真实运行面板的视图明确失败，不用占位实例伪造激活。横向滚动句柄以 `(ProjectId, PanelGroupId)` 为运行期键并随快照 reconcile，组内顺序或激活项变化时将 active 滚入视野；完整列表由 AppRoot 持有并注册为 FocusManager 模态节点，取消只还焦，选择先收合再激活目标。原因：溢出只改变展示，不得丢失 ViewKey 或让未注册弹层与焦点权威争抢。边界：滚动位置不是布局事实，不进入持久 DTO；标题不是身份，非终端标题与操作随对应视图阶段接入同一组模型。
- **焦点弱所有权**：`FocusManager` 只弱引用 FocusHandle 与 owner 凭证，以不复用的代次 token、逻辑父链和项目焦点记忆协调还焦；控件销毁或隐藏后不得因渲染帧仍强持句柄而继续可聚焦。实际焦点经 pending-input 与 focus-lost 订阅同步，项目切换先快照真实焦点。边界：Manager 不延长视图生命周期，模态层仍须自行遮罩背景指针命中。
- **侧栏快捷键与焦点所有权**：视图快捷键的打开、恢复、显示、聚焦与关闭只经 core `activate_shortcut` 转换，AppRoot 统一协调焦点注册、可见性和还焦，不在 GPUI 层复制开关规则。SideView 与活动栏按钮均为全局非项目节点；按钮焦点生命周期独立于 SideView 实例，启动只注册不送焦，显式关闭注销节点，隐藏只撤销视图焦点资格。原因：实例代次与按钮持久身份不同，隐藏或销毁后不得残留可聚焦路径。边界：聚焦判定包含视图后代；关闭或隐藏聚焦视图后还焦其可见按钮，无可用按钮时回 workspace。
- **按钮菜单组织单源**：`Shift+F10` 与右键共用 AppRoot 持有的同一菜单入口；菜单注册为 FocusManager 模态节点，收合经既有还焦链返回触发按钮。排序、换区、隐藏与重置顺序只调用 core 组织转换，并复用统一实例效果、焦点可见性与实际变化才落盘协调。原因：菜单是拖拽的键盘等价物，不得形成第二套布局或焦点规则。边界：隐藏按钮保留已打开实例并还焦相邻可见按钮，无按钮时回 workspace；跨槽交换保留双方实例；重置顺序不改变分组、显隐、槽位或几何。
- **SideView 实例与私有状态**：`SideViewHost` 独占侧栏组织状态与全部存活实例，按 core 转换效果创建、替换、保留或关闭实例；`SideView` 独占强类型私有状态，关闭与 Drop 共用一次 checkpoint，写盘只经 WorkspaceWriter。原因：组织状态、GPUI 生命周期与持久事实不得形成双源。边界：隐藏不销毁实例；私有状态在进入 GPUI 前完成预载，无记录才允许默认态回写，读取或解码失败按视图设置写屏障，显式编辑才可解除；普通队列拒收的关闭快照保留为待终态，新一代次成功提交即作废旧待终态，持久化 owner 析构时只补交仍未解决的最新代次。
- **侧栏组织状态恢复**：启动在 GPUI 前从工作区库恢复唯一 `SidebarState` 并移交给 SideViewHost；按钮与显隐等显式组织编辑统一经 WorkspaceWriter 保存。原因：首帧不得先显示默认组织再跳变，启动恢复失败也不得被默认态静默覆盖。边界：无记录或字段级修复不自动回写，只有显式编辑产生写请求；普通队列拒收时保留最新待终态，后续成功入队作废旧副本，持久化 owner 退出时经独立终态通道补交。
- **侧栏几何与手势**：`SidebarState` 只保存用户显式宽度与比例；窗口压缩只夹紧实际绘制和无障碍数值，主区与双槽保留各自最小尺寸，高度不足时侧栏整体纵向滚动，不回写临时几何。键盘与拖动从当前可见值起算，分隔线焦点资格、双击复位、全窗拖动覆盖层及组织变化时的手势取消由 AppRoot 统一协调。原因：临时视口约束不得污染持久偏好，不可见手势层不得截获输入。边界：可见值调整一旦成为显式编辑，仍按 core 几何范围夹紧并保存。
- **分屏空间边界**：拆分动作以窗口尺寸扣除活动栏与实际可见侧栏后的项目内容区校验最小组尺寸，渲染与动作共用同一占宽判定。原因：整窗宽度会让侧栏挤占后的过密分屏错误通过 core 校验。边界：隐藏整个侧栏才释放其宽度，隐藏单个按钮不改变内容区。
- **无旧恢复旁路**：本模块不读取、迁移或清理旧 session 与磁盘历史材料，不与旧 tabs/SplitTree 同步双写。原因：新根必须只有一条布局与生命周期通道。边界：生产恢复只能由启动协调显式注入一致快照，实体层不得自行读盘。
