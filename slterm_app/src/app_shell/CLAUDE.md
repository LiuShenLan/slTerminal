# 应用壳组合层

> GPUI 壳的组合根：以 AppRoot 装配项目、运行面板、窗口与外观。

## 决策与红线

- **壳即前端**：壳内状态权威 = `AppRoot` 直持 `ProjectSnapshot` 与全部项目运行实体，无投影层。原因：单进程直持状态，避免跨层同步。边界：窗口装配只能选择一个运行根，不得保留旧 tabs/SplitTree 或第二套项目状态。
- **项目运行根边界**：`app_root` 以 `ProjectSnapshot` 为唯一项目、布局与逻辑终端事实源，强持全部项目运行实例。原因：项目切换必须保留隐藏项目终端，且不得形成新旧双树。边界：模块决策与验收见其目录文档；不得读取旧 session 或自建持久化通道。
- **Document 批量关闭保存**：统一关闭主干的 Save 阶段逐项执行真实条件保存并聚合全部失败；任一失败必须使 `CloseCoordinator` 失败于 Save，不得进入快照提交、Panel 销毁或 PTY 停止。已成功保存项保持新磁盘事实且不回滚，失败项保留正文与脏态。原因：批量部分失败不能丢正文，也不能把已落盘结果伪装成可整体回滚。边界：执行体只负责 Document 保存与状态回执；真实 Panel／PTY 保留必须由 AppRoot 阶段接线验证，纯状态或执行体测试不替代该证据。
- **Paged 真实读取**：`PagedDocument` 只在后台顺序扫描源文件并保存连续页范围，不保留全文；每页严格复用 core 编码解码，页边界按完整字符与行尾提前收束；边界若落在 CR 后则把 CR 留给下一页，CRLF 不得跨页。逐页读取复核真实文件身份与源长度，外部增长或替换不得沿用旧索引；外部刷新以全文件指纹区分相同页范围下的内容变化，干净超限切 Paged，脏 Document 不丢 Rope 与保存出口。`chunks_for` 只接受请求捕获的同一页索引与指纹，后台查找与完整复制复用该分页端口。原因：大文件不得物化全文或把半个字符送入解码。边界：生产消费归 AppRoot Paged 打开与只读视图；该服务不得在前台调用。
- **诊断宏拦截**：`println!`/`eprintln!` 在本模块文本域内编译期报错；诊断统一走 `try_write_stderr`。原因：无效标准句柄上裸打印会 panic。
- **壳事件通道**：壳事件使用容量 64 的有界 `sync_channel`，生产发送统一为非阻塞 `try_send`，队列满只记录脱敏诊断。启动链持有命名管道服务并把 hook 事件按有界批次投递为 `AiHookEvents`，窗口结束后先停管道再 join 泵线程。原因：托盘、通知、URL 与 writer 回调不得因事件洪峰无界增长或阻塞前台。边界：不在回调中阻塞等待队列；事件载荷不进入诊断文本。handover 经 application 单点 helper 投递，完成回执使用容量 1 的 `sync_channel`，投递与 AppRoot 回执均用 `try_send`；投递 Full/Disconnected 分别映射 QueueFull/Closing，回执接收端断开只放弃答复，不阻塞或 panic。
- **文件树 watcher 调度**：`WatcherService` 按 `FileTreeRoot` 登记路径与可见性，事件按 200 毫秒合并，连续事件最长 1,000 毫秒内复核；隐藏期间忽略纯界面事件，重新可见只复核一次，根替换与注销立即丢弃旧待审。原因：不可见 UI 不得维持私有监听或累积重复刷新。AppRoot 按已打开的 Explorer／Commit／AgentFiles 实例登记根，侧栏不可见时保留登记但把根移出 OS watch，重新可见只复核整根一次；目录脏路径在复核就绪时结算，Explorer 重读受影响目录及父目录，Commit 重取状态，Agent 根重新同步。边界：实际 OS watch 仍归既有 `FsWatch`，时间结算复用壳事件泵，不新增轮询；Document watcher 不因 UI 隐藏暂停。
- **文件操作计划**：Explorer 与 Agent 文件树共用 `FileOperationService`；新建、复制、重命名和删除先生成不可变 `OperationPlan`，执行前重新解析词法目标与真实位置并重新判定授权。复制分别校验源 Read 与目标 Write，其余写操作校验 Write；计划比较文件身份、目标父目录身份和预期指纹，不携带可沿用授权；计划与执行的真实授权代次来自进程级单源，项目移除／重定位与 Agent 根撤销或改路径必须推进代次，使旧计划与在途保存失败。目录身份经真实 Windows 句柄取得；重命名与复制提交不得携带目标替换标志，目录复制拒绝 reparse point。原因：树加载后的链接重定向、目标或父目录替换、失权不得转化为写盘副作用，预检后的同名目标也不得被覆盖。边界：服务含阻塞 I/O，只在后台调用；系统 CRUD、流式复制与回收站仍归 `platform::file_operations`，目标真正不存在可按完成处理，悬空链接等既有对象不得误报缺失，其他变化一律中止且不修改磁盘。
- **粘贴冲突与部分成功**：`PasteService` 在零写入预检中聚合冲突并捕获各既有目标的不可变删除计划；执行逐项串行重建复制／移动计划，Replace 先复核源再回收已披露目标，Skip 保留冲突，Cancel 零修改。执行中新增冲突不继承 Replace，成功项不因后续失败回滚。每个实际项在副作用前经 `PasteJournal` 登记并进入 Applying， outcome 指纹落账后才可提交；登记失败零修改，提交失败报告 `NeedsAttention`。启动时 `PasteJournalRecoverer` 先对账登记哈希、步骤源指纹与授权代次；移动无论是否已有 outcome 都须证明源缺失、目标无 reparse、规范位置与身份不变，目录 outcome 覆盖完整后代，未知复制／替换保持 `NeedsAttention`，不自动重放。原因：一次确认不得扩张到替换后的新对象，源失效不得先销毁目标，崩溃也不得重发未知副作用。边界：服务含阻塞 I/O 与串行等待，只在后台调用；生产 Journal 只经 WorkspaceWriter 单写线程，报告逐项保留成功、跳过、拒绝、失败与待人工复核。
- **视觉语言**：仅暗色；Linear 为默认；暖黑明度阶梯、发丝线分隔、单强调色、等宽字体、无动效。原因：产品定位与「界面消失」的阅读优先。边界：色值以主题表为真值，不在壳内硬编码；状态用圆点而非 emoji。
- **布局单点**：运行与持久布局都以 `ProjectLayout` 为权威，只经其规范 DTO 转换。边界：禁止旧 session layout 或第二套序列化回流。
- **默认 Shell 设置**：启动链在 GPUI 前读取一次设置，`shell` 覆盖参与真实探测与白名单校验；设置值失效时回退默认探测链并告警，不阻断启动。运行期设置变更由 AppRoot 在后台重新解析，成功才替换默认 Shell，新建终端使用新值，既有终端保持原进程。原因：默认 Shell 是进程创建事实，解析含真实进程探测，不能在前台或每次按键重复执行。边界：终端恢复仍使用持久化的记录 Shell，不重新解释当前默认值。
- **静默启动**：首窗 `show=false`/`focus=false` 创建；本层任何路径不得 show/activate/聚焦窗口。只有端口报告托盘窗口与图标真实就绪时才允许隐藏；静默分支有界等待，超时回退可见窗口。原因：启动不得抢焦点或闪现，也不能让窗口在没有托盘入口时隐藏。
- **运行与退出事实**：`WorkspaceWriterRuntime` 在启动时登记并保留本次完整 `WorkspaceMetadata`（含 `run_id` 与 Unix epoch 毫秒创建时间），保留既有 `store_epoch` 并向启动恢复传递上一运行退出事实；`AppRootPersistence` 在既有启动恢复连接读取当前 `store_epoch` 并移交 AppRoot 供局部、项目与应用退出关闭，不另开读取通道。正常 ApplicationExit 完成局部段与最终 flush 后，由 GPUI 外 `GlobalCloseRuntime` 工作线程独占停止控制面、回收 writer 与失败转发器并提交 `clean_shutdown`，窗口收到 Completed 或 Abandoned 回执后才可销毁；控制面明确失败保留 writer 供显式重试，writer、转发器或回执结果未知时 fail-closed，任一失败均不写正常退出。原因：启动恢复、各作用域关闭、控制面与 Runtime 世代必须共享同一真实运行身份，最终状态不得先于其他持久提交或窗口销毁。边界：运行标记与最终冲刷共用同一工作区库，请求与每次回执均使用有界通道，GPUI 前台不等待控制面或 writer；最终提交失败由 GPUI 外工作线程以当前主窗 HWND 为 owner 弹出原生确认；只有用户选择取消才映射知情放弃，MessageBoxW 失败或其他返回值均上抛且不得产生 Abandoned 回执；放弃保持 `clean_shutdown=false` 并明确旧布局与残留快照可能恢复；异常窗口断连由工作线程兜底回收，仍先尝试 writer 最终冲刷与转发器 join，控制面失败不得伪造正常退出。
- **学习运行所有权**：工作区维护通过后才在 GPUI 外启动 `LearningService` 与独立写线程；服务克隆经 `AppRootServices` 注入，runtime 留在 `run_shell_once` 外层作用域，窗口结束并完成全局关闭后显式排空、join。损坏或高版本只降级为内存学习并保留原库，不阻断工作区。原因：学习 I/O 不得进入前台，也不能留下无 owner 的全局写线程。边界：学习写失败不污染工作区 `clean_shutdown`；启动中途失败由 runtime Drop 复用同一关闭路径。
- **启动维护硬闸门**：主实例组合序固定为 OS 单实例锁 → 工作区库恢复打开（有效副本恢复或双损隔离）／`begin_run`／按领域注册表维护 → writer 与失败转发器 → 领域恢复（布局归一先于快照端口）→ `LocalControlService` → `GlobalCloseRuntime` → GPUI 窗口。恢复打开产生封闭壳事件，由 AppRoot 以 typed i18n 明确提示，不携带路径或正文；布局、侧栏与 ViewState 的跳过／修复同样聚合计数并经同一 typed 提示在首帧报告，不得只写日志。维护未通过时不得创建 writer、转发线程与普通后台任务；维护或 writer 启动失败只记录脱敏诊断并进入独立诊断分支，布局或快照领域恢复失败则先回收 writer 与转发线程再进入同一诊断分支，已登记的本次运行保持 `clean_shutdown=false`，不得加载领域运行状态、启动控制面或创建正常工作区窗口；全局关闭所有者启动失败同样立即返回且不得创建窗口，已启动控制面、writer 与失败转发器必须显式 shutdown／join 后回收。原因：恢复事实未安全时继续启动会放大写入与运行副作用。边界：维护或 writer 失败只开放只读诊断与重试窗口，不得加载领域运行状态或启动控制面、PTY 与普通后台任务；维护阻断提供二次确认的显式放弃（先整库归档再按阶段删除未完成事实），成功后才关闭诊断窗并重走同一启动链；诊断初始化只使用默认设置与暗色 token，禁止设置恢复写盘和壁纸加载；重试仅关闭诊断窗，外层在持续持有 OS 单实例锁的情况下从同一启动链重新执行，禁止以无 client 正常工作区替代。
- **控制面组合序**：仅 writer 可用时在 `AppRootPersistence` 恢复完成后绑定 `LocalControlService`，复用 writer 本次元数据与同一壳事件发送端；绑定失败记录脱敏错误并沿用降级 UI，不得伪造元数据或留下可用假端点。随后把未开放服务与 writer 一并移交 `GlobalCloseRuntime`；常规窗口在首帧呈现并激活后、静默窗口在事件泵装配后，只经有界开放请求让工作线程发布发现记录，前台不执行文件 I/O 或等待回执。全部窗口与运行时 client 通过专用有界生命周期通道持有开放权；断连必须取消尚未处理的开放，在途开放结束后立即撤销，窗口销毁或生产原生句柄获取失败不得触发开放。开放失败只记录脱敏错误并保留统一关闭链；正常路径在窗口销毁前显式停止服务并执行 writer 退出链，未启动服务视为清理成功；`application.run` 返回后只 join 已完成或断连兜底的工作线程，不再另开第二条关闭链。原因：发现记录只能指向首帧后完整真实运行，监听与发现撤销必须先于正常退出标记和窗口销毁。边界：OS 单实例锁仍由 `run()` 持有；本层不接第二实例 handover 入口。

## 验收与测试

- 虚拟窗口：`cargo test -p slterm --test lib_tests --features gpui-test-support -- --test-threads=1`。
- 必测面：AppRoot 挂载与绘制、项目与布局单源、启动事件排水、关闭意图各提交阶段的真实子进程崩溃重开对账、事件通道容量与 AppRoot 销毁后接收端释放、激活与关闭生命周期、运行标记与最终冲刷成功/失败后的正常退出事实、全局控制面失败重试与窗口断连兜底回收、正常退出提交先于窗口销毁、静默启动不 show/activate、诊断宏拦截。
- 真实 GPU/桌面会话行为由构建产物人工验收，边界见 `.claude/docs/testing/exemptions.md`。

## 操作

- 新增视图：先扩封闭 `ViewKey` 与单一注册点，再由 AppRoot 所有权链接线。
- 新增启动副作用：接入 `lib.rs::run()` 的同一启动链，不在子模块私开入口。
- 调整视觉语言：改主题表与语义 token，不在壳内写颜色字面量。
