# AI agent 识别与屏幕规则

> 从终端屏幕判定 agent 身份与状态；屏幕规则随仓，识别结果供状态投影与通知使用。

## 决策与红线

- **屏幕规则是唯一判定源**：内置与用户规则共用同一结构边界；assistant 正文里的字不足以证明存在一个活的输入表单。原因：正文与表单在纯文本屏幕上形态相近，必须用结构规则区分。
- **注意力区域**：默认取最后一个空提示符之后的屏幕；Codex 的无框 composer 可能是草稿或轮换占位文案，带编号的选择行与 composer 使用同一字形，因此 composer 之后的行才是当前注意力区域。
- **活输入控件判定**：只看最新的控制行，旧的被引用表单压不过当前的中断 footer 或新 composer；二选一提示（y/n）与按键控制行才构成输入请求；含 `interrupt`/`to stop` 的行不算。原因：不能把正在干活的回合误判为等待输入。
- **`AgentKind` 封闭集**：内置 agent 身份是封闭枚举；新增 agent = 枚举 + 屏幕规则 + 必要的安装器/目录表登记。原因：识别与安装、状态投影必须同一身份集。
- **宽松落盘、严格消费**：未知来源的会话字符串可落盘，但恢复注入必须经 `AgentKind::parse` 归一；不归一即不可恢复。原因：面向所有 AI CLI，但不让未知来源触发恢复动作。
- **规则随仓**：屏幕规则以 TOML 随仓维护；修改规则须补对应屏幕样例用例。原因：规则是行为合同，不能只靠线上观察。

## 验收与测试

- 定向测试：`cargo test -p slterm --test lib_tests <filter> -- --test-threads=1`；禁止 `--lib` 或裸 filter 直打默认 lib target。
- 必测面：注意力区域截取、Codex composer 边界、二选一提示、按键控制行、中断 footer 排除、最新控制行胜出、未知 source 的归一/拒绝。
- 规则用例位于本模块内嵌测试；新增屏幕样例必须覆盖正例与反例。

## 操作

- 新增 agent：扩 `AgentKind`、添加屏幕规则与样例用例，再接入安装器/目录表。
- 调整规则：只改规则与样例，不在调用点写特判。
