# 生命周期与维护期

> 规定单实例启动、异常对账、正常关闭、恢复和更新移交的统一顺序，禁止以内存状态替代持久提交结果。

## 决策与红线

### 启动与单实例

启动按以下命名边界推进：

```text
入口与锁 → 维护期 → 领域恢复 → 可见性激活 → 服务开放
```

- 入口只读取一次 `SLTERM_CONFIG_DIR`、`SLTERM_LOCAL_DIR` 和命令行，构造不可变 AppPaths。两个环境变量只接受绝对路径，非法即明确失败；不读取 `SLTERM_RUNTIME_ENDPOINT`，也不接受 token 环境注入。
- 在创建 UI、PTY、watcher、历史展示和普通后台任务前取得 OS 单实例锁，并写入本次 run_id、PID 与进程创建时间的运行标记。锁已存在时只尝试 LocalControlServer 移交；连接、认证或移交失败都报错退出，绝不创建第二窗口。
- LocalControlServer 与 OS 锁分离：锁证明实例所有权，服务器负责 `runtime` 与 `handover` 两个作用域。维护期完成前不开放写请求；未可服务时写请求进入有界队列，读请求返回 `not_ready`，队列满或关闭开始即拒绝。
- 启动不按解析结果反写布局。先恢复项目与布局，再按 DocumentId 对账快照和授权占位，随后加载获准正文，最后按可见性与确定性顺序启动允许的 PTY。

### 维护期

维护期严格依次处理：

```text
库版本与完整性分流
→ ManagedOperationJournal 对账
→ 待处理备份恢复／撤回
→ 关闭意图对账
→ 快照扫描与索引重建
→ 历史隔离对账
```

- 每一步都有持久状态和专门恢复器；恢复器不知道的操作不凭文件名猜测。状态不明保留全部副本并进入 NeedsAttention，不自动永久化。
- 工作区库只接受当前 schema。高版本只读，当前版本损坏先走事务恢复与有效副本，仍失败才隔离并以空工作区继续；任何分支都不得覆盖原损坏数据。
- 快照索引可从自描述文件重建。先建立布局归属，再将有主快照交回既有 Document；无主快照进入显式恢复队列，不归入活跃项目。
- 历史隔离对账先于历史展示。完整隔离且未到期的项目继续隐藏，未完成项目保留或恢复来源，无法确认的批次保留来源和副本。
- 维护期失败只开放能安全提供的只读诊断与重试，不启动会改变相关状态的 PTY、watcher 或后台写入。

### 正常关闭

窗口关闭、托盘退出、项目移除、面板／终端关闭、Runtime 关闭和更新安装都调用同一个 CloseCoordinator，但请求必须携带关闭作用域。局部关闭只处理自己的对象集合；应用退出与更新移交才执行全局服务和正常退出段。

共享主干为：

```text
冻结关闭作用域的新变更（应用退出同时冻结外部请求）
→ 收集对象、代次和决定
→ 保存 Document／Hooks
→ 提交设置、需保留的布局、终端记录与关闭／删除意图
→ 停止关闭集合相关 PTY
→ 删除已提交恢复材料并销毁对应 Panel
```

仅应用退出与更新移交继续：

```text
停止全局服务与 watcher、撤销端点记录
→ 提交正常退出状态
→ 销毁窗口或进入更新 Handoff
```

- 收集阶段统一列出关闭集合中的脏 Document、Hooks 草稿、运行终端和未完成显式操作；保存、丢弃、取消均形成明确决定。取消在任何提交前恢复原运行状态。
- 关闭意图记录对象身份、代次、每项决定和提交指纹。最后引用判断在收集时完成，关闭集合外的共享 Document 不得被丢弃。
- 任一必要状态提交失败就停止进入下一破坏阶段，保留面板、PTY、草稿和恢复材料，提供重试；不得以 best-effort 继续。项目移除与批量面板关闭不停止无关服务、不撤销端点，也不写全局正常退出标记；项目专属布局和 ViewState 按项目删除协议在删除意图提交后清理。
- 快照等恢复材料只在对应关闭意图提交后、相关 Panel 销毁前删除。正常退出状态是应用退出的最后持久提交，不得提前到恢复材料删除之前；局部关闭不执行该提交。
- 最终状态提交失败时提供重试，或允许用户显式选择“退出且不保存本次窗口状态”并提示旧布局与可能残留的快照会在下次启动恢复；已停止 PTY 不自动重开，不伪造正常保存成功。OS 强杀不提供正常关闭保证，下次启动以对账结果为准。

### 恢复、重置与更新

- 备份恢复和撤回在当前进程鉴权、校验、预览、关闭预检后写入维护请求；实际替换只发生在下一启动维护期。维护提交后更换 store_epoch，并重新生成事件流。
- 跨机器恢复的项目先进入 RelocationRequired。用户重新授权并提交重定位前，不读取正文、不启动 PTY、不把旧根静默改绑。
- 更新安装先完成资产校验和用户确认，再进入 AwaitingClose 并调用 CloseCoordinator。最终状态提交失败取消 handoff；退出后的安装进程使用独立计划、PID＋创建时间、旁置锁、旧版回退和启动对账。
- 更新移交和 Runtime 关闭都遵守关闭中拒绝新写；安装程序不得直接杀进程、删数据目录或绕过维护期。

## 验收与测试

- 在测试子进程的真实提交边界注入终止，覆盖日志准备、正文应用、事务提交、关闭意图、正常退出标记、快照删除、恢复点和更新 handoff；重启后同时检查磁盘、数据库和副本。
- 双实例测试覆盖锁已存在、服务器未就绪、认证失败、队列满、移交失败和主窗口关闭中，第二进程均不得创建窗口。
- 正常关闭测试覆盖保存、丢弃、取消、共享 Document、Hooks 外部修改、PTY 停止失败和最终提交失败；任何失败不得静默进入破坏阶段。
- 异常启动测试覆盖有主／无主快照、损坏快照、布局缺失引用、未到期隔离批次和不明日志；不重复创建 Panel 或永久化不明材料。
- 恢复与更新测试断言 store_epoch、stream_epoch、旧 Runtime 代次和旧 PTY 写入全部失效，失败时旧版本和恢复点仍可回退。

## 操作

- 新增持久副作用时先登记其维护期恢复器和崩溃测试，再接入 UI 或 Runtime。
- 关闭相关实现不得直接调用进程退出；统一返回 CloseCoordinator 的结构化结果，由最外层决定退出或重试。
- 发布前使用真实 `slterm.exe` 验证正常关闭、强杀恢复、更新移交和第二实例行为，并将不可自动化条件登记到测试豁免。
