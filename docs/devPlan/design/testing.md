# 测试设计与验收证据

> 规定纯领域、应用服务、真实 Windows、崩溃恢复、GPUI 和 Runtime conformance 的测试接缝与证据规则。

## 决策与红线

### 测试层次与隔离

- core 测试覆盖纯状态机、解析器、路径判定、差分、编码、布局、补全和协议 DTO；不依赖 GPUI、真实用户目录或网络。
- application 服务测试使用假 Clock、FileSystem、GitProcess、Http、Credential、WindowsIntegration 和 PTY 端口；SQLite 使用临时目录真实数据库，不用内存 mock 替代事务与 WAL 验证。
- GPUI 测试使用虚拟窗口验证焦点、IME、命令上下文、共享 Document、布局恢复和关闭守卫；测试 feature 双门控，生产构建不带夹具。
- Windows 集成测试验证原子替换、ACL、硬链接、目录联接、回收站、ConPTY、凭据隔离和命名管道。特殊权限或桌面会话条件跳过必须登记豁免及兜底层级。
- Runtime conformance 启动真实 GUI 与 CLI，使用临时 AppPaths、隔离数据根和 `sk-test` 假凭据；不连接真实套餐服务，不使用用户凭据或真实工作区。
- 全量 cargo 与脚本钉测试串行执行；定向测试必须走显式 `lib_tests` target，禁止 `--lib` 或裸 filter 直打默认 lib target。

### 领域测试矩阵

| 领域 | 必须覆盖的行为族 | 主要证据 |
|---|---|---|
| 路径与身份 | 词法／规范／文件身份、能力并集、链接重定向、跨机重定位 | 属性测试、真实 Windows 文件测试 |
| 布局与视图 | 拆分合并、ViewKey 往返、未知过滤、实例销毁与隐藏差异 | proptest、GPUI 虚拟窗口 |
| Document | 编辑事务、撤销清脏、保存并发、编码、分页、外部变化 | Rope 属性、故障注入、GPUI |
| 语法与 Markdown | 全语言资产、增量中止、同源投影、安全 HTML／SVG、资源授权 | 样例语料、网络安全断言 |
| Diff 与 Git | 空白行键、deadline、固定绑定、索引回滚、部分成功 | 属性测试、真实临时仓库 |
| 终端与补全 | 背压、resize 水位、可信镜像、代次、学习清空 | ConPTY、假时钟、学习库 |
| Agent 与 Hooks | 能力目录、恢复幂等、隔离对账、子树保存、注入提交 | 假适配器、崩溃子进程、命名管道 |
| 设置与备份 | 单例队列、主题完整性、凭据排除、加密、维护恢复 | 真实 SQLite、DPAPI、篡改测试 |
| Runtime | 握手、方法面、幂等、OutcomeUnknown、事件续传、schema | 双进程 conformance |
| Windows 与发布 | 套餐调度、更新校验、托盘、诊断清理、安装回退 | 假平台、实机人工核验 |

### 故障注入与崩溃测试

- 在测试子进程的真实提交边界终止，再启动对账磁盘、数据库和副本。覆盖临时文件 flush／rename／目录同步、ACL、SQLite 提交、Online Backup、日志状态、关闭意图、正常退出标记、快照删除、恢复点、隔离批次和更新 handoff。
- 每个 Journal 状态 `Prepared`、`Applying`、`Committing`、`Committed`、`RollingBack`、`RolledBack`、`Failed`、`NeedsAttention` 都有可观察输入与恢复断言；状态不明不得自动永久化或重发副作用。
- 结果代次测试在任务完成前销毁所有者、改变 revision、切换项目、替换 token、重连 PTY、轮换 stream_epoch 和恢复 store_epoch，旧结果必须丢弃。
- 并发测试覆盖保存期间继续编辑、批量保存部分成功、关闭集合外共享 Document、多来源历史删除和重复 Runtime mutation；不得以时序假设代替同步点。
- 安全测试使用恶意 HTML／SVG／Markdown、链接重定向、路径别名、重复 JSON 键、超大输入、恶意压缩图片和伪造协议；断言无越权、无网络旁路、无敏感日志。

### 性能与资源断言

- 大列表、大文本、分页、虚拟化和后台取消使用结构断言与可复现实机场景，不写无环境前提的时延承诺。
- 性能记录必须包含硬件、Windows 版本、数据规模、测量方法、预热与统计口径；契约容量和调度数值直接由所有者测试固定。
- 反复创建／销毁视图、PTY、watcher、Runtime 客户端和后台任务后检查线程、句柄、队列和内存不持续增长；隐藏与销毁分别验证。

### 追溯与豁免

- 追溯关系为 featureSpec 所有者及验收场景 → devPlan 设计章节 → 实现测试例名／人工豁免。使用场景名和测试名，不引入编号体系。
- [追溯矩阵](../traceability.md) 初始目标测试名为计划锚，不代表测试已存在；实现后将状态改为已执行并填实际证据，最终逐条核销，不能只以全量测试全绿替代覆盖检查。
- 不可自动化面必须在 `.claude/docs/testing/exemptions.md` 登记根因、兜底层级和人工核验方式；条件跳过不是默认豁免，未登记不得交付。
- 测试失败、跳过和人工未核验必须如实进入阶段证据；进度文件不得将计划锚写成已通过。

## 验收与测试

- 门禁包括架构／依赖、文档策略、禁名、clippy、fmt、全量串行测试、脚本门禁自测和必要的真实 Windows 验收。
- 测试自身要有负例：错误版本、错误代次、错误路径、错误哈希、错误凭据和错误提交顺序均应被识别，不能只测成功路径。
- 真实进程验收确认没有第二窗口、孤儿 PTY／watcher／更新进程、遗留端点记录或未对账副本。
- 发布前核对追溯矩阵、豁免登记、许可清单、Runtime schema 和安装包内容；缺证据即未完成。

## 操作

- 全量与定向命令使用 [.claude 命令矩阵](../../../.claude/docs/operations/commands.md)；新增测试 target 时同步命令矩阵与架构门禁。
- 新功能先写失败行为测试，再实现；修复自己引入的红灯可直接修，但必须在交付中说明。
- 新增豁免、人工步骤或性能基线时同步本文件、豁免文档和追溯矩阵，不把口头结论当作验收。
