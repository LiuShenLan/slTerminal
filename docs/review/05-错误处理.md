## 2. unwrap/panic 审计统计

- **Rust 端 `unwrap()` / `expect()` / `panic!` / `unreachable!` 总行数**：约 **1009** 行（`rg -n` 匹配数）。
- **生产代码中数量**：经脚本按 `#[cfg(test)]` / `mod tests` 块外扫描，并结合 `state.rs`、`pty/spawn.rs`、`notify/mod.rs`、`hooks/claude/inject.rs`、`agent_history/claude/ops.rs` 等关键文件人工复核，**生产代码中未发现 unwrap/expect/panic/unreachable! 调用**。
- **测试代码中数量**：约 **1009** 行，全部位于 `#[cfg(test)] mod tests` 或单元测试辅助函数内，符合 Rust 测试习惯。
- **Mutex / RwLock 中毒处理**：生产代码中所有 `Mutex::lock()` / `RwLock::read()` / `RwLock::write()` 均使用 `map_err(...)` 将中毒错误转换为 `AppError::IoKind`/`AppError::Pty`/`AppError::Git`/`AppError::Notify`，不会传播 panic。例如：
  - `src-tauri/src/state.rs:191` project_root 写锁
  - `src-tauri/src/state.rs:204` ring buffer 锁
  - `src-tauri/src/pty/spawn.rs:230` ConPtyInner 锁
  - `src-tauri/src/notify/mod.rs:190` watch_paths 锁
- **数组/集合直接索引**：生产代码中未发现 `vec[i]`、`HashMap::get(...).unwrap()` 等高风险直接索引。
- **`unreachable!`**：全仓库未使用。

**高风险点**：无 P0 级 unwrap/panic 风险点。

## 5. 建议修复

按优先级排序，不制定执行计划：

1. **建立前端统一错误解析与通知机制（P1）**
   - 在 `src/ipc/` 或 `src/lib/` 增加 `parseAppError(error): AppError | null`，将 Rust `AppError` 的 camelCase JSON 变体解析为结构化对象。
   - 所有 IPC 调用统一通过该解析器处理错误，支持按 `ioKind`/`pty`/`git`/`validation`/`pathNotAllowed` 等变体给出差异化提示。
   - 增加全局错误通知/状态栏入口，关键错误（保存失败、spawn 失败、项目数据损坏）必须 toast 或状态栏提示。

2. **消灭关键路径的静默吞错（P1）**
   - `src/main.tsx:38`、`src/App.tsx` 启动链、`src/stores/projects.ts` 加载/保存、`src/features/explorer/useFileTree.ts` 加载目录、`src/panels/terminal/useXterm.ts` 关键 PTY 操作等，catch 后至少记录日志并给出用户可感知的降级或提示。
   - `loadSettings`/`load_projects` 的 JSON 损坏降级应返回带 `corrupted` 标志的对象，调用方据此告警。

3. **为面板增加局部 ErrorBoundary（P1）**
   - 在 `panelRegistry.ts` 或 `PageDockviewHost` 渲染面板时包裹 `ErrorBoundary variant="inline"`，防止单个面板渲染错误导致整个 Workspace 崩溃。

4. **后端错误上下文增强（P1/P2）**
   - `From<std::io::Error>` 丢失路径；建议在涉及文件路径的命令内核（如 `fs_*_impl`）使用 `map_err` 将路径注入消息，而非依赖通用 `?` 转换。
   - `AppError` 可考虑增加 `ConfigParse`/`PathTraversal` 等更细变体，但需同步更新前端解析器与 DTO。

5. **统一错误消息风格（P2）**
   - 用户可见错误消息统一为中文业务语义，技术细节（锁中毒、OS error code 等）写入 tracing/应用日志。
   - 前端增加 `getErrorMessage(err)` 工具函数，统一从 `unknown` 错误中提取可读消息。
