## 7. 建议修复

1. **立即处理 P0 漏洞**：优先修复 `serialize-javascript` RCE，通过升级 `@wdio/mocha-framework` 或覆盖 resolution 到 ≥7.0.5。
2. **升级 E2E 工具链**：整体升级 `@wdio/*` 到 wanted/latest patch，同步升级 Rust 侧 `tauri-plugin-wdio-webdriver` 到 1.3.0；若 E2E 近期不启用，考虑将其依赖从主 `package.json` 移除或移入独立 workspace。
3. **补全未声明依赖**：将 `json-schema` 与 `@lezer/highlight` 显式加入 `package.json` 依赖，避免传递依赖漂移导致构建/类型失败。
4. **回退或锁定 xterm 预发布**：评估终端是否必须依赖 xterm beta 特性；如非必要，回退到最新稳定版；如必须保留，建立 beta 版本升级审批与回归测试。
5. **升级 notify 到正式版**：持续跟踪 notify 9.0 正式版发布，及时替换 RC 依赖。
6. **制定 major 升级计划**：重点处理 `typescript` 6→7、`dockview-react` 6→8、`json-schema-library` 9→11、`@testing-library/jest-dom` 6→7、`jsdom` 29→30、`@types/node` 25→26。
7. **统一版本号策略**：在团队内约定 `^`/`~`/精确版本的使用规则，建议生产运行时依赖使用精确版本或 `~`，开发工具使用 `^`，并依赖 lock 文件保持一致。
8. **配置 knip entry**：将 `e2e-tests/**/*.ts` 加入 `knip.json` entry，消除 `@wdio/*` 误报，使依赖审计结果更干净。
9. **建立定期依赖审计 CI 门禁**：在 CI 中恢复 `npm audit`（需切换 registry 到 npmjs 或配置 mirror 支持 security advisories），安装并运行 `cargo audit`，阻止新增高危漏洞合并。
10. **评估 JSON Schema 库去重**：研究 `codemirror-json-schema` 与 `json-schema-library` 职责边界，考虑统一为单一库以减少维护面。
