# 独立复核台账

> 基线 `53c2a1504a287917f78e58f580a7bd4b3e752060`（当前分支）；复核对象为 `docs/review/` 下 23 份分报告的阻断与重要项。

## 基线与方法

- 逐份读取 23 份分报告，提取全部“阻断”和“重要”条目；一般与提示项只在同源、重复或冲突时纳入。
- 对每条问题重新读取被引用的源码、文档章节、测试函数体与调用点，不以报告自述作为证据；结论只取“确认／驳回／无法验证”。
- 跨报告同一问题合并为一个条目，列出全部来源；严重度冲突以本次重读的代码证据裁定，可上调或下调一级并写明理由。
- 门禁证据只读取作业临时目录下的日志，不重跑 cargo、测试、脚本或网络。
- 复核期间未修改任何源码、配置、既有文档；唯一写入为本台账。

## 复核范围与限制

- 已重读的主要代码面：应用壳关闭链与设置/导航/Hooks 接线、Document 注册/外部变化/搜索替换/编码、Markdown 投影与渲染调度、GPUI 终端视图与终端核心事件循环、Runtime 协议/服务/派发/事件环、持久化与加密备份、平台集成与更新链、脚本与发布链、工作区/侧栏/路径授权。
- 已重读的文档面：根与各层 `CLAUDE.md`、相关 featureSpec 与 devPlan 章节、测试豁免表、发布说明与 `CHANGELOG`。
- 未执行：cargo、构建、测试、安装器、真实 GUI/PTY/IME、真实 Windows 凭据库、真实网络与 SMB 共享、真实发布机核验。凡结论依赖这些运行时事实的条目，另在“无法验证项详解”列出缺失证据。
- 报告中的“一般”“提示”未逐条复核；只在与阻断/重要同源时并入对应条目。

## 驳回项详解

- **“以下目标例名在源码中不存在”这一组证据部分被驳回。** `app-root-content` 的追溯矩阵条目与 `test-quality`、`plan-audit` 的同类表述把多个例名整体判为不存在。重读确认 `document_discard_respects_external_reference`、`ordinary_open_does_not_deduplicate_diff_or_gitshow`、`document_rename_preserves_identity_and_view`、`explorer_rejects_cross_root_cut_and_descendant_paste`、`diff_conflict_snapshot_is_immutable`、`diff_large_and_binary_side_degradation` 均以 `fn` 定义存在于工作区、侧栏或 Document core 测试中；其中 `commit_rollback_preserves_staged_changes` 确实不存在。该子证据被驳回，但这些用例只覆盖 core/服务层、未经过生产面板或未覆盖产品入口的“证据层级不足”结论仍成立。台账保留“追溯矩阵证据层级不一致”问题，严重度重要。
- **`diff_conflict_snapshot_is_immutable` 与 `diff_large_and_binary_side_degradation` 的存在不等于产品能力成立。** 两者分别位于 `slterm_document` 的 diff 测试，验证 core 的不可变快照与大文件/二进制按侧降级；应用 `build_source_content` 仍要求可编辑 Rope，`DiffInput::conflict` 无生产调用。因此“产品级冲突快照/大文件降级缺失”仍确认，但报告若以“例名不存在”作为主要证据，该证据被驳回。
