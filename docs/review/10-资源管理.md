## 2. 生命周期与泄漏面逐项审计

### 2.1 后端 PTY 会话

- **创建**：`pty_spawn`（`spawn.rs:958`）通过 `Uuid::new_v4()` 生成 session_id，创建 `PtySession` 后插入 `PtyState.sessions`。
- **回收**：正常路径 `pty_kill`（`:1261`）先 remove 再 kill + join reader；`PtySession::Drop`（`state.rs:37`）会兜底 join reader_handle。
- **缺口**：
  - 无会话总数上限（P0-1）。
  - `child.kill()` 返回值被丢弃，`handle.join()` 无超时（P1-3）。
  - 关闭序列仅依赖前端 `TerminalRegistry`，前后端状态不一致时后端 session 泄漏（P1-5）。

### 2.2 后端文件系统监听

- **创建**：`notify_watch`（`notify/mod.rs:287`）将 watcher 放入 `LruWatcherPool`，容量 5。
- **回收**：池满时 LRU 淘汰，`AppState` Drop 时 `stop_all`；`FileWatcher::Drop` 发送停止信号并 join 线程。
- **缺口**：
  - 递归监听未排除大目录（P0-2）。
  - 前端只 start 不 stop，项目删除/切换后 watcher 仍保留到 LRU 淘汰（P1-8）。
  - 容量硬编码且暂停仍占句柄（P2-15）。
  - `notify_watch` 为同步命令，可能阻塞 IPC worker（P1-9）。

### 2.3 后端 git 仓库缓存

- `AppState.git_repo_cache`（`state.rs:78`）在 `git/mod.rs` 多处通过 `get_or_open_repo` 使用。
- 无清理/淘汰机制，切换项目后旧 `git2::Repository` 仍保留（P1-4）。

### 2.4 前端终端子系统

| 组件 | 订阅/定时器 | 清理状态 | 问题 |
|------|-------------|----------|------|
| `usePtyOutput` | idle/max timer | 仅 `cancelPendingFlush` 可被外部调用 | 卸载时未主动清理定时器（P1-6） |
| `useXterm` | `requestAnimationFrame`、agent-event listen、fit timeout | `cancelAnimationFrame`、unlistenAgentEvent、kill PTY | 未调用 `cancelPendingFlush`（P1-7） |
| `usePtyResize` | ResizeObserver + resize timer | `disconnect` + `clearTimeout` | 合规 |
| `useTerminalInstance` | WebGL retry timers、`document.fonts.ready` | `cancel` WebGL、dispose addon/Terminal、clear E2E buffer | 合规（`fontsReadyCancelledRef` 双重检查） |
| `useCommandDetection` | OSC 133 handler | `disposable.dispose()` | 合规 |
| `useClipboardHandler` | OSC 52 handler | `disposable.dispose()` | 合规 |
| `useFontSizeWheel` | wheel listener | `removeEventListener` | 合规 |
| `TerminalPanel` | TerminalRegistry subscribe、title/param change disposables、loading timer | unsubscribe/dispose/clearTimeout | 合规 |

### 2.5 前端数据 hooks

| Hook | 清理状态 | 问题 |

### 2.6 前端轮询任务

- `pageApis.ts:switchToPageAndFocus` / `openHooksConfigPanel` 使用 100ms×50 轮询，无取消机制（P2-13）。
- `restoreSession.ts:waitFor` 同样不可取消（P2-14）。

### 2.7 Ring Buffer

- 后端 `output_ring` 容量 256KB（`state.rs:199`），`ring_buffer_append` 在超过容量时从头部丢弃，有界安全。
- 前端 `usePtyOutput` pending buffer 上限 64KB，`e2eTextBuffer` 上限 1000 行，有界安全。

## 5. 建议修复（按优先级排序）

1. **限制 PTY 会话无限增长（P0）**
   - 在 `pty_spawn` 增加 `MAX_PTY_SESSIONS` 上限，返回结构化 `AppError`。
   - 关闭序列增加后端 kill-all 命令，避免前后端状态不一致导致泄漏。

2. **收敛文件监听事件风暴（P0）**
   - 在 `notify_watch` 中为 watcher 增加排除列表（`node_modules`、`target`、`.venv`、`.git` 等）。
   - 评估是否改为非递归监听 + 按需刷新。

3. **强化 PTY 清理可靠性（P1）**
   - `pty_kill` 检查 `child.kill()` 返回值，失败时尝试 `TerminateProcess`。
   - 对 `reader_handle.join()` 增加超时，避免 kill 失败后永久阻塞。

4. **增加 git 仓库缓存淘汰（P1）**
   - 给 `git_repo_cache` 设置 LRU 容量上限，或在 `set_project_root` 时清理非当前项目/无关仓库。

5. **补齐 watcher 生命周期（P1）**
   - 暴露 `notify_stop_watch` 命令，项目移除/切换时调用；`removeProject` 联动清理。
   - 将 `set_project_root` 与 `notify_watch` 改为 async + `spawn_blocking`，避免阻塞 IPC worker。

6. **清理终端输出定时器（P1）**
   - `usePtyOutput` 提供显式 dispose，`useXterm` cleanup 中调用 `cancelPendingFlush()`。

7. **取消可丢弃的轮询任务（P2）**
   - `switchToPageAndFocus`、`openHooksConfigPanel`、`restoreSession.ts:waitFor` 支持 `AbortSignal`。

8. **修复 hooks 配置守卫泄漏（P2）**
   - `useHooksConfig.confirmDiscard` 的 `setTimeout` 存 ref，effect cleanup 中 `clearTimeout`。
   - `setLayer` 的 async IIFE 加 `try/catch`。

9. **给 useAgentStatus 初始扫描加 generation（P2）**
   - 与 `useFileTree` 的 `genRef` 模式一致，避免项目快速切换时状态覆盖。
