2. 关键路径静默吞错 / 降级（启动链、持久化、PTY、文件树）。
3. 同步阻塞命令与事件风暴（`set_project_root`、`notify_watch`、PTY reader、fs-event）。

## 3. P0 必须修复清单

### P0-1 `serialize-javascript` RCE 漏洞

- **位置**：`package.json` / `package-lock.json`（`@wdio/mocha-framework` 传递依赖）
- **来源维度**：06-依赖审计 #1
- **详细说明**：`serialize-javascript <=7.0.4` 存在 GHSA-5c6j-r48x-rmvq RCE；当前 `@wdio/mocha-framework` 锁定在受影响版本。
- **修复方向**：升级 `@wdio/mocha-framework` 到 ≥8.14.0，或覆盖 `serialize-javascript` 到 ≥7.0.5；E2E 暂不启用时可移出主依赖。
- **预估工作量**：小

### P0-2 Shell 白名单仅比对文件名导致 RCE

- **位置**：`src-tauri/src/pty/shell.rs:29-58`、`src-tauri/src/pty/spawn.rs:979`
- **来源维度**：07-安全性 #1
- **详细说明**：`validate_shell_allowlist` 只取文件名比对，攻击者可传入项目根下的 `cmd.exe` 或篡改 `PATH` 绕过白名单，经 `CreateProcessW` 执行任意程序。
- **修复方向**：白名单校验程序真实身份（系统目录 / 签名 / 哈希）；`resolve_shell_info` 对用户提供的绝对路径不再信任文件名。
- **预估工作量**：大

### P0-3 Hook 信号目录未过滤符号链接导致越界读取

- **位置**：`src-tauri/src/hooks/signal.rs:82-127`、`src-tauri/src/hooks/watcher.rs:155-174`
- **来源维度**：07-安全性 #2
- **详细说明**：`~/.slterminal/hooks-events/` 中的 `.json` 文件被直接读取并 emit，未过滤符号链接；低权限进程可放置指向敏感文件的 symlink，经 `agent-event` 泄露内容。
- **修复方向**：`process_signal_file_with` / `collect_signal_files` 增加 `is_symlink` 检查；或将信号目录权限收紧为仅应用自身可写。
- **预估工作量**：中

### P0-4 `Workspace` 为每个 page 保留 Dockview 实例

- **位置**：`src/workspace/Workspace.tsx:253`
- **来源维度**：08-性能 P0-1
- **详细说明**：所有 `allPages` 都渲染 `PageDockview`，仅通过 `visible={page.pageId === activePageId}` 隐藏；page 越多，React 树、DOM 节点、Zustand 订阅者线性增长。
- **修复方向**：只渲染当前 active page 的 Dockview，切换时卸载旧实例；需要保留状态的 page 用快照 / 懒卸载策略。
- **预估工作量**：大

### P0-5 文件 watcher 递归监听且未排除大型依赖目录

- **位置**：`src-tauri/src/notify/mod.rs:103-110`、`src-tauri/src/fs/mod.rs`
- **来源维度**：08-性能 P0-2、09-稳定性 #1、10-资源管理 #2
- **详细说明**：`notify_watch` 使用 `RecursiveMode::Recursive` 监听项目根目录，`fs_read_dir` 不过滤 `node_modules`、`target`、`.venv` 等；大仓库产生事件风暴，debouncer 与 Tauri 事件队列可能无限积压。
- **修复方向**：增加可配置排除列表（`node_modules`、`target`、`.venv`、`.git` 等），或改为非递归监听 + 按需刷新。
- **预估工作量**：中

### P0-6 `fs_read_file` 一次性读入整个文件

- **位置**：`src-tauri/src/fs/mod.rs`
- **来源维度**：08-性能 P0-3
- **详细说明**：`fs_read_file` 使用 `std::fs::read_to_string` 一次性读入完整文件；前端虽有 10 MB 硬限制，但大文件仍会导致后端内存峰值高、IPC 包大、编辑器卡顿。
- **修复方向**：改为分块读取或通过 stream/channel 推送；编辑器对大文件采用虚拟化或仅加载可见区域。
- **预估工作量**：大

### P0-7 `set_project_root` 同步命令在主线程执行

- **位置**：`src-tauri/src/state.rs:186`、`src/App.tsx:84-87`、`src/stores/projects.ts:154`、`src/workspace/Workspace.tsx:216`
- **来源维度**：03-架构合规性 #3、07-安全性 #14、08-性能 P0-4、09-稳定性 #7、10-资源管理 #9
- **详细说明**：`set_project_root` 是同步 `#[tauri::command]`，在主线程执行 `dunce::canonicalize`；慢路径（网络驱动器、大量符号链接）会阻塞 Tauri 主线程，且多个调用方仅 `console.error` 静默失败。
- **修复方向**：将 canonicalize 移入 `spawn_blocking`，命令改为 `async`；调用方在失败时阻止 `setActivePage` 或提示用户。
- **预估工作量**：中

### P0-8 PTY reader 每 16 KB 就发送一次 Channel 消息

- **位置**：`src-tauri/src/pty/reader.rs`
- **来源维度**：08-性能 P0-5
- **详细说明**：`reader_loop` 以 16 KB 缓冲区循环读取，每次成功读取都经 `Channel` 推向前端；高输出场景 IPC 调用次数与字节数成正比，头部开销高。
- **修复方向**：在 reader_loop 中引入 1–2 ms 本地批处理或 4–8 KB 最小发送阈值，合并多次小读取。
- **预估工作量**：大

### P0-9 `pty_spawn` 未限制后端 PTY 会话总数

- **位置**：`src-tauri/src/pty/spawn.rs:958`
- **来源维度**：09-稳定性 #2、10-资源管理 #1
- **详细说明**：用户持续新建终端可能耗尽 Windows ConPTY/进程句柄，导致后续 spawn 失败或系统资源紧张。
- **修复方向**：增加 `MAX_PTY_SESSIONS` 硬上限，在 `PtyState` 维护计数或检查 `sessions.len()`，超限返回结构化 `AppError`。
- **预估工作量**：小

## 6. 架构约束专项结论

综合 `02-架构约束合理性.md` 与 `03-架构合规性.md`：

**需修订的约束**：

1. **约束 #11（测试覆盖）**：当前要求“所有改动代码都需全量自动化测试”，但 `.claude/test-inventory.md` 已登记 9 项既定豁免（DOC-01）。应修订为“可自动化部分必须覆盖，不可自动化部分须在 DOC-01 登记豁免并注明原因”。
2. **约束 #9（平台分支收敛）**：当前措辞未区分业务逻辑 `#[cfg(windows)]` 与测试用例中的平台特性分支。应明确业务 cfg 仅允许出现在 `pty/`、`conpty_api`/`shell`/`win_build`，测试 cfg 可豁免但须说明。
3. **约束 #5（面板封闭）**：`hooksConfig` 已形成“hub 容器 + 注册表分派子编辑器”的新模式，应补充该合法形态，避免开发者误以为子编辑器也必须是顶层 Dockview 面板类型。
4. **约束 #4（DTO 双边对应）**：`HooksLayer` 泛化为 `string` 后，语义值集散落在 CLI profile 与后端 provider 两处。应补充“字段类型泛化后，语义值集须在 profile 与后端 provider 同步登记并配合同步测试”。
5. **约束 #6（配色单点）**：应将 `FileIcon` 六色盘、`NavProjectRow` 文件夹蓝、启动链 fail-safe 等完整例外清单写入约束正文，并规定新增例外须同步登记于对应模块 CLAUDE.md。

**被违反的约束（代码层面）**：

- 硬约束 #2： `src-tauri/src/projects.rs:5` 直接导入 `settings::app_data_dir`，跨模块共享未经过 `AppState`。
- 硬约束 #3：`set_project_root` / `notify_watch` 为同步命令，阻塞 I/O 未使用 `spawn_blocking`。
- 硬约束 #9：`#[cfg(windows)]` 出现在 `lib.rs`、`fs/mod.rs`、`settings.rs`、`agent_history/claude/ops.rs` 的测试代码中。
- ADR-0003（无动效）：`src/panels/terminal/TerminalPanel.tsx:206` 使用 `transition: "opacity 0.3s"`。

**约束体系缺口（建议补充）**：

- **Zustand stores/ 全局状态约束**：状态与业务分离、持久化经指定 IPC、禁止跨 store 隐式依赖。
- **通用注册表约束**：`CliProfileRegistry`/`FileViewerRegistry`/`SideViewRegistry`/`ShortcutRegistry` 等模块级单例的统一接口、side-effect import 触发、`_reset` 测试隔离。
- **hooksConfig schema 单点**：SchemaStore 官方 schema + hooks 子 schema + Draft07 校验应作为项目资产写入约束或模块 CLAUDE.md。
- **CLI profile 能力分派模式**：`configEditor` 分派、notifications/agentHistory 策略分派已成为扩展新 CLI 的核心机制，应纳入约束或 ADR。

## 7. 主题归纳

跨维度的共性问题主题如下：

1. **无界资源增长**：PTY 会话无上限、`git_repo_cache` 无淘汰、`LruWatcherPool` 容量偏小、文件 watcher 递归监听大目录。根因：缺少资源配额与淘汰策略。
2. **静默吞错 / 降级**：启动链、持久化、PTY、文件树、设置保存等关键路径大量 `catch(() => {})` 或仅 `console.error`。根因：前端缺少统一错误解析器与通知机制，后端持久化未返回 corruption 标志。
3. **DTO 契约漂移 / 弱类型**：`DirEntry` 可选性、`HooksLayer` 任意 string、hooks 配置 Rust 端 `serde_json::Value`、无 `AppError` 结构化解析器。根因：泛化 CLI 后语义契约散落在 profile/provider/类型三处，缺少同步机制。
4. **生命周期与取消遗漏**：`usePtyOutput` 定时器、`readHistoryTitle` promise、`switchToPageAndFocus` 轮询、`restoreSession.ts:waitFor`、watcher start/stop 不对称。根因：异步任务缺少 `AbortSignal`/dispose 语义。
5. **订阅/渲染粒度过粗**：`TerminalPanel` 订阅整个 `TerminalRegistry`、`Workspace` 保留所有 page Dockview、`SideBar` display:none 不卸载、`useNavTree` 全量重建。根因：缺少按 ID 的细粒度 selector 与按需卸载策略。
6. **同步阻塞命令**：`set_project_root`、`notify_watch` 在主线程执行阻塞 I/O。根因：部分命令未遵循「阻塞 I/O 用 `spawn_blocking`」约束。
7. **安全纵深防御薄弱**：Shell 白名单仅文件名、hook 信号/文件监听不过滤 symlink、HTML iframe 键盘转发无 token、剪贴板读取权限过宽、自定义命令未白名单。根因：边界校验与权限最小化未完全落地。
