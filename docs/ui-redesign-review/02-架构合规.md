## 问题清单

### [P1] 多处组件/样式直接硬编码色值，未走 theme/colors.ts facade
- 位置：
  - `src/App.css:59,63,66` — 滚动条滑块 `rgba(255, 255, 255, 0.10/0.20/0.28)`
  - `src/App.css:75` — 全局 `:focus-visible` outline `#6e9ff2`
  - `src/main.tsx:30-31` — IPC 超时错误页 `background:#0a0a0b`、`color:#ece9e4`、`color:#d9706b`
  - `src/features/titleBar/TitleBar.tsx:22` — 关闭钮 hover 底 `#c04747`
  - `src/features/explorer/FileIcon.tsx:37-44` — 文件类型六色盘（`#7fa8e8` 等）
  - `src/features/navTree/NavProjectRow.tsx:23` — 项目文件夹蓝 `#7fa8e8`
- 描述：颜色字面量直接出现在全局 CSS、启动 fail-safe 页、组件 inline style 常量中，未通过 `theme/colors.ts` token 引用。局部模块 CLAUDE.md（titleBar/explorer/navTree）将其登记为例外，但根 CLAUDE.md 硬约束 #6 明确既定例外只存在于 `src/panels/CLAUDE.md`（终端 adapter），因此构成明确违规。
- 依据：硬约束 #6
- 来源：本次重设计引入（UI-808/GL-01、启动链 fail-safe、UI-602/NAV-09/TB-03）
- 修复建议：
  - `App.css` 滚动条三色与 focus 色新增 CSS 变量，由 `theme/colors.ts` 的 `ROOT_CSS_VARS` 注入；
  - `main.tsx` 超时页改为读取 `ROOT_CSS_VARS` 或等待最小方案加载后再渲染；
  - 文件类型六色盘、项目文件夹蓝、关闭危险色在 `theme/schemes/linear.ts` 新增语义 token（如 `FILE_TYPE_COLORS`、`CLOSE_HOVER_BG`），组件全部引用 token。

### [P1] navTree 直接引用 panels/terminal 内部 TerminalRegistry
- 位置：
  - `src/features/navTree/NavTree.tsx:56` — `import { TerminalRegistry } from "../../panels/terminal/TerminalRegistry";`
  - `src/features/navTree/NavTree.tsx:107-119` — `findPanelForSession` 调用 `TerminalRegistry.getAll()` 遍历 PTY 会话元数据
- 描述：统一导航树未通过 `panels/terminal/` 的公开出口（`index.ts` 仅导出 `TerminalPanel`）获取终端会话信息，而是直接依赖 terminal 模块内部实现。虽然仅读取未自存，但违反了面板封闭/模块边界收敛原则；根 CLAUDE.md 约束 #8 只规定 PTY 映射由 TerminalRegistry 单点管理，并未授权其它 feature 直接引用其内部 API。
- 依据：目录分层原则（面板封闭/模块间不互相穿透）+ 硬约束 #8（单点管理语义延伸）
- 来源：本次重设计引入（NAV-03 运行中历史会话切换定位）
- 修复建议：在 `panels/terminal/index.ts` 公开只读查询函数（如 `findPanelIdBySession(cliId, sessionId)`），或将该查询上提到 `workspace/pageApis`，`navTree` 仅调用上层暴露的接口。

## 核查覆盖说明

1. **invoke 只出现在 `src/ipc/`**：合规。全仓 grep 仅 `src/ipc/*` 调用 `invoke(`，其余文件调用 `src/ipc/` 暴露的领域函数。
2. **后端按功能分模块、共享经 `state.rs` AppState**：合规。`lib.rs` 的 `generate_handler!` 注册 33 条命令，均来自对应模块；`AppState` 集中持有 pty/watcher/project_root/git cache。
3. **命令统一注册、返回 `Result<_, AppError>`、阻塞 I/O 用 `spawn_blocking`**：合规。`fs/git/settings/projects/agent_history` 均使用 `spawn_blocking`，命令签名返回 `Result<_, AppError>`。
4. **DTO 双边对应 snake_case ↔ camelCase**：合规。抽查 `agent_history/mod.rs` 与 `src/types/agentHistory.ts` 字段一一对应且使用 `#[serde(rename_all = "camelCase")]`。
5. **面板封闭**：合规。`panelRegistry.ts` 注册 6 种类型，与 `src/panels/*/` 实际目录一致；`PANEL_TYPES` 白名单完整。
6. **配色单点**：违规。见问题 [P1]「多处组件/样式直接硬编码色值」。
7. **布局单点**：合规。`navTree` 仅通过 `workspace/pageApis` 切换页面/聚焦面板，`makeEmptyLayout` 返回空对象；未直接操作 Dockview `toJSON/fromJSON`。
8. **会话元数据单点**：基本合规。`navTree` 自身不存储 PTY 会话元数据，依赖 `useAgentStatus`/`useAgentHistory`；但直接读取 `TerminalRegistry` 内部 API 造成边界穿透，见问题 [P1]。
9. **平台分支收敛**：基本合规。业务逻辑 `#[cfg(windows)]` 集中在 `src-tauri/src/pty/`；`fs/settings/agent_history/state` 中的 `#[cfg(windows)]` 仅用于测试断言（平台默认行尾/符号链接/只写文件行为），非业务逻辑。
10. **权限最小化**：合规。`src-tauri/capabilities/default.json` 未使用通配 `*`，仅声明所需插件权限；自定义命令按 Tauri 2 默认自动放行（已在 capabilities 中备注）。
11. **测试覆盖**：无法静态逐行判定。新增模块（titleBar、ConfirmDialog、toast、navTree、StatusDot、icons）均有对应 L2 测试文件；完整覆盖以 `.claude/test-inventory.md` 为准。
