# pebrel 重构优化 spec · 分片 06：设置 / 主题 / i18n

baseline commit：`e537d528c508e8607d0f5f9fd25e5902f40d661e`（pebrel，Rust + GPUI 模块化单体）

## 优化面

本分片覆盖六件事：

1. **设置核心**——`nebula_settings` crate 全景：`nebula_settings.txt` key=value 读写路径（全局决策已定改 JSON，本分片裁定「语义照抄、载体替换」）、`RuntimeSettings` 单一权威大结构、键域枚举族、宽容解析合同、语言注册表、`agent_hooks` 偏好、`app_icon` 色板、`cursor_motion`/`ligatures`/`notifications`/`scrolling` 各小域、`restore_default_settings` 重置语义、`paths` 目录解析与旧数据迁移——逐面裁定。
2. **主题系统**——`TermTheme`/`ExactTermColors` 终端色表模型、`ReviewedPalette` UI 语义槽、`custom_theme.rs` 用户主题值模型、`wcag_contrast_ratio`/`meets_wcag_aa` 对比度校验、`theme_library` 版本化文档/有界导入导出/持久化、主题包 ZIP、`theme_editor`/`theme_picker`/`theme_transfer` GUI；**仅暗色定位下 pebrel 亮/暗双主题机制的裁定**（亮主题全砍，含 `LIGHT_FOREGROUND`/`LIGHT_ANSI` 替换表与 `follow_system_theme`）；对照 slTerminal 现状 `src/theme/`（schemes 值文件、`SchemeRegistry`、`colors.ts` facade、硬约束 #6 配色单点）给出 GPUI 世界主题 token 机制重建方向。
3. **GUI 设置界面**——`gpui_shell/settings_pane/` 整体形态（导航分组、表单行节奏、select 值/显示分离）、`navigation.rs` 的中英文搜索关键词索引（搜索=路由查找而非过滤）、`theme_editor`/`theme_package`/`scrolling`/`appearance_advanced`/`localization`；对照 slTerminal `src/features/settingsCenter/`（`SettingsPageRegistry` 注册表家族契约、全局/Agent 二分）与 `src/panels/settings/`。
4. **i18n**——`nebula_app/i18n/*.json` → `build/i18n.rs` build.rs 静态生成（`Message` 枚举 typed ID + `MESSAGES` 静态表零分配查询）、`format.rs` 命名占位符、en-US 与 zh-CN 键集完全相同硬合同、`tools/i18n-contract` 独立合同 workspace + `tests/i18n_contract.rs`、`platform/locale.rs` 系统 locale 探测、`docs/internationalization.md` 文案规则——**语言只留 en-US + zh-CN**（已定），其余九语整删。
5. **hooks 配置迁移**——slTerminal `src-tauri/src/hooks/` 与设置中心 `hooksConfigGui.ts` 在新设置体系的归宿，与分片 03 的 ai_hook 安装器交界裁定。
6. **slTerminal 侧现状对照**——`src-tauri/src/settings.rs`（settings.json 八键白名单、原子写/.bak/保存锁）、`src/stores/`（纯状态约束 #12）、`src/theme/`、`src/features/settingsCenter/` 的映射与保留资产清单。

已定全局决策：GUI 设置页照抄；设置持久化 JSON 化（砍 Lua 栈与 key=value 文本，GUI 写入的权威文件改 JSON）；主题 WCAG 对比度校验照抄；i18n 静态生成机制照抄、语言只留 en-US + zh-CN；不采纳 Lua 配置栈（mlua/config_builder/nebula_config 的 Lua 后端/derive 诊断体系）、多平台、SSH、Quick terminal；仅暗色模式定位；`nebula_*` → `slterm_*` 改名。

## 采纳点

### 设置核心（nebula_settings crate）

1. **照抄：`RuntimeSettings` 单一权威大结构 + `from_raw` 宽容解析合同**（`nebula_settings/src/lib.rs` 的 `RuntimeSettings` / `RuntimeSettings::from_raw`）。一个结构承载全部运行时用户设置，逐键语义钉死：未知值回退默认、钳制范围（如字号 4–96）、`Option` 字段 None=键未设置由调用方回退、`parse 宽容`（手改配置文件的人写错不炸）。这是设置模型的心智核心——字段即合同，JSON 化后逐字段语义原样保留，只换读写载体。
2. **照抄：键域小枚举族模式**（`lib.rs` 的 `CursorShapeName` / `AcceptKeyName` / `CompletionStyleName` / `TabsPositionName` / `TabRevealName` / `DensityName` / `NewTabPositionName` / `WindowingBehaviorName` / `VcsDisplayName` / `BellModeName` / `BlurModeName` / `CellWidthModeName` / `ProxyModeName`）。每个枚举四件套——`from_settings`（大小写/空白归一 + 历史别名兼容）、`settings_value`（写盘值）、往返测试、`ALL`/`VALUES` 常量供 GUI 枚举——新设置键一律按此形态落地，杜绝散落的字符串比较。
3. **照抄：「显式值权威」三元模式**（`lib.rs` 的 `RuntimeSettings::opacity_is_explicit` / `blur_is_explicit`、`pane_card_radius` 四键的 `None`=用户没设过跟随主题默认）。模式一句话：默认值可以来自主题/回退层，但用户显式写过（哪怕写的恰好是默认值）必须保持权威——切主题、切回退源都不能悄悄改写用户意志。该模式在 `custom_theme.rs` 的 `ThemeTypography`/`ThemeEffects` Option 字段上同构复用，是整套设置/主题优先级体系的地基。
4. **照抄：`persist_keys`/`apply_updates` 的读-改-写语义**（`lib.rs` 的 `persist_keys` / `apply_updates`、`persist_keybinds` / `apply_keybinds`）。语义三件套：已有键原地替换、缺失键追加、未知键/注释原样保留（用户手改与未来的新键不被设置页写盘清掉）；全量读-改-写由保存锁串行化。载体按全局决策换成 JSON 段级浅合并——slTerminal 现状 `src-tauri/src/settings.rs` 的 `merge_settings`/`save_settings_blocking` 已同构且更严（原子写 + .bak + 白名单 + 1MB 上限），裁定语义对齐 pebrel、机制保留 slTerminal 自有资产。
5. **照抄：语言注册表宏 `languages!`**（`nebula_settings/src/language.rs` 的 `languages!` / `LanguagePref` / `LanguageInfo` / `LanguagePref::from_locale`）。单行注册一种语言，`ALL`/`VALUES`/`LANGUAGES`/native name/component locale 全部由宏生成——选择器、语言枚举、运行时查找表同源零分叉；`from_locale` 的 locale 协商（POSIX 后缀剥离、zh 的 Hans/Hant 与 TW/HK/MO 区域判定、地区变体回退主语言）照抄。**裁剪**：语言集从 11 家裁到 `System`/`ZhCn`/`EnUs` 三家（已定），宏形态不变。
6. **照抄：`scrolling` 档位与归一**（`nebula_settings/src/scrolling.rs` 的 `SCROLLBACK_VALUES` / `DEFAULT_SCROLLBACK_LINES` / `DEFAULT_SCROLL_SPEED` / `MIN_SCROLL_SPEED` / `MAX_SCROLL_SPEED` / `SCROLL_SPEED_STEP` / `normalize_scroll_speed` / `scrollback_lines`）。回滚行数七档白名单（档位外一律回默认，防手改出 1 行/一千万行）、滚速 0.25×–4× 步进 0.25、非有限值回默认 1.0——「档位约束 + 归一钳制」的模式同样适用于后续一切数值设置键。
7. **照抄：`reset` 的重置语义全家**（`nebula_settings/src/reset.rs` 的 `restore_default_settings` / `default_settings_text` / `RESET_KEYS`）。重置=删除全部已知键回到默认，未知键与用户数据（含 hook 授权类显式选择）保留；落盘前时间戳备份（`before-reset-<ts>-<pid>-<seq>.bak`）、tmp + rename 原子写、无效文件不覆盖直接报错；`reset_covers_every_runtime_settings_key` 用源文本反射解析 `from_raw` 读取的每个键断言都在 `RESET_KEYS` 里——防「加了新设置忘了加进重置清单」的结构性漂移，JSON 化后该反射测试以等价形态保留（键集合从 JSON 段 schema 提取对账）。
8. **照抄：`AgentHook` 每 CLI hook 偏好模型**（`nebula_settings/src/agent_hooks.rs` 的 `AgentHook` / `AgentHook::enabled` / `all_updates` / `setup_updates`）。每 agent 独立键 + 历史全局键兜底 + 默认仅两家开启 + 「显式安装/卸载写全部、恢复默认只写默认两家并保留用户对其余家的选择」的安装器合同。与分片 03 的安装器交界：该偏好段是新设置模型的内置段，安装器读它做接入/卸载决策。`settings_key` 按 `slterm_*` 命名空间改名。
9. **照抄：`Ligatures` 三态与主题优先、`CursorMotion` 显式 opt-in**（`nebula_settings/src/ligatures.rs` 的 `Ligatures` / `Ligatures::enabled`、`nebula_settings/src/cursor_motion.rs` 的 `CursorMotion`）。On/Off/Theme 三态——Theme 档把决定权交给主题声明（`enabled(theme)` 吃主题参数），默认值偏安全侧（连字默认开、光标动效默认关）；无效值一律回默认不炸。仅暗色裁定后 `enabled` 的主题参数语义不变（跟随主题自身的 typography 声明，与亮暗无关）。
10. **照抄：`NotificationDuration` 时长档合同**（`nebula_settings/src/notifications.rs` 的 `NotificationDuration` / `NotificationDuration::timeout`）。默认/5/10/30/90/常驻六档；`Default` 档保留各调用方既有寿命、`timeout(None)` 的 None 语义=原本常驻——「Default 是不覆盖而非某个具体秒数」这一语义是通知系统的解耦点（分片 09 消费）。
11. **照抄：`parse_hex_rgb`/`format_hex_rgb` 颜色文本往返**（`lib.rs` 的 `parse_hex_rgb` / `format_hex_rgb` / `Rgb8` / `Rgba8`）。`#rgb`/`#rrggbb` 宽容解析、写盘统一六位小写、非 hex/长度错/含中文一律 None——设置文件与主题文档共享的颜色文本记号，测试锁定往返。
12. **参考：`AppIconPalette` 值表宏形态**（`nebula_settings/src/app_icon.rs` 的 `app_icons!` / `AppIconName` / `AppIconPalette`）。「宏生成枚举 + 每变体携带完整展示值表（中英名 + 三色板）」的形态可参考；二十五枚色板的产品功能不照抄（见不采纳点），宏形态吸收进其他值表类设置域。
13. **参考：`paths` 目录解析单点与环境覆盖优先**（`nebula_settings/src/paths.rs` 的 `settings_dir` / `settings_path` / `first_override`）。「环境变量覆盖 → 系统标准目录」的两级解析与 exe 无关、与多实例无关的单点形态可参考；slTerminal 现状已有同构资产（`app_dir.rs` 的 `app_data_dir`，便携 exe 同级 + `SLTERM_DATA_DIR` 覆盖），裁定保留 slTerminal 侧单点、pebrel 的双名覆盖（`PEBREL_CONFIG_DIR`/`NEBULA_CONFIG_DIR` 并读）不采纳。
14. **参考：`paths/migration.rs` 的防御性迁移机制**（`nebula_settings/src/paths/migration.rs` 的 `migrate_data_at` / `write_if_absent` / `publish_file` / `is_migration_artifact`）。锁文件 + 完成哨兵（幂等重入）、临时文件 + 「拒绝覆盖已存在目标」发布（并发写不互相踩）、迁移产物可识别清理——这套机制的整体对象（Nebula→Pebrel 目录搬迁）不采纳，但同样的防御性形态是 slTerminal 自身 settings.json 旧八键 → 新设置模型段迁移的参照样板（见优化方向）。
15. **参考：`ThemeName::card_geometry` 的「主题自带几何」机制**（`lib.rs` 的 `ThemeCardGeometry` / `ThemeName::card_geometry`、`lib.rs` 顶部 `DEFAULT_PANE_CARD_RADIUS` 常量族）。卡半径/卡缝/投影/分界竖线四键一组跟主题走、用户 `Option` 覆盖优先（采纳点 3 同模式）、单一真源常量（旧壳/新壳曾各写一份字面量导致白边事故的注释教训一并迁移）。GPUI 世界的 pane 卡几何落位随 workspace chrome 分片，本分片只保留值模型槽与「跟主题走 + 显式覆盖」的优先级机制。

### 主题系统

16. **照抄：`TermTheme`/`ExactTermColors` 终端色表影响模型**（`lib.rs` 的 `TermTheme` / `ExactTermColors` / `ThemeName::term_theme`）。「一个主题对终端色表的全部影响」聚合为 background + `Option<ExactTermColors>`（前景/ANSI-16/光标/光标文字/光标描边/选中前景/选中背景）——`None` 字段=主题未声明、调用方保留用户配置或宿主默认的显式缺省语义照抄；`ExactTermColors` 整表声明的主题（Nord）与只声明背景的主题两种形态并存。仅暗色裁定：`is_light` 字段与浅色替换消费方不进入 slterm 模型。
17. **照抄：`ReviewedPalette` UI 语义槽位**（`nebula_settings/src/themes.rs` 的 `ReviewedPalette` / `ThemeName::reviewed_palette` / `ReviewedPalette::code_background` / `FreshPalette`）。shell/background/foreground/muted/accent + selected/line（带 alpha）+ red/green/yellow/blue/purple/cyan 语义六色 + frame 的固定槽位集——「终端色表」与「UI chrome 色」两套数据分离、各自单源；`code_background` 的 alpha 合成（selected 前景色按 alpha 叠到 pane 底）照抄。这是 GPUI 世界主题 token 的重建基础（对照 slTerminal 现状 `schemes/types.ts` 的 `UiTokens` 分组——gitFile/gitGutter/explorer/sidebar 等区域组 + 标量段，槽位组织粒度实现期融合，纪律一致：语义槽单点、消费只引用槽）。
18. **照抄：内置主题目录机制**（`themes.rs` 的 `ThemeName::BUILTIN` / `BUILTIN_NAMES` / `ThemeName::available`、`lib.rs` 的 `ThemeName::from_prompt_name` / `ThemeName::prompt_name`）。可选清单常量化、退休标识仍可解析但映射到继任主题（老用户配置不炸、选择器不出现）、持久化名与展示名分离且兼容读取多别名——「目录即合同」的多配色方案机制照抄，内置主题集合本身与 slTerminal 现状方案（`src/theme/schemes/linear.ts`）对齐实现期定，注册表形态替代 hand-rolled 枚举。
19. **照抄：`custom_theme.rs` 用户主题值模型全家**（`nebula_settings/src/custom_theme.rs` 的 `ThemeDefinition` / `ThemeAppearance` / `TerminalThemeColors` / `IndexedPalette` / `ThemeUiColors` / `ThemeTypography` / `ThemeLayout` / `ThemeEffects` / `ThemeValidationError` / `ThemeDefinition::from_builtin` / `derived_ui` / `resolved_ui` / `with_*` 编辑族）。承重设计逐一保留：值模型零序列化零文件格式（文件格式归应用侧适配器，crate 是无依赖权威——`custom_theme.rs` 模块头注释的分层原则照抄）；`IndexedPalette` 完整 256 色表（前 16=ANSI 镜像，色立方/灰阶按 xterm 常量生成，测试锁定）；`ThemeUiColors::from_terminal` 的 derive 派生规则（UI 锚点从已解析终端值推导、终端前景背景逐字不动、唯一共享规则不许多适配器各自实现背景混合）；`Option` 字段=未覆盖（None 保留用户全局设置）；`with_*` 不可变编辑返回副本；`validate` 全标量范围校验（名称/字体/字号/行高/字距/字重/布局/透明度各有专属错误变体）。仅暗色裁定：`ThemeAppearance` 枚举不进 slterm 模型，`from_terminal` 的双权重混合简化为暗色单权重。
20. **照抄：WCAG 对比度校验全家**（`custom_theme.rs` 的 `wcag_contrast_ratio` / `meets_wcag_aa` / `foreground_recommendations` / `readable_tint` / `relative_luminance` / `mix_rgb` / `blend_rgb`）。相对亮度按 WCAG 2 公式（sRGB 线性化 + 0.2126/0.7152/0.0722 加权）、AA 普通文本 4.5:1 阈值、`foreground_recommendations` 给出原色+冷/暖两个可读候选（原色永远排第一——用户颜色绝不静默改写，候选只供建议）、候选不达标时向白/黑较优端点逐步混合直至达标。主题编辑器的保存/推荐路径消费（见采纳点 26），测试锁定多背景下的推荐达标。
21. **照抄：`theme_library` 分层**（`nebula_app/src/theme_library/mod.rs` 的模块边界、`document.rs` 的 `ThemeDocument` / `SCHEMA_VERSION` / `MAX_DOCUMENT_BYTES`、`formats.rs` / `store.rs` / `preferences.rs`）。应用侧文件格式与设置 crate 值模型的分层照抄：版本化 JSON 信封（schema 版本字段、未知字段留在值树供未来 schema 演进、256KB 上限）；导入/导出适配器有界（输入字节上限、候选数上限、诊断不静默丢）；持久化 store 带 `RevisionPrecondition` 乐观并发（保存携带修订号、不匹配拒绝——外部编辑过就不覆盖）；`builtin_document`/`seed_document` 种子形态。「设置层管值、应用层管格式」的单方向依赖照抄。
22. **照抄：主题包 ZIP 机制**（`theme_library/package/` 的 `Manifest` / `Author` / `CheckedPackage` / `export_package`、`nebula_app/tests/theme_package_cli.rs`）。带版本化 manifest 的主题包导出/导入、整包有界检查（不解可信以外的字段）——主题分享载体照抄，分发渠道不做。

### GUI 设置界面

23. **照抄：`settings_pane` 整体形态**（`nebula_app/src/gpui_shell/settings_pane.rs` 的 `SettingsPane` / `try_persist` / `try_persist_checked` / 行渲染族）。左导航 + 右表单的设置页形态、`row(标签, 描述, 控件)` 统一节奏、控件宽度/行高/分组间距常量族、写盘失败 toast + 回滚控件到已存值的「保存失败可感知」合同、值域与写盘形态经枚举族单点往返（采纳点 2）——「设置页只负责摆控件、改动经统一持久化入口、保存失败必须让用户看见」三纪律照抄，JSON 化后 `try_persist` 落点换成新 JSON 写通道、布尔直接落 JSON 真布尔。
24. **照抄：`navigation.rs` 路由与搜索关键词索引**（`settings_pane/navigation.rs` 的 `SECTION_IDS` / `SECTION_SEARCH_TERMS` / `NAV_GROUPS` / `visible_nav_sections`、`settings_pane/search_header.rs`）。**搜索是路由查找不是页面过滤**——每个设置节挂一个中英混合别名串（「font 字体」「更新」「回滚 滚动」），查询命中即跳到拥有该控件的节；路由 id 只追加不重用（隐藏节保留编号防路由漂移）、视觉分组与路由编号分离、`HIDDEN_NAV_SECTIONS` 可隐藏不删位。中英文关键词索引机制原样照抄——这是「找得到设置」的产品能力，与语言数量无关（只留两语后别名串相应收缩，机制不变）。

### i18n

31. **照抄：`build/i18n.rs` 静态生成器全家**（`nebula_app/build/i18n.rs` 的 `generate` / `message_variant` / `catalog::parse` / `catalog::placeholders`、`build.rs` 的 `i18n::generate`、`build/i18n/catalog.rs`）。build.rs 编译期从 JSON 目录生成 Rust 源码的整套机制照抄：JSON 目录由语言注册表（采纳点 5）驱动遍历；**en-US 与 zh-CN 键集完全相同且非空是构建期硬合同**（不等即 panic）；每语言键集不得超出英文（未知 id 报错）；命名占位符集合跨语言一致校验；message id 合法性 + 变体名碰撞检测；重复 id/空串/非字符串/嵌套与点号冲突全拒绝；相同英文文案的 `source_id` 反查只在所有语言同义时生成（歧义短语不借翻译）；**部分目录构建期回退英文**（缺失键直接填英文值，运行时不做回退逻辑）；`MESSAGES` 静态二维表给全部构建 profile 一份进程级静态分配。运行时零解析、零文件读、零锁——`docs/internationalization.md` 的 Runtime contract 逐条照抄。
32. **照抄：`i18n/mod.rs` 查询 API**（`nebula_app/src/i18n/mod.rs` 的 `UiLanguage` / `LanguagePreference` / `Message` / `UiLanguage::text` / `tr` / `pick` / `format` / `tr_args` / `for_locale`）。`text(Message::...)` 类型化 ID + 表索引直接取 `&'static str`（新代码唯一入口，缺 ID 编译失败）；`tr("stable.id")` 字符串键兼容层（目标语言→英文→原键三级回退）；`pick(中文, 英文)` 旧双语硬编码迁移桥（中英即时分支、歧义英文短语不反查）；`LanguagePreference::resolved` 显式语言缺失时经系统 locale 解析、解析不出回英文。裁剪到两语后 `pick` 立即分支与 `tr`/`text` 三层全部保留——机制不因语言数收缩而简化。
33. **照抄：`format.rs` 命名占位符替换**（`nebula_app/src/i18n/format.rs` 的 `substitute`）。参数值字面插入绝不二次解析为占位符（防注入式串扰）、缺失参数原样可见（不静默吞）、`{{`/`}}` 转义、未成对花括号原样保留、预分配容量——格式化是唯一允许创建 String 的翻译路径（无参查询零分配合同不被冷路径破坏），测试锁定注入防护。
34. **照抄：i18n 合同测试 + 独立合同 workspace**（`nebula_app/tests/i18n_contract.rs` 的 `first_and_repeated_translation_lookups_allocate_nothing` / `translation_lookup_fits_a_small_stack` / `embedded_translations_stay_within_the_initial_payload_budget`、`tools/i18n-contract/` 的独立 crate + build.rs）。`#[global_allocator]` 计数器断言首次与重复查词全语言零分配（零分配合同有机器验证，不靠注释自律）；64KB 小栈子进程跑查词（静态表物化在调用方栈上的回归隔离）；翻译文本 payload 预算上限 + 消息条数下限；生成器与查找核心经 `#[path]` 复编进零渲染依赖的独立 workspace——合同可脱离应用壳运行。全部照抄，payload 预算值实现期按两语实际重定。
35. **照抄：`platform/locale.rs` 系统 locale 探测**（`nebula_app/src/platform/locale.rs` 的 `system_locale` / `native_locale`）。Windows `GetUserDefaultLocaleName` 一手取用户界面语言 + POSIX 环境变量（`LC_ALL`/`LC_MESSAGES`/`LANG`）回退——探测与文本渲染解耦（探测结果进应用状态，渲染只认解析后的 `UiLanguage`）。macOS 分支随多平台砍（见不采纳点）。
36. **照抄：`docs/internationalization.md` 的文案规则**（该文档 Runtime contract / Add a language / Checks 各节）。typed ID 新代码纪律（缺 ID 编译期失败）、`tr`/`pick` 是渐进迁移入口而非继续堆双语硬编码的理由、格式化独立路径、组件库 locale 与自有文案覆盖分开记录不假装全量、payload 预算纪律、母语审校要求——规则集照抄，语言集改为 en-US + zh-CN（「Add a language」退化为「改键」操作，注册表一行 + 两语 JSON 同步的合同流程不变）。

## 不采纳点

1. **`nebula_settings.txt` key=value 文本格式与行级协议整族**（`lib.rs` 的 `RawSettings` / `RawSettings::from_text` / `value` / `f32` / `bool_on`、`persist_keys` 的行序保留原地替换、`keybind_pairs` / `keybind_pairs_from_text` / `persist_keybinds` / `apply_keybinds` 的 `keybind=combo:Action` 多行协议）。理由：全局决策已定 JSON 化——JSON 自带键唯一与类型，宽容布尔八拼写（`1/true/yes/on`）与行序保留都是文本格式的补偿机制，JSON 世界无对象；键位绑定改归 JSON 段内数组（结构归分片 07，本分片只登记格式裁定）。「未知键保留、读-改-写」语义由采纳点 4 继承，不算损失。
2. **`quick_terminal.rs` 整支**（`nebula_settings/src/quick_terminal.rs` 的 `QuickTerminalMode` / `QuickTerminalSize` 及设置模型/`settings_pane` 对应页）。理由：已定不采纳 Quick terminal。
3. **多平台路径与 locale 分支**（`paths.rs` 的 macOS/Linux `default_dir` 分支、`platform/locale.rs` 的 macOS CoreFoundation 分支、全 crate 的 `#[cfg(unix)]` 权限保留）。理由：Windows-only 定位；迁移机制里的 unix hard_link 发布同理，只留 Windows `MoveFileExW` 形态。
4. **Nebula→Pebrel 目录迁移本体**（`paths.rs` 的 `migrate_legacy_data`、`migration.rs` 的 `DATA_FILES` 十四文件改名映射、`canonical_data_file_name` / `legacy_data_file_name`、`.pebrel-migration.lock`/`.pebrel-migration-v1` 哨兵对、`PEBREL_CONFIG_DIR`/`NEBULA_CONFIG_DIR` 双名覆盖）。理由：slTerminal 全新 fork 无 nebula 历史用户可迁；防御性机制已按采纳点 14 登记为参考（服务对象换成 slTerminal 自身旧 settings.json）。改名映射 `nebula_*` → `slterm_*` 只影响新命名空间，不涉及兼容读取。
5. **亮主题全套**（`custom_theme.rs` 的 `ThemeAppearance::Light`、`lib.rs` 的 `LIGHT_FOREGROUND` / `LIGHT_ANSI` 浅色替换表与「浅色主题替换前景/ANSI-16」消费语义、`RuntimeSettings.follow_system_theme`、`TermTheme.is_light` 的亮暗分支、`themes.rs` 亮色 `ReviewedPalette` 成员、`ThemeUiColors::from_terminal` 亮暗双权重混合）。理由：仅暗色定位——没有亮主题就没有替换对象，跟随系统外观无可跟随；主题模型只带暗色语义，`is_light`/appearance 字段不进入 slterm 模型。机制若未来重启（产品定位修订）再从 git 历史取回。
6. **`BlurModeName` 五档材质与旧用户迁移包袱**（`lib.rs` 的 `BlurModeName` 五档、`from_settings` 里旧布尔 `blur=1` → Mica 的迁移分支、缺省 Mica vs Acrylic 的既有用户兼容注释）。理由：窗口背景材质是窗口域产品特性，slTerminal 未立该需求（存留随 workspace/window 分片裁定）；「旧壳布尔值迁移到新枚举」的包袱无旧用户可背。其按 DWM 每帧成本排序、默认档必须性能安全的注释纪律作为模式参考保留（任何未来成本分级枚举照此建模）。
7. **SSH 代理设置域与 VCS 的 SVN 档**（`lib.rs` 的 `ssh_proxy_mode` / `ssh_proxy_url` / `ssh_proxy_no_proxy`、`VcsDisplayName::Svn`）。理由：SSH 整支不采纳；slTerminal VCS 面 git-only，SVN 档无对象。
8. **`TermTheme.powerline` 提示符八槽位**。理由：slTerminal 无 powerline 提示符特性，八槽段色模型无消费方；「主题声明扩展槽位供宿主消费」的模式本身已由采纳点 16/19 覆盖。
9. **mobile/relay、backup 云备份、providers 供应商设置页**（`settings_pane/mobile/`、`settings_pane/backup/`、`settings_pane/providers/`、`mobile.rs` / `backup.rs` / `providers.rs`）。理由：mobile 随多平台砍；云备份（webdav/s3/sftp 远端）与 AI 供应商 API 配置非本分片范围——供应商/providers 归分片 08（AI assistant），云备份 slTerminal 侧无对应产品决策，登记不采纳；设置导航节集合相应收缩。
10. **i18n 其余九语目录与注册**（`nebula_app/i18n/` 下 zh-TW/fr-FR/de-DE/es-ES/pt-BR/it-IT/ru-RU/ja-JP/ko-KR、`language.rs` 注册表对应九行）。理由：已定只留 en-US + zh-CN；部分目录构建期回退机制保留（采纳点 31），但当前两语均走完整键集硬合同，无部分目录。
11. **`nebula.toml` 配置层级**。理由：全局决策砍 Lua 栈后设置单源化——pebrel 的「`nebula_settings.txt` 权威高于 `nebula.toml`」双层优先级（`lib.rs` 模块头注释、`RuntimeSettings` 的 font fallback 语义）失去存在基础；slTerminal 世界 JSON settings 是唯一权威，无 toml 回退层。
12. **slTerminal 现状将被替代的自研件**——`hooks/signal.rs` 信号文件载荷形态（管道直连替代，分片 03 已裁）与 `app_icon.rs` 式 25 色板产品功能（slTerminal 无任务栏/exe 换图标需求）。理由：被替代项与无对象特性；对应机制性资产已按采纳点 12/37 登记参考。

## 优化方向

- **设置模型单源重建**：pebrel `nebula_settings` 平移为 `slterm_settings` 模块（GPUI 单进程内嵌，不再独立 crate 亦可，边界纪律不变——值模型/验证/语言注册/持久化合同在内，UI 控件与编排在外），`RuntimeSettings` 权威大结构 + 键域枚举族 + 宽容解析 + 「显式值权威」三元模式全部落地 JSON 段；slTerminal 现有 settings.rs 原子写/.bak/保存锁/损坏三态/1MB 上限作为写通道底座保留，顶层键白名单从字面量数组进化为「设置注册表驱动」（新键注册即入白名单与重置清单，`reset_covers_every_runtime_settings_key` 的反射对账思想以 JSON schema 等价形态守住）。`nebula_*` 键名全部 `slterm_*`，权威文件名与位置沿用 slTerminal 便携目录单点。
