## 2. 新发现问题

### P2：`terminalTabConfig` 死代码残留
- **位置**：`src/panelRegistry.ts:73`
- **说明**：`terminalTabConfig` 仅被 `src/__tests__/panel-registry.test.ts` 使用，生产代码与 e2e 均无消费，`knip.out:132` 将其标为未使用导出。FE-35 未按约定删除或改为测试专用注释。
- **建议**：删除该常量并同步移除/改写 `panel-registry.test.ts` 中的相关断言；若保留，应显式标注“测试专用”并加入 `knip.json` entry 以避免误报。

### P2：`src/ipc/CLAUDE.md` 仍记录已删除的 `setFocus`
- **位置**：`src/ipc/CLAUDE.md`（window.ts 段落）
- **说明**：文档仍将 `setFocus` 列为 `window.ts` 的 wrapper 之一，但 S14 已删除 `src/ipc/window.ts` 中的 `setFocus`，造成文档与代码不一致。
- **建议**：同步删除文档中 `setFocus` 相关描述。

### P2：面板级 ErrorBoundary 无恢复/重置机制
- **位置**：`src/panelRegistry.ts:32-48` / `src/lib/ErrorBoundary.tsx`
- **说明**：`withPanelBoundary` 单点包裹正确，但 `ErrorBoundary` 未在面板参数变化或用户操作时重置 `error` 状态。Dockview 多实例 + CSS 显隐方案下面板实例跨页面存活，一次渲染错误会导致该面板永久显示占位，直至页面或面板被关闭。
- **建议**：为 inline fallback 增加“重试”按钮，点击后 `setState({ error: null })`，使用户可在不关闭面板的情况下尝试恢复。

### P2：关闭序列中 `ptyKillAll` 未加总超时
- **位置**：`src/App.tsx:156-163`
- **说明**：前端 `TerminalRegistry` kill 已用 `Promise.race(..., SHUTDOWN_TIMEOUT_MS)` 兜底，但随后的 `pty.ptyKillAll()` 直接 `await`，未再包超时。`pty_kill_all` 内部逐 session 串行 kill+join（3s/个），极端多 session 场景下可能显著拖长关窗时间。
- **建议**：将 `ptyKillAll()` 同样包进 `Promise.race([pty.ptyKillAll()], SHUTDOWN_TIMEOUT_MS)`，与 BE-06 超时语义一致。

### P2：`waitFor` 轮询的 `setTimeout` 在 abort 后仍会触发一次
- **位置**：`src/workspace/pageApis.ts:91-96`、`src/features/agentHistory/restoreSession.ts:48`
- **说明**：abort 后下一轮 `signal.aborted` 检查才退出循环，当前 tick 的 `setTimeout` 不会被取消，会在 abort 后继续产生一次 100ms 的微任务。虽不造成逻辑错误，但增加了不必要的延迟。
- **建议**：在 `waitFor` 内部监听 `signal` 的 `abort` 事件以 `clearTimeout` 当前 tick 的定时器。
