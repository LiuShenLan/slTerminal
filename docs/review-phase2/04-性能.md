## 2. 新发现问题

### P1 — FE-01 `MAX_PAGES` 实现为「每项目上限」，与 D1「页面总数上限」契约不符

- **位置**：`src/stores/projects.ts:107-115`
- **说明**：D1 决策与 S12 契约均要求「页面总数上限 `MAX_PAGES = 20`」以限制多 Dockview 实例导致的内存/DOM 线性增长。当前实现仅判断 `project.pages.length >= MAX_PAGES`，即**每个项目**最多 20 页。当用户创建多个项目时，全局页面总数仍可无限增长，D1 的防无界增长目标未完全达成。
- **修改建议**：在 `addPage` 中增加全局页面总数校验（例如 `Object.values(get().projects).flatMap(p => p.pages).length >= MAX_PAGES`），超限同样拒绝 + toast「页面数已达上限」；同步更新 L2 测试与 ADR 登记。

### P2 — FE-16 `projectIdForCwd` 由「首命中」改为「最深前缀」，嵌套项目行为变化

- **位置**：`src/features/navTree/useNavTree.ts:139-170`
- **说明**：原实现为遍历全部项目做前缀匹配，返回 `Object.values` 首命中项目。新实现先建 `rootPathIndex`，再逐级上溯返回**最深前缀**项目。若存在嵌套项目（子目录项目后创建），旧实现可能返回父项目，新实现恒返回子项目。虽然注释称「更精确」，但改变了历史会话归属语义，且未在 `nav-tree-history.test.tsx` 等测试中显式覆盖嵌套场景。
- **修改建议**：确认产品是否接受嵌套项目归子项；如接受，补 L2 测试固化该语义；如要求保持原首命中语义，将 `projectIdForCwd` 改为按 `projects` 原始遍历顺序查 `rootPathIndex`。

### P2 — FE-30 虚拟化后选中项滚出视口无自动滚动跟随

- **位置**：`src/features/explorer/FileTree.tsx:596-751`
- **说明**：虚拟化后仅渲染可见切片。当前 FileTree 无方向键导航，选中依赖鼠标点击，点击自然落在可见区；但若未来通过 `explorer.open` 命令或程序式设置 `selectedPath` 使选中项位于窗口外，组件不会自动滚动到选中项。这是虚拟化常见缺口，当前虽未触发回归，但行为不等价于「非虚拟化列表始终渲染全部行」。
- **修改建议**：在 `FileTree` 中添加 `useLayoutEffect`，当 `selectedPath` 变化且对应行不在 `[start, end]` 窗口时，通过 `scrollRef.current.scrollTop` 滚动使其可见；并补 L2 测试。

### P2 — `useFileTree` `refreshSubtreeAt` 未处理目标目录本身被删除的场景

- **位置**：`src/features/explorer/useFileTree.ts:224-298`
- **说明**：`refreshSubtreeAt` 定位到「变更路径的最近展开祖先」后调用 `loadDirectory(targetPath)`。如果 `targetPath` 本身已被删除，`loadDirectory` catch 返回 `[]`，随后 `mergeLayer` 会用空子节点替换该目录。但 `targetPath` 作为目录行仍保留在父层，视觉上成为一个空目录行，而非消失。需要下一次 `refreshExpanded` 或 fs-event 才会被清理。
- **修改建议**：在 `refreshSubtreeAt` 返回 `true` 后，若 `loadDirectory` 因「路径不存在」返回 `[]`，可额外检查父层并移除该目录行；或文档化接受该延迟清理行为。

### P1 — `projects.ts` `switchToPage` 直接调用 IPC，违反硬约束 #12

- **位置**：`src/stores/projects.ts:159-186`
- **说明**：约束 #12 规定「store 只存状态不存业务逻辑，持久化一律经 `src/ipc/` 对应领域函数，禁止在 store 内直接调用 `invoke`」。`switchToPage` 作为 store action 直接调用 `setProjectRoot(project.rootPath)`，属于在 store 内发起 IPC 副作用。
- **修改建议**：将 `setProjectRoot` 调用上提到调用方（`NavTree`/`Workspace`/`pageApis`），store 仅更新 `activePageId`；或作为历史遗留债务单独登记豁免并规划迁移。
