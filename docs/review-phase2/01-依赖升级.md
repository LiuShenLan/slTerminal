## 2. 新发现问题

### P0

1. **knip `--production` 未达「零误报」，CI 新门禁将直接失败**
   - 位置：`.github/workflows/ci.yml:45-46`、`knip.json`
   - 说明：`npx knip --production` 退出码 1，报告 `Unused files (38)`、`Unused exports (146)`。项目采用大量注册表/副作用导入/动态分派（panelRegistry、CliProfileRegistry、ShortcutRegistry、FileViewerRegistry、sideViewRegistry 等），knip 默认分析会把这些注册入口、类型再导出、测试工厂辅助文件判定为未使用。
   - 修改建议：
     - 方案 A（推荐）：在 `knip.json` 中补充 `ignoreExports`、`ignoreFiles`、`ignoreDependencies` 规则，或添加 `entry` 覆盖所有副作用导入入口（如 `src/panelRegistry.ts`、`src/features/**/*Registry.ts`、`src/main.tsx` 等），再跑 `npx knip --production` 直到退出码 0。
     - 方案 B：CI 中改为 `npx knip --production --dependencies`（仅检查未使用/未声明依赖），与 TE-12 原始目标（消除 @wdio 误报）一致，但需同步修正 stages.md/checklist 中「零误报」表述。

### P1

2. **TypeScript 7 依赖声明不真实，主 `typescript` 字段仍指向 TypeScript 6 包装器**
   - 位置：`package.json:80`、`package.json:59`
   - 说明：`package.json` 将主 `typescript` 声明为 `npm:@typescript/typescript6@^6.0.2`，导致 `require('typescript')` 得到 TS6 兼容包装器；`npx tsc` 之所以能显示 `7.0.2`，是因为 `@typescript/native` 别名恰好也暴露了 `tsc` bin，两个包在 `node_modules/.bin` 竞争。该设计使依赖声明与运行时核心工具版本不一致，且 `typescript-eslint@8.61.1` 的 parser/type-utils 实际解析到 `@typescript/old`（TS6），与 TS7 编译器 AST/语义存在漂移风险。
   - 修改建议：
     - 若必须上 TS7：将主 `typescript` 直接改为 `^7.0.2`，并同步将 `typescript-eslint` 升级到支持 TS7 的版本（或临时用 `overrides`/`resolutions` 统一 TS7）。
     - 若 `typescript-eslint 8.x` 尚未稳定支持 TS7，应回退到「主 `typescript` 用 6.x，暂缓 TE-07」，或明确在 ADR 中登记「双 TS 并存」为临时工程债务并给出升级触发条件。

3. **`@tauri-apps/plugin-dialog` npm 版本落后于 cargo 与 wanted**
   - 位置：`package.json:39`、`src-tauri/Cargo.toml:23`
   - 说明：review 06 要求 plugin-dialog 升级到 wanted 2.7.2；当前 npm 仍锁 `2.7.1`，而 cargo 侧因 Tauri 2.11.5 已升级到 `tauri-plugin-dialog v2.7.2`。Tauri 插件 npm/cargo 版本通常应保持一致，minor 不一致可能导致 JS API 与 Rust 命令签名偏差。
   - 修改建议：将 `package.json` 中 `@tauri-apps/plugin-dialog` 改为 `2.7.2`，刷新 `package-lock.json`，并补 L2/E2E 覆盖 dialog 调用路径的回归断言。

### P2

4. **WDIO 工具链存在同一包多版本实例**
   - 位置：`package-lock.json`
   - 说明：`npm ls` 显示 `@wdio/globals` 同时存在 `9.31.0`（直接依赖）与 `9.29.1`（由 cli/local-runner/service 传递）；`expect-webdriverio` 同时存在 `6.0.5`（直接）与 `5.7.0`（传递）；`webdriverio` 同时存在 `9.30.1` 与 `9.30.0`。虽 E2E 9/9 通过，但多实例可能在未来导致类型不匹配或行为不一致。
   - 修改建议：调整 `package.json` 中 `@wdio/globals`/`expect-webdriverio` 版本，使其与 `@wdio/cli` 等传递约束对齐；必要时用 `overrides` 统一 `@wdio/*` 与 `expect-webdriverio`、`webdriverio` 单版本。

5. **`json-schema-library` 仍同时存在 9.x 与 11.x 两个 major**
   - 位置：`package-lock.json`、`package.json:50`
   - 说明：`codemirror-json-schema@0.8.1` 深度绑定 `json-schema-library@9.3.5`，导致即使直接依赖升到 11.6.2，依赖树仍保留 9.3.5 副本。项目已在 `src/features/hooksConfig/CLAUDE.md` 与 `schema/index.ts` 注释中登记去重评估结论，属于已知债务。
   - 修改建议：跟踪 `codemirror-json-schema` 上游是否发布支持 json-schema-library 11.x 的新版本；或评估替换为 `@cfworker/json-schema`/`ajv` 等单一库方案，减少维护面。
