# 06 — 新增 CLI 接入清单（Onboarding Checklist）

> 总规格：`docs/spec/multi-cli/00-需求规格.md`（决策 D2/D12，验收 AC-4）。本清单是「新增一个编码 CLI 专门支持」的完整改动面索引——目标：身份识别类接入收敛到「一个 profile 文件 + 一行注册 + 图标资源」；带 hooks/历史能力的接入另加「一个后端 provider + reporter 资产」。
>
> **本清单的正确性由 mock profile 全链路测试实证**（AC-4）：测试夹具按本清单走一遍，全绿即证明清单完备。

## 1. 接入形态总览

| 接入级别 | 改动面 | 获得能力 |
|----------|--------|---------|
| **A. 仅身份识别** | 前端 profile 文件 + 注册 + 图标 | OSC 133 命中 → 页签标题/🟡/logo + agentSession 会话行（双态：🟡 运行中/无图标，用量 `--`） |
| **B. A + hooks 能力** | + 后端 CliHooksProvider + reporter 脚本资产 + 前端 hooks 策略 | 四态页签 emoji + 会话行四态/用量条 + F4 通知 + hooks 注入/卸载/状态 + 配置编辑（可选 hasConfigEditor） |
| **C. A + 历史能力** | + 后端 CliHistoryProvider + 前端 history 策略 | 历史区聚合条目 + 恢复/删除/复制命令/分支恢复 |
| **D. B + C 全能力** | 两者叠加 | 同 claude 现状 |

| # | 步骤 | 落点 | 说明 |

## 3. 清单 — B 级（hooks 能力）

前置：完成 A 级。

| # | 步骤 | 落点 | 说明 |
|---|------|------|------|
| B1 | hooks 策略（前端） | profile 的 `capabilities.hooks`：eventToStatus/classifyNotification/contextLimit/restartHint/hasConfigEditor | eventToStatus 把该 CLI 事件映射进四态；无对应概念的事件映射 null |
| B2 | 后端 provider | `src-tauri/src/hooks/<id>/`：实现 CliHooksProvider 六方法（inject/uninstall/injection_status/context_usage/config_read/config_write） | 照 claude provider（`hooks/claude/`）先例；静态注册表以 cliId 注册 |

| B4 | 注入实现 | 该 CLI 的 hooks 配置写入路径与 merge 策略（claude 先例：`~/.claude/settings.json` 10 事件 matcher 追加 + 版本检测） | 完全 CLI 专属，provider 内部自由实现；原子写 + 非法 JSON 中止为推荐契约 |
| B5 | L1 测试 | `hooks/<id>/` 内 `#[cfg(test)]` | provider 注册/六命令 cliId 透传/注入幂等/reporter 模板内嵌校验（含 SLTERM_PANEL_ID/版本号）；`--test-threads=1` |

| B7 | L4 测试（可选但推荐） | `hooks.e2e.ts` 追加该 CLI 的注入/信号文件链路用例 | E2E-05 用户目录隔离备份集合须追加该 CLI 的配置路径（`run-wdio.cjs`） |

## 4. 清单 — C 级（历史能力）

前置：完成 A 级。

| # | 步骤 | 落点 | 说明 |
|---|------|------|------|
| C1 | history 策略（前端） | profile 的 `capabilities.history`：supportsFork/buildResumeCommand/buildRestoreInput | buildRestoreInput = pty.write 注入内容（含 `\r` 结尾，照 claude 先例）；supportsFork=false 则菜单不展示分支恢复 |

| C3 | 扫描根 env 覆盖 | `SLTERM_<ID>_PROJECTS_DIR`（照 SEC-02 模式，每次调用读 env 不缓存） | E2E fixture 隔离用；生产不设置 |

**C 级即可获得**：历史区聚合条目（行 logo 区分 CLI）+ 恢复/删除/复制恢复命令/分支恢复（supportsFork）。

## 5. 接入后自动获得（零改动项）

以下机制对任何已注册 CLI 自动生效，**无需任何接入动作**：

- **终端平台能力**（D4 全局常驻）：DA1 应答/合帧/resize 分离 debounce/OSC 52/OSC 8/Kitty 键盘/Ctrl+Enter/Ctrl+C 透传/COLORTERM 等 env 注入/flags 0x7。
- **SLTERM_PANEL_ID 路由键**（MC-110）：PTY spawn 恒注入，reporter 直接可用。
- **信号通道**（MC-203）：watcher 双通道 + `agent-event` 广播，新 CLI 的信号文件自动被消费。
- **聚合 UI 框架**：历史区三下拉框/cwd 分组/搜索/相对时间/操作矩阵/双击三分派/SessionActionDialog。
- **恢复编排四步框架**：项目入列/页面保障/页面切换/终端恢复——差异仅在 buildRestoreInput（C1）。
- **hub 面板选择行**：hasConfigEditor=true 即自动出现按钮（MC-502）。
- **logo 资源守卫**：注册即被遍历断言（MC-108）。

## 6. 接入纪律（红线）

1. **禁止在 profile 体系外新增 CLI 字面量**（MC-4）：通用层（lib/panels/terminal、features/agentStatus、features/agentHistory、features/notifications、ipc、types）不得出现该 CLI 的名字/事件名/路径；AC-5 grep 守卫覆盖。
2. **C10 同款契约**：reporter 任何路径 exit 0、不写 stderr——削弱即阻塞 claude 等宿主 CLI。
3. **SEC-05 等价**：delete 的 sessionId 校验 + 定位不信托前端，是新 provider 的强制实现项（MC-304）。
4. **watcher 轮询补漏勿削弱**（win10 实证防线）；`compute_conpty_flags` 锁 0x7 勿动（PASSTHROUGH_MODE 吞鼠标滚轮，无法自动化守卫）。
5. **测试纪律**：L1 `--test-threads=1`；`npm run build:e2e` 与 `npm run wdio` 串行；E2E 不得触碰用户真实 `~/.claude/` 等目录（env 覆盖 + fixture 隔离）。
6. **文档同步**：test-inventory 用例登记、模块 CLAUDE.md、CONTEXT.md（如新术语）。

## 7. mock profile（验收夹具约定）

AC-4 的 mock profile 是**测试夹具而非真实 CLI**，约定：

- id `"mockcli"`，commands `["mockcli"]`，iconSrc 指向测试用 PNG（`public/cli-icons/` 放最小合法 PNG 或测试目录资产经资源守卫豁免注释——二选一，建议放真实最小 PNG 保持守卫统一）。
- 含 hooks + history 全能力（策略为恒等映射/桩实现），hasConfigEditor=true + 桩编辑器组件。
- **仅在测试环境注册**（vitest 测试文件内 register + `_reset` 清理；L4 如需则经 E2E helper 注册，`E2E_ENABLED` 门控红线不变）。
- 验证点（AC-4 全表）：OSC 133 命中页签/logo/agentSession.cliId → eventToStatus/classifyNotification 被调用 → 历史聚合条目 + 恢复注入 → hub 面板选择行两枚按钮 + 切换 + 持久化。
