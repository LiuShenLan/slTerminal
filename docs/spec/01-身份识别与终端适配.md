> 总规格：`docs/spec/multi-cli/00-需求规格.md`（决策 D2/D3/D4）。现状基线：`docs/analysis/01-pty-terminal.md`、`docs/analysis/04-ui-status.md`（04-3~8）。

## 1. 域范围

## 3. 已知限制（规格确认，不修）

| 限制 | 说明 |
|------|------|
| npx/bunx 调用不识别 | `npx claude` 首 token 为 `npx`，无法归因；如需支持未来以「npx 第二 token」规则另立需求 |
| 路径限定调用不识别 | `~/bin/claude` / `./claude` 首 token 含路径分隔符，不匹配裸命令键 |
| cmd.exe 无 OSC 133 通道 | Enter hook 依赖 PSReadLine，仅 pwsh/powershell 注入（`panels/CLAUDE.md` 明示）；cmd.exe 下 CLI 识别不可用，页签/会话行不建 |
| 未注入 hooks 时无 sessionId | OSC 133 通道只能提供 matchedCommand，sessionId/transcriptPath/用量均不可用（现状语义保留） |

## 4. 边界条件

1. **同名命令冲突**：两个 profile 的 commands 含相同首 token（如第三方 CLI 也叫 `claude`）——注册表后注册覆盖先注册（照 register 同 id/同键覆盖语义），规格不引入冲突检测；profile 注册为代码内静态行为，冲突由 code review 拦截。
2. **命令行首 token 大小写**：保持现状精确匹配（Windows 命令行实际大小写敏感场景罕见），不引入 toLowerCase（避免 `Claude` 等误判）。
3. **空命令行/仅空白**：`matchByCommand("")` 返回 null（现状 `trim().split` 后空串查表不命中，行为保留）。
4. **未命中**：OSC 133 C 未命中任何 profile → 不置 isCommandRunningRef、不动页签/会话（现状 `rule == null` 分支保留）。
