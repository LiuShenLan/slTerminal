# L3+L4 E2E 测试 Review 报告

## 问题清单

### [高] L3 `production-osc.test.ts` 复制生产 OSC 处理实现，存在维护漂移风险
- **维度**: mock 合理性
- **证据**: `test/terminal/production-osc.test.ts:41-121`
- **证据类型**: 静态推断
- **问题**: 测试文件内重新实现了 `registerOsc52`、`registerOsc133`、链接处理逻辑，与生产文件 `src/panels/terminal/useClipboardHandler.ts`、`useCommandDetection.ts`、`useXterm.ts` 的代码重复，未复用生产实现。生产 OSC 处理修复或调整时 L3 测试不会自动跟随，可能出现生产行为已变、测试仍绿的假阴性，违背 bugfix 须附防复发测试的原则。
- **建议**: L3 直接加载生产 OSC handler 模块注册到 headless terminal，仅 mock 剪贴板/通知等副作用边界。

### [高] L3 `keyboard.test.ts` 不覆盖生产快捷键分发路径
- **维度**: 覆盖率
- **证据**: `test/terminal/keyboard.test.ts:35-37,72-317`
- **证据类型**: 静态推断
- **问题**: 文件显式标注相关分组为 xterm.js 基础行为回归，断言 `term.input(...)` → `onData` 的恒等透传，不经生产 `attachCustomKeyEventHandler` → `ShortcutRegistry` → `usePanelFocus` 链路。生产快捷键（`Ctrl+Shift+C` 复制、`Ctrl+Shift+V` 粘贴、Shift+Tab、Ctrl 组合键接管等）在 L3 无守卫；`ShortcutRegistry` 或终端焦点逻辑变更时 L3 无法捕获回归。
- **建议**: 将生产 `attachCustomKeyEventHandler` 挂到 headless terminal 上断言按键分发结果，或在文件头明示「仅 xterm 基础行为」并将生产快捷键覆盖归入 L2/L4 的明确责任。

### [高] L4 多处树展开使用固定 350ms sleep，脆弱且慢
- **维度**: 稳定性与确定性
- **证据**: `e2e-tests/agent.e2e.ts:88`、`e2e-tests/history.e2e.ts:101`、`e2e-tests/mockcli.e2e.ts:233`
- **证据类型**: 静态推断
- **问题**: 循环内无条件 `await new Promise((r) => setTimeout(r, 350))`，未等待任何 DOM/状态条件。机器负载或导航树异步展开延迟变化时易 flaky；每次循环至少等 350ms，累积拉低 L4 执行速度。
- **建议**: 改为条件等待（`waitUntil` 目标节点出现/aria-expanded 变化），超时上限兜底。

### [高] L4 `history.e2e.ts` 吞掉 `createProject` 失败
- **维度**: 断言有效性
- **证据**: `e2e-tests/history.e2e.ts:112-115`
- **证据类型**: 静态推断
- **问题**: `__slterm_e2e_createProject` 的结果经 `.catch(() => null)` 捕获并丢弃，且 `void proj` 忽略返回值。项目创建失败时测试不会立即失败，后续基于该项目的扫描/恢复/删除断言可能基于不存在的状态运行，产生误导性通过或难以定位的失败。
- **建议**: 断言创建结果非空再继续，失败时以创建错误信息直接 fail。

### [高] L4 `terminal.e2e.ts` 键盘快捷键断言未验证真实快捷键路径
- **维度**: 断言有效性
- **证据**: `e2e-tests/terminal.e2e.ts:111-130`
- **证据类型**: 静态推断
- **问题**: 发送 `browser.keys(["Control", "Shift", "v"])` 后，断言仅检查通过 `__e2e_writeToTerminal` 注入的 `e2e_paste_verify` 标记，未验证按键是否真正被终端/快捷键处理器消费。快捷键绑定失效、焦点不在终端、或 `attachCustomKeyEventHandler` 拦截逻辑变更时，测试仍可能通过，无法防御 `Ctrl+Shift+V` 粘贴路径回归。
- **建议**: 断言粘贴内容真实到达 PTY 回显或 xterm 缓冲区，而非仅断言注入标记。

### [中] L4 launcher 在 `process.on('exit')` 同步执行用户目录恢复
- **维度**: 基建
- **证据**: `e2e-tests/run-wdio.cjs`
- **证据类型**: 静态推断
- **问题**: 备份还原、目录清理放在 `process.on('exit')` 同步回调中执行。清理阶段阻塞或抛出异常时无法在退出流程中报告，可能静默污染用户 `~/.slterminal/settings.json`、projects JSON、hooks 目录等真实数据；跨运行残留。
- **建议**: 清理逻辑移到 `onComplete` hook 或显式 try/finally 主流程，exit 回调仅作兜底并打印恢复结果。

### [中] L4 launcher 尝试下载 msedgedriver 引入外部网络噪音
- **维度**: 稳定性与确定性
- **证据**: `e2e-tests/run-wdio.cjs`（实跑日志 `docs/test-review/e2e-baseline.log`、`docs/test-review/e2e-rerun.log` 可见下载尝试后回退）
- **证据类型**: 实证
- **问题**: 启动时先尝试下载 Edge driver，失败后回退 embedded driver。每次运行增加不可控外部依赖与延迟；无网络或 Edge 版本不匹配时可能失败，降低 L4 可重复性。
- **建议**: 默认直连 embedded driver，下载路径改为显式 opt-in。

### [中] L4 `beforeSuite` 仅重置 projects store，未隔离 settings 等其它持久化状态
- **维度**: 隔离性
- **证据**: `e2e-tests/wdio.conf.ts`（beforeSuite 段）
- **证据类型**: 静态推断
- **问题**: 每个 spec 开始前仅调用 `__slterm_e2e_resetProjects()`，未重置 settings、keybindings、sideBar、fontSize 等配置。跨 spec 的 settings 修改（如 L4 自身或上次异常残留）可能泄漏，导致后续 spec 在非标状态下运行。
- **建议**: beforeSuite 增加 settings/keybindings 等持久化状态的统一 reset，或每个 spec 声明所需状态快照。

### [低] L4 `retries: 1` 掩盖潜在 flakiness
- **维度**: 稳定性与确定性
- **证据**: `e2e-tests/wdio.conf.ts`（mocha retries 配置）
- **证据类型**: 静态推断
- **问题**: mocha 配置用例级重试一次。偶发失败被自动重试消除，本次 rerun 全绿不能证明上述 sleep/断言缺陷不会在未来触发。
- **建议**: CI 上以 retries=0 跑一轮作为 flakiness 观察面，或记录重试次数上报告警。

### [低] L3 不覆盖 Windows ConPTY / 真实后端
- **维度**: 覆盖率
- **证据**: `test/terminal/*.test.ts`
- **证据类型**: 静态推断
- **问题**: 全部 L3 用例运行在 node + `@xterm/headless` 环境，无后端 PTY、无 Windows ConPTY、无 shell 集成脚本。reader 微批、ConPTY flags、OSC 7/133 注入、DA1 模拟、SPAWN_LOCK、路径沙箱等生产关键路径不在 L3 覆盖范围内，相关回归需依赖 L1/L4。
- **建议**: 在 L3 层 CLAUDE.md / test-inventory 中明示该层职责边界，确认上述关键路径在 L1/L4 确有对应用例（缺口分析见 07 号报告）。
