# 阶段 2：通知 + 会话总览

> 阶段 1 信号文件通道的自然延伸：状态数据既已到达前端，向外（任务栏/toast）与向总览（侧栏视图）两个方向呈现。
> 标注约定：**【已确认】** = 用户问答拍板；**【推导默认】** = 已确认决策的直接推论，开发前可复核。

## F4 任务栏闪烁 + toast 通知

### 功能目标

用户切走窗口做别的事时，不错过 claude 的三类关键事件：需要授权、任务跑完、出错了。

### 调研依据

通知是社区第三大 hook 用例，6+ 独立通知工具（Desktop/ntfy/Slack/Discord/飞书/钉钉）验证需求（D5b §3.1 排名 3、D1 §3.1）；Tauri 生态有 `@tauri-apps/plugin-notification` 可发系统 toast（D1 §5.1）。

### 功能详述

**触发门控**：仅窗口失焦时触发【已确认 Q8】——窗口聚焦时不发 toast、不闪任务栏（用户正盯着，无需通知）。

**三类通知事件**【已确认 Q8】：

| 类别 | 信号来源 | toast 场景 |
|------|---------|-----------|
| 权限请求 | Notification(permission_prompt) / PermissionRequest | claude 卡住等授权，不来处理就一直停着 |
| 任务完成 | Stop | 切走窗口等长任务，完成即可回来看结果 |
| 错误 | StopFailure / PostToolUseFailure | API 错误或工具失败，需要人工介入 |

**任务栏闪烁**：任一页签进入注意态🟡（权限请求）期间，Windows 任务栏图标闪烁（flashFrame）；窗口聚焦或状态被覆盖后停止【推导默认】。

**toast 行为**：

- 内容：项目名 + 页签标题 + 事件类别 + 时间【推导默认】
- 点击 toast → 聚焦 slTerminal 窗口 + 切换到对应操作页面 + 聚焦对应页签【已确认 Q8】
- 多会话同时触发：各自独立 toast，由系统通知中心自然堆叠【推导默认——不做聚合】

### 边界条件

1. 窗口聚焦时零通知【已确认 Q8】
2. toast 点击必须精确落到**发起事件的那个页签**（经 SLTERM_PANEL_ID 路由），页签已关闭时仅聚焦窗口【推导默认】
3. 通知事件同样来自信号文件通道——未注入 hooks 的会话无通知【推导默认】
4. 任务栏闪烁仅跟随注意态🟡，完成✅/错误❌只发 toast 不持续闪烁【推导默认】

### 明确不做

- 不做逐事件通知开关（零配置）【已确认 Q8 选项语义】
- 不做声音提醒、自定义 toast 样式、通知历史中心
- 不做窗口聚焦时的任何通知变体（如标题栏横条）

### 验收要点

1. 窗口失焦 + claude 发起权限请求 → toast 出现 + 任务栏闪烁；点击 toast → 窗口聚焦并落到正确页签
2. 窗口失焦 + 长任务 Stop → toast 出现；窗口聚焦时不发
3. 窗口聚焦状态下三类事件 → 无任何通知
4. 事件页签已关闭时点 toast → 仅聚焦窗口，不报错

## F5 Agent Status 侧栏视图

### 功能目标

SideBarArea 新增视图，一屏总览**当前项目**所有运行中的 claude 会话：哪个在干活、哪个等我、上下文还剩多少，点击即跳转。

### 调研依据

多 tab 管理是 Claude Code 重度用户核心痛点（D1 §4.3）；claude-hud 证明上下文用量是最高频需求（D1 §5.4 MVP），其数据来源为 transcript JSONL 解析（原生 token 数据，非估算）。

### 功能详述

**视图注册**：`sideViewDefs.ts` 追加注册（两步流程：实现组件 + `sideViewRegistry.register`），id/title/icon【推导默认：id `agent-status`、title "Agent 状态"、icon 🤖】，默认归属上区按钮组【推导默认——与 projects/explorer/commit 同区】。

**显示范围**：当前活跃项目的所有运行中 claude 会话（跨该项目下的多个操作页面）【已确认 Q6】。

**每行内容**【已确认 Q6/Q7】：

| 元素 | 数据来源 |
|------|---------|
| 页签标题 | TerminalRegistry / titleManager |
| 四态图标 | F3 同一状态机（信号文件通道） |
| 上下文用量条（百分比 + 条形） | transcript JSONL 被动解析：`message.usage` 字段（claude-hud 模式，原生 token 数据）；JSONL 路径由信号文件 `transcriptPath` 定位 |

**交互**：点击行 → 切换到对应操作页面（如不在当前页面）+ 聚焦对应页签【已确认 Q6】。

**更新时机**：新信号事件到达时顺带更新该行的四态与上下文用量（事件驱动，不做定时轮询）【推导默认——与 claude-hud 的事件驱动更新一致，避免固定间隔读大文件】。

### 边界条件

1. 范围 = 当前项目；切换项目时视图内容跟随切换（旧项目会话行清空，加载新项目）【已确认 Q6 语义】
2. 空态：当前项目无运行中 claude 会话 → 显示"当前项目无运行中的 claude 会话"占位文案【推导默认】
3. 会话退出（SessionEnd / OSC 133 D）→ 该行**移除**（视图是"运行中会话"总览，非历史列表）【推导默认】
4. 行排序：按最近事件时间倒序（最活跃的在上）【推导默认】
5. 未注入 hooks 的 claude 会话：行存在（OSC 133 C 检测到启动），四态为🟡，上下文用量条显示为不可用态【推导默认——无 transcriptPath 无法解析 JSONL】
6. 上下文用量解析失败（JSONL 损坏/格式变更）→ 该行用量条降级为不可用态，不影响四态显示【推导默认】

### 明确不做

- 不做展开详情、工具活动流、代办进度【已确认 Q7】
- 不做全局（跨项目）会话列表【已确认 Q6】
- 不做会话历史记录、用量统计图表
- 不做定时轮询刷新【推导默认】

### 验收要点

1. 当前项目开 3 个 claude 页签（分属 2 个操作页面）→ 视图 3 行，四态各自正确，点击跨页面跳转聚焦正确
2. 上下文用量随 claude 工作推进而更新（事件驱动，非轮询）
3. claude 退出 → 行移除；全部退出 → 空态文案
4. 切换项目 → 视图内容切换到新项目
5. 未注入会话 → 行存在、🟡、用量条不可用态
