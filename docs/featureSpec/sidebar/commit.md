# Commit

> 拥有 Git 变更列表、过滤、只读导航和受限单行回滚／删除；仓库写入语义复用 PathPolicy 与 Document 守卫，不提供第二套 Git 工作流。

## 数据根与渲染态

- 数据根为活跃项目根所在仓库的实际 RepoRoot；项目根可位于仓库子目录，列表覆盖整个仓库工作区，路径相对 RepoRoot 显示。
- RepoRoot 只授予 Git 与相关文件读取，不单独授予写入或终端能力。破坏性操作按目标当前能力并集判定，不把“在仓库内”误当作可写。
- 无活跃项目显示无根态；首次加载或数据根变化显示加载态；读取失败显示分类错误；读取成功显示就绪态。四态互斥。
- 数据根变化立即清空旧列表、过滤、当前行和滚动，取消旧请求；不得短暂混入新项目数据。折叠和 ignored 显示偏好保留。
- 就绪刷新保留旧列表直到新结果返回；失败保留列表并显示“可能已过期”与重试，不变成空列表。
- 项目不是仓库、找不到 Git、权限不足、仓库损坏和根不可访问分别提示，不统一归因，也不自动 `git init`。

## 列表、过滤与排序

- 分组固定为 Changes、Unversioned Files，以及可选“已忽略”。不提供多选、批量回滚／删除、分页或浮动视图。
- Changes 包含已跟踪 added、modified、deleted、renamed、conflict 和未知状态；Unversioned Files 只含 untracked。列表展示合并状态，但回滚授权仍须区分 staged 与 unstaged。
- untracked 目录展开为文件行；嵌套仓库和子模块只显示顶层条目，不递归内部。renamed 只显示新路径一行，提示旧路径与新路径。
- 未知已跟踪状态使用中性“未知”标签并显示原始状态码；不伪造为修改或删除。
- 状态同时使用文字和主题语义色；每行显示图标、文件名、父目录后缀和完整路径提示。
- 过滤只匹配文件名和完整相对路径的大小写不敏感子串；renamed 不匹配旧路径，不支持正则、通配符或排除语法。
- 过滤同时作用于各组，计数等于过滤后条目数；不改变底层数据、排序和折叠。无匹配时保留组并显示空态。
- 各组按完整相对路径以固定 Unicode 规则排序，不依赖系统区域设置；renamed 使用新路径。
- 已忽略默认隐藏且不计数。开启后独立分区展示，目录不递归展开；忽略项只支持聚焦、过滤和复制路径，不打开、定位或执行破坏操作。
- 列表只保留当前数据根一份数据，大列表按可见区域渲染；读取和过滤不得阻塞前台。

## 刷新与可见性

- 监听 RepoRoot 内工作区文件及索引、HEAD 和引用；对象库与日志不单独触发。项目根外的仓库事件可触发刷新，但不扩大写授权。
- 文件事件尾部去抖 200 毫秒，连续事件最长 1,000 毫秒内至少复核一次；任意时刻最多一次读取，后续触发合并。
- 手动刷新通过按钮或 `F5`；进行中禁止重复，保留当前列表。视图重新可见时合并复核一次。
- 视图不可见时暂停监听并取消未触发计时；进行中的显式回滚／删除可完成并保留结果。关闭视图销毁实例和 watcher，重新打开重新读取。
- 监听不可用时显示“自动刷新不可用，可手动刷新”；不通过高频轮询伪装监听。
- 根重定位后 Commit 按新活跃项目根重新解析仓库；既有 Diff 与 GitShow 不因此改绑新仓库。

## 打开映射与身份

| 状态 | 打开结果 |
|---|---|
| added、untracked、unknown 且工作区文件存在 | 统一文件路由，普通 Document 视图 |
| deleted | 固定创建时仓库、HEAD 提交版本和路径的 GitShow |
| modified、renamed、conflict | 绑定仓库与工作区 Document 的 Diff |
| unknown 且文件不存在 | 提示并不创建 Panel |
| ignored | 不打开 |

- modified／renamed／conflict 的工作区侧直接引用共享 Document；已有未保存文本时不得重新读盘形成第二份缓冲。
- renamed Diff 保留 HEAD 旧路径与工作区新位置；conflict 只显示冲突文本，不提供三方合并或自动解决。
- deleted GitShow 捕获创建时 HEAD；之后 HEAD 移动或根重定位不改变其版本。
- 重复打开按目标 `ViewKey` 聚焦；普通文档、Diff 与 GitShow 是不同逻辑视图，不靠标题后缀建立身份。
- 落点为活跃项目聚焦 PanelGroup，无组则创建首组；不跨项目聚焦。激活期间项目切换则放弃并提示。
- 目标只有 RepoRoot 读授权时以只读方式打开；另一有效根授予写能力时按能力并集处理，不额外制造根外独立缓冲。
- 文件消失、内容不可读或创建失败时显示错误并刷新；显式新建失败不留空 Panel。

## 菜单、定位与复制

- 除 unknown 外，行可通过右键或 `Shift+F10` 打开菜单；菜单依次提供定位、复制路径和按状态可用的破坏性操作。
- “在文件浏览器中显示”要求工作区目标存在且位于当前 ProjectRoot；renamed 定位新路径。定位不自动改变 Explorer 的过滤或忽略设置。
- deleted 或目标不存在时定位禁用并说明；无权限或项目已变化时不发起请求。
- “复制路径”复制该条目的绝对工作区路径；deleted 可复制记录中的预期路径，即使当前不存在。成功、失败均非阻塞反馈，不复制文件正文。
- ignored 只提供复制路径；unknown 不提供上下文菜单，仍可按打开映射激活。
- 无可写能力的条目保留破坏性菜单项但禁用并说明；不得只因 RepoRoot 可写之外的项目根外位置就覆盖另一有效根的授权判定。

## 受限回滚

### 可用范围

- 回滚只放弃未暂存工作区变化，并从当前索引恢复工作区；**不得把索引重置到 HEAD**。
- modified：仅在存在未暂存修改时可用。若同时有 staged 修改，回滚后工作区匹配索引，staged 差异保留。
- deleted：仅在删除尚未暂存时可用，从索引恢复文件；若索引包含 staged 内容，恢复的是该索引版本。
- renamed：只有能够确认重命名尚未暂存、索引仍保存原路径时才可提供；staged rename 不提供通用回滚。
- 纯 staged 修改或删除没有可放弃的未暂存变化，回滚禁用并说明；conflict 一律不提供通用回滚。
- added 不走回滚；其删除是下节独立操作。ignored 与 unknown 不提供回滚。
- 无法可靠区分 staged／unstaged 或状态超出上述精确形态时，默认禁用并引导刷新或使用终端，不执行猜测性 Git 命令。

### 确认与执行

- 确认框显示完整路径、将丢弃的未暂存变化和“从索引恢复工作区，索引不变”；明确操作无应用内撤销，默认焦点在取消。
- 目标存在打开的脏 Document 时，先进入该 Document 的保存／丢弃／取消守卫；取消或保存失败不执行 Git 操作。守卫完成后重新读取状态并再次确认目标仍符合原操作。
- 执行前重读索引与工作区状态、真实路径和写授权；状态或路径变化则中止并提示刷新。不得以打开菜单时的旧状态作为执行依据。
- modified／deleted 只写工作区，不改索引。成功后所有引用该 Document 的干净视图按统一外部修改规则更新；不得建立独立回滚缓冲。
- 未暂存 renamed 的回滚从索引恢复旧路径，并清除新路径工作区条目；不改索引。新路径清除失败按部分成功报告并刷新，不通过修改索引掩盖残留。
- 符号链接按 Git 条目本身处理，写前仍经 PathPolicy 重解析；不得跟随到未授权目标。
- 操作串行、可审计，结束后无论成功或失败都刷新真实现状；部分成功必须列出已完成与未完成部分。

## added 与 untracked 删除

- untracked 删除优先移入 Windows 回收站；确认中说明回收站恢复路径。回收站不可用时，只有再次明确披露并确认后才永久删除。
- staged added 可在确认中明确“先取消暂存，再移入回收站”后执行；该索引修改属于删除操作的独立步骤，不是回滚。
- 取消暂存失败时不得移动或删除文件；取消暂存成功但删除失败时按部分成功报告，文件以 untracked 留存。
- 执行前重新校验状态、路径与授权；目标已不存在时刷新并提示，不伪造回收站结果。
- 符号链接只处理链接项本身且不得越过 PathPolicy；无应用内撤销，回收站恢复由系统提供。
- 删除优先回收站并不允许静默回退永久删除；实际采用的方式必须在结果中说明。

## 状态与生命周期

| 状态 | 关闭视图后重开 | 应用重启 |
|---|---|---|
| 分组折叠、已忽略分区折叠、ignored 开关 | 恢复 | 恢复同一状态 |
| 滚动位置 | 恢复并夹取到有效范围 | 恢复同一位置并重新校验 |
| 列表数据 | 重新读取 | 重新读取 |
| 过滤、当前焦点行、菜单、确认框、通知、错误和刷新警告 | 清除 | 清除 |
| 进行中的读取代次 | 取消旧实例任务 | 不恢复 |

- 折叠、ignored 和滚动属于该逻辑视图的 `ViewKey` 状态；两条恢复路径不得采用不同口径。
- 显式隐藏整个侧栏不销毁实例，可保留当前列表和过滤等运行态；不可见期间仍暂停监听。
- 切换项目是数据根变化，不是普通关闭重开：过滤、当前行和滚动清空，旧读取结果丢弃。
- 破坏性操作已获确认并开始后可跨视图隐藏完成；结果不写入新项目列表，也不因界面关闭而丢失审计或错误。

## 键盘与错误

- 单击只聚焦，双击或 `Enter` 打开；分组标题用 `Enter`／`Space` 折叠。方向键跨组移动，Home／End 到首尾，`Ctrl+F` 聚焦过滤，`F5` 刷新。
- 菜单关闭后焦点回到原行或最近可见行；模态确认默认安全操作，IME 与减少动效遵循跨域规则。
- 错误区分根不可访问、非仓库、Git 缺失、权限、仓库损坏、索引锁和文件占用；均提供可执行恢复路径。
- 日志与审计只记录操作、路径、来源、结果和必要指纹，不记录文件正文、差异正文或凭据。

## 验收判据

- **Given** 文件同时含 staged 与 unstaged 修改，**When** 回滚，**Then** 工作区恢复为索引内容，staged 差异保留，索引未重置到 HEAD。
- **Given** 纯 staged 修改、staged rename 或 conflict，**When** 查看回滚，**Then** 不提供可执行通用回滚，并说明没有可用操作或状态受限。
- **Given** deleted 尚未暂存且索引含 staged 内容，**When** 回滚，**Then** 从该索引版本恢复，而不是从 HEAD 恢复。
- **Given** 未暂存 renamed，**When** 回滚，**Then** 旧路径从索引恢复、新路径工作区条目清除且索引不变；失败按部分成功显示。
- **Given** 目标 Document 有未保存修改，**When** 回滚，**Then** 先完成保存／丢弃／取消守卫；取消时磁盘和索引均不变。
- **Given** 从 Commit 打开已有脏 Document 的 Diff，**When** 对比工作区，**Then** 使用共享实时文本，不读盘生成独立缓冲。
- **Given** GitShow 创建后 HEAD 前进或项目根重定位，**When** 刷新，**Then** 仍读取创建时固定版本。
- **Given** staged added 删除，**When** 用户确认，**Then** 先取消暂存再进回收站；第一步失败时文件不动，第二步失败显示部分成功。
- **Given** untracked 所在卷无回收站，**When** 删除，**Then** 只有再次明确确认永久删除后才执行，不静默回退。
- **Given** RepoRoot 只读但另一有效根授予目标写能力，**When** 执行合法回滚，**Then** 按能力并集判定；只有 RepoRoot 时禁用写操作。
- **Given** 菜单打开后状态从 unstaged 变为 staged，**When** 确认执行，**Then** 写前重检中止并刷新，不执行旧回滚。
- **Given** 折叠、ignored 和滚动已改变且过滤与错误存在，**When** 关闭重开或重启，**Then** 两条路径均恢复持久项并清除过滤、错误、菜单和焦点。
