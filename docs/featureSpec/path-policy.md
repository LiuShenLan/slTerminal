# 路径与授权

> 拥有路径身份、操作级授权、根能力并集、显式会话授权与根重定位契约；各功能篇只声明请求的操作，不另建越界例外。

## 路径身份

- **词法路径**用于项目唯一性、历史归属和展示；Windows 下统一绝对路径与分隔符，并按平台规则比较大小写。
- **规范路径**解析符号链接、目录联接等重定向，用于包含性与授权判断。
- **文件身份**在文件系统支持时由卷与稳定文件标识确定，用于合并硬链接等别名；不支持时退回规范路径，并保留保存前冲突检测，不宣称能识别全部别名。
- 新增项目或重定位根时同时检查词法唯一性与真实目标查重；无法完成真实路径查重时拒绝操作，不以“可能未重复”继续。
- 项目根暂时不可访问不改变 `ProjectId`，也不自动把项目改绑到另一目录。

## 授权来源与能力

授权按操作分别判定，不因“能读”推导“能写”，也不因“能浏览”推导“能作为终端 cwd”。

| 来源 | 默认能力 | 持久性 |
|---|---|---|
| ProjectRoot | 读取、项目内写入、终端 cwd、启动恢复 | 随项目持久化 |
| RepoRoot | 仅 Git 与相关文件读取；不单独授予写入或终端能力 | 随可解析仓库关系持久化 |
| AgentRoot | 默认只读、禁止终端；写入与终端须分别显式开启 | 随根注册持久化 |
| 根外显式读取 | 仅用户当次选择的文件读取 | 仅当前运行期 |
| 另存为目标 | 仅当前 Document 对选定目标的写入 | 仅当前运行期 |
| 显式输出目标 | 仅当次导出、备份或诊断对用户选定单文件目标的写入 | 仅当次操作 |
| 内置 CLI 声明目标 | 仅对应 Hooks、历史记录等内置集成明确声明的文件与操作 | 随集成能力有效，操作前重检 |

- 操作只要仍被至少一个有效根授权即可执行；嵌套根采用能力并集。只读根不授予写能力，也不抹除另一独立根的既有授权。
- 同一真实目录只允许一个 Agent 根；重复别名不得形成多份能力或树节点。
- 删除根立即撤销其授权，并取消该根后续自动读取、刷新与写入。
- Document 失去读取授权后保留已加载内容与编辑状态，停止自动刷新；失去写入授权后禁止原地保存，但仍可另存为。
- 根外显式读取不扩大到同目录其他文件、Markdown 资源、文件树或终端 cwd。
- 显式输出目标不授予目录或其他文件能力，不得被后续操作静默复用；目标已存在时仍须按对应功能确认覆盖并原子写。
- 内置 CLI 声明目标必须收敛到固定能力清单和最小路径集合：Hooks 只能读写声明配置及托管材料，历史集成只能读取、隔离和按守卫恢复声明记录；均不派生任意文件或终端能力。

## 操作判定

| 操作 | 授权规则 |
|---|---|
| 自动打开与启动恢复读取 | 仅持久授权可自动读取；会话级根外授权不跨重启。 |
| 原地保存 | 写前重新解析真实目标；当前 Document 必须仍有该目标写授权。 |
| 文件树新建、移动、重命名、粘贴、删除 | 每个源与目标分别校验所需能力；批量操作不得把一项授权扩展给其他项。 |
| 终端 cwd | 必须由允许终端的有效根授权；显式 cwd 无效时拒绝，不改投其他目录。 |
| Markdown 本地资源 | 每个资源独立取得持久读取授权；根外文档被打开不等于其资源获批。 |
| Markdown 显式本地文件链接 | 用户点击可授予该文件会话级只读；不授予写入与资源读取。 |
| Runtime 与第二实例 | 复用同一判定，不因调用来源获得额外能力。 |
| 普通导出、加密备份与诊断输出 | 仅写入用户当次选择的单文件目标，先完整校验再原子替换。 |
| Hooks 与历史会话集成 | 只执行内置 CLI 声明目标所需的精确操作，历史隔离与撤销还须通过版本对账。 |

- 设备路径、盘符相对路径不作为隐式授权输入；UNC 只有在真实目标获得授权时才允许。
- 敏感操作前重新解析真实目标。链接重定向不得继承旧路径授权；已打开 Document 因此进入位置冲突并暂停原地保存，直至用户重新确认有效目标。
- 保存、删除、回滚等操作除了路径授权，还须通过对应的版本对账、确认和审计规则。

## 根重定位与撤销

根重定位只改变 ProjectRoot 与项目的关联：

- 不移动文件，不按相对路径重绑既有 Document，不重建面板，不改变 `ProjectId`。
- 立即重新计算所有操作授权；失去读取授权的内容保留但停止刷新，失去写入授权的内容只能另存为。
- Diff 不得改用新仓库中同相对路径的 HEAD；GitShow 继续使用创建时固定的仓库、版本和路径。
- Hooks Project／Local 草稿先完成保存／丢弃／取消守卫；取消或保存失败则不重定位。
- 既有 PTY 不终止、不改变 cwd；之后的新终端使用新根。
- 启动恢复中的终端旧 cwd 在新根下无授权时，可回退新根并明确提示；显式新建终端不采用此回退。

根删除与重定位不同：删除立即撤销能力，不把“重定位后的新根”当作旧授权的延续。

## 启动与异常恢复

- 仅 ProjectRoot、RepoRoot 的只读范围和有效 AgentRoot 等持久授权可以触发自动读取。
- 启动恢复只自动读取具有持久授权的磁盘正文。仅持有会话级根外读／另存为写授权，或原授权根已失效的面板，在正常重启后恢复“需要重新授权”占位，不读取磁盘；用户重新授权后才加载。
- 异常退出若存在有主 Document 快照，仍按崩溃恢复契约对账并恢复未保存文本；快照恢复不重新授予磁盘读取、刷新或写能力，未获持久授权前不得自动重读磁盘。
- 异常启动存在 Document 快照时，先恢复布局并对账未保存文本，不先用磁盘内容覆盖快照。
- 无法完成授权判定时默认拒绝对应操作，并保留明确重试或重新授权入口。

## 验收判据

- **Given** 同一文件经硬链接或不同词法路径打开，**When** 文件系统提供稳定身份，**Then** 全应用复用同一 Document；不支持身份时按规范路径去重并保留保存冲突检测。
- **Given** 一个只读根与另一个可写根覆盖同一目标，**When** 保存，**Then** 可写授权仍有效；删除可写根后立即禁止原地保存。
- **Given** 根内链接在打开后重定向到根外，**When** 保存或删除，**Then** 写前重新校验并拒绝继承旧授权。
- **Given** 根外文件经 Markdown 链接打开，**When** 正常重启应用，**Then** 只显示重新授权占位，未授权前不读取磁盘。
- **Given** 根外 Document 只有会话级授权且异常退出前留有快照，**When** 异常启动，**Then** 可恢复未保存文本但不自动重读磁盘，也不恢复刷新或写授权。
- **Given** Document 已加载后失去读取授权，**When** 磁盘继续变化，**Then** 内容保留且停止刷新；仍可按写授权情况另存为。
- **Given** 项目根重定位到另一仓库，**When** 查看既有 Diff 与 GitShow，**Then** 不使用新仓库同相对路径内容替代原绑定。
- **Given** 新增项目或重定位时无法完成真实路径查重，**When** 提交，**Then** 操作被拒绝且原项目关系不变。
