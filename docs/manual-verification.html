V1 · 「版本过旧」→ 重新注入 → 用量条链路 Stage 03

验证什么

Stage 03 将 reporter 的 SCRIPT_VERSION 从 2 升到 3（键名 transcriptPath → usageSourcePath 全链路更名）。已注入用户（如你当前环境）打开 app 应显示「版本过旧」，点击注入后升级为 v3 并恢复用量条链路（决策 7 先例路径）。

前置条件

  • 前置步骤已全部完成；reporter 文件确认仍为 SCRIPT_VERSION = 2

操作步骤

  1. 启动 slterminal.exe，打开 hooks 配置面板（工具栏 hooks 按钮——F6 注入入口并入的位置）
  2. 观察注入状态条（编辑器工具栏上方）——当前应为「注入状态：版本过旧」（警示色）
  3. 点击「注入」按钮，等待状态条变化
  4. 核对文件版本：Select-String SCRIPT_VERSION C:\Users\liush\.slterminal\hooks\slterm-hook-reporter.js —— 应为 3；并确认新脚本含 usageSourcePath（Select-String usageSourcePath 同路径）
  5. 用量条链路实测：在终端页签运行 claude，进入会话并让它完成一个小任务（如「输出 hello」），打开侧栏 Agent Status 视图观察会话行
  6. 信号驱动确认：会话期间检查 ~/.slterminal/hooks-events/ 目录短暂出现 .json 信号文件（被 watcher 消费后删除属正常）
期望结果：
  • 注入前状态条 = 「注入状态：版本过旧」；点击注入后 = 「注入状态：已注入」
  • reporter 文件 SCRIPT_VERSION = 3，且 payload 键为 usageSourcePath（不再有 transcriptPath）
  • Agent Status 会话行显示上下文用量百分比（如「50%」），随会话推进更新；用量条不是「--」占位
失败判定与处理： 注入后状态条未变 / 文件仍 v2 / 用量条不更新 —— 截图控制台报错（WebView2 F12），在 docs/review-fix/ 下记录问题反馈；不要回滚代码。

V2 · null 映射事件首达 → 侧栏无图标行 Stage 02

验证什么

Stage 02（ZQ-3 决策 2）：普通 Notification 类事件（claude 策略映射 status = null）首达时建行但不设状态图标——感知会话存活（SessionStart 丢失场景）且不误标 🟡。视觉确认：Agent Status 侧栏出现无图标的行。

前置条件

  • V1 已通过（reporter v3 注入完成，事件映射链路可用）
  • 已打开一个项目页面（Agent Status 视图依赖项目上下文）

操作步骤（方式 A：自然触发，推荐）

  1. 打开 Agent Status 侧栏视图（活动栏 Agent 状态图标）
  2. 在终端运行 claude，完成一个小任务；claude 会话中会产生 Notification 类事件
  3. 观察侧栏：会话进行中/结束后行存在；若该会话首达事件为 null 映射（普通通知），行应无状态图标

操作步骤（方式 B：信号文件精确注入，可复现）

  1. 终端运行 echo $SLTERM_PANEL_ID，记下 panelId
  2. 确认事件目录：New-Item -ItemType Directory -Force $HOME\.slterminal\hooks-events
  3. 构造信号文件（文件名格式 <panelId>-Notification-<毫秒时间戳>.json）：
{
  "event": "Notification",
  "sessionId": "manual-null-test",
  "timestamp": 1786000000000,
  "cwd": "D:/你的项目路径",
  "toolName": null,
  "notificationType": "info",
  "cliId": "claude",
  "panelId": "<上面记下的 panelId>"
}
  1. 保存为 ~/.slterminal/hooks-events/<panelId>-Notification-<时间戳>.json（watcher 3 秒轮询消费）
  2. 打开 Agent Status 侧栏，等待几秒，观察是否出现 manual-null-test 行
期望结果：
  • 侧栏出现会话行（标题按 cwd 或回退链显示）
  • 该行状态列空白（无 ⚡ / 🟡 / ✅ / ❌ 任一图标）——即「感知存活但不误标」
  • 方式 B：信号文件被消费删除（目录无残留）；行在会话结束后按既有规则消失
注意：方式 B 的 notificationType 填 info（普通通知）；若该值映射出图标（如变体映射 attention/error），改用 info 之外的普通形态或方式 A 自然触发。行显示「无图标」即通过，出现 🟡/⚡ 即失败。

V3 · hub 面板 claude 编辑器分派全链 Stage 04

验证什么

Stage 04（KZ-1）后，hub 编辑器槽经 profile.capabilities.hooks.configEditor 分派渲染 claude 专属编辑器；Stage 05（KZ-7/CS-3）补了 mockcli 双向分派（L4 已覆盖）。人工验证真实 claude 编辑器的全链路：选择行 → 分派渲染 → 层切换 → GUI/JSON → 保存写盘 → 注入三态 → dirty 守卫。

前置条件

  • V1 已通过（已注入 v3）

操作步骤

  1. 打开 hooks 配置面板：选择行应渲染 claude 按钮（claude logo 16×16 + displayName「claude」）
  2. 编辑器分派：点击选择行（或保持默认选中）——编辑器槽渲染 claude 编辑器（非空态占位；面板无「该 CLI 未提供配置编辑器」字样）
  3. 层切换：依次切 user / project / local：
    • user 层：任何时候可用
    • project / local 层：项目打开（rootPath 就绪）后按钮才可点；无项目时禁用（提示需项目路径）
  4. GUI 模式编辑：任选一层，添加一个 hooks 条目（如 SessionStart → echo 命令），观察表单联动
  5. JSON 模式：切到 JSON 模式，确认编辑区渲染（悬停/波浪线提示可用；无自动补全属预期——2026-08-01 验收决策）
  6. 保存写盘：点击「保存」→ 按层核对磁盘文件：
    • user 层 → ~/.claude/settings.json 的 hooks 子树被替换（merge 保留 permissions/env/$schema 等其他字段）
    • project 层 → 项目 .claude/settings.json
  7. 重启提示：保存后出现重启提示条（「重启 claude 生效」类文案）
  8. 注入/卸载三态：工具栏「注入」→ 状态条「已注入」；「卸载」→「未注入」（hooks 从 settings.json 移除）；再「注入」→「已注入」（恢复）
  9. dirty 守卫：修改内容未保存 → 切换 CLI / 关闭面板 → 出现未保存确认弹窗
  10. 控制台检查：F12（WebView2 DevTools）确认无报错/警告堆积
期望结果：
  • 选择行仅渲染 claude（一个按钮）；编辑器渲染正常，无空态占位
  • 三层切换正常；project/local 无项目时禁用
  • 保存真实写盘且 merge 保留其他字段（不整体覆盖文件）；重启提示出现
  • 注入/卸载三态流转且互不残留；dirty 守卫弹窗触发
  • WebView 控制台无 JS 报错
失败判定与处理： 分派未渲染（出现空态占位）→ 检查是否选中了非 claude 项；保存未写盘 → 检查层对应文件路径；其余异常截图记录反馈。
