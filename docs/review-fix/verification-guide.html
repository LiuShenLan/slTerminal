验证 1｜S01 E2E 全量实跑

1Stage 01 依赖安全排雷npm run e2e
验证什么

WDIO 9.28→9.30.1 + tauri-plugin 1.3.0 大版本升级后，embedded 驱动链路完整可用（升级后自动化门禁只覆盖到 build:e2e，真正跑通 E2E 需人工）。

怎么验证
  1. 确认工作树干净、main 分支为最新（5e2a4f2）。
  2. 在项目根目录运行 npm run e2e。
  3. 等待全部 spec 执行完毕（约 5-10 分钟，单实例串行）。
期望结果
  • 全部 E2E spec 通过：terminal(7) / editor(5) / html(1) / sidebar(2) / commit(2) / hooks(5) / agent(6) / history(7) / mockcli(3)，合计约 38 条 active。
  • 无驱动层批量超时（全部 spec 卡「Workspace 未就绪」= helper 被 tree-shake，属构建问题）。
失败处置

若全部超时：确认是 npm run e2e（VITE_E2E=1）而非裸 tauri build；若单条失败，查看 wdio 报告定位（WDIO 升级后多为测试自身时序问题，参照修复循环先例）。

验证 2｜S03 白名单后全功能实测

2Stage 03 命令白名单化（SEC-07）高风险
验证什么

34 条命令白名单（build.rs AppManifest + capabilities 逐条 allow）生效后，前端所有功能路径仍可正常 invoke。白名单配置错误的表现是 invoke reject（权限不足报错），而非功能静默失败。

怎么验证
  1. 启动 debug 构建产物，创建/打开一个项目。
  2. 终端：默认 shell（pwsh）正常启动；输入命令（如 dir）有回显；claude 可启动。
  3. 文件：文件浏览器展开目录、打开一个 .ts 文件、编辑后 Ctrl+S 保存成功。
  4. git：在有变更的仓库中打开 Commit 面板，变更列表正确；双击 modified 文件打开 diff 面板。
  5. hooks：活动栏底部「配置」打开 hooksConfig 面板，能读取 user/project/local 三层。
  6. 历史：导航树历史区能展开扫描出会话。
  7. 如已执行验证 1，确认 E2E 全量通过（权限缺失会表现为 invoke reject）。
期望结果
  • 上述 5 条功能路径全部可用，无任何 invoke reject / 权限报错。
  • 开发者工具 Console 无 not allowed / ACL 类错误。
失败处置

某条路径报权限拒绝：对比 src-tauri/build.rs 的 commands 清单（34 条）与 src-tauri/capabilities/default.json 的 allow- 条目（34 条）是否一一对应；补缺后重建。

验证 3｜S05 大仓库 watcher 事件量

3Stage 05 watcher 排除与生命周期（BE-02）
验证什么

事件侧排除大目录（node_modules/target/.venv/dist 等七元素）后，大仓库的文件变更刷新正常且 CPU/事件量显著下降。

怎么验证
  1. 打开一个含 node_modules / target 的大仓库（本仓库即满足条件）。
  2. 打开文件浏览器，任务管理器观察 slterminal CPU 占用约 30 秒（基线）。
  3. 修改 src/ 下任意文件 → 文件树应刷新（含 git 状态色变化）。
  4. 在 node_modules/ 下创建/修改一个文件 → 文件树不应刷新、CPU 不应有波动。
期望结果
  • 正常文件变更仍即时刷新（300ms 内）。
  • 排除目录内变更不触发任何刷新；CPU 空闲占用明显低于旧行为。
失败处置

排除目录变更仍触发刷新：检查 WATCH_EXCLUDE_DIRS 是否在事件循环生效（notify/mod.rs）；该修复正确性由 L1 测试锁定，手工验证主要确认真实大仓库场景无回归。

验证 4｜S06 claude 高输出流畅度 + 滚轮 + kill

4Stage 06 PTY reader 微批（BE-05/06）高风险·异常即回滚
验证什么

reader 微批（读到即续读，64KB 累积发送）不引入可见延迟；kill 加固（3s join 超时）后 kill 路径可靠。这是终端核心数据路径，流畅度只能实测兜底。

怎么验证
  1. 启动终端并运行 claude，发起长流式回复（如「写一篇 2000 字文章」）；或运行 Get-Content big.log -Tail 100000 类高输出命令。
  2. 观察输出滚动流畅度——逐行流畅出现，无停顿后突涌。
  3. 输出过程中快速连续输入字符，确认无吞输入。
  4. 鼠标滚轮上下滚动终端缓冲区，确认滚动正常。
  5. 运行 claude 时关闭终端页签（kill 路径），再确认无残留进程（配合验证 8）。
期望结果
  • 高输出流畅无卡顿；输入无丢失；滚轮滚动正常（ConPTY flags 仍 0x7，未受本 Stage 影响）。
  • kill 后终端关闭干净。
失败处置（重要）：批处理引入任何可见延迟 / 吞输入 / 滚轮异常 → 回滚本 Stage 并重建：
git revert 3e30ab6 → npx tauri build --debug --no-bundle → 重测本项。

验证 5｜S07 大文件打开 / 超限拒绝

5Stage 07 fs_read_file 分块（BE-03）
验证什么

Channel 分块推送（256KB/块）后，接近 10MB 大文件正常渲染无卡顿；超 10MB 拒绝行为不变。

怎么验证
  1. 生成近 10MB 文本文件（PowerShell）：
1..450000 | ForEach-Object { "line $_ - some content to pad out the line length" } | Out-File -Encoding utf8 big.txt
# 约 11-12 MB？过大则减少行数；目标 ≈ 8-9 MB（如 350000 行）
  1. 在文件浏览器中打开 big.txt → 编辑器应完整渲染，滚动流畅。
  2. 生成超过 10MB 的文件（1..500000 | ...）→ 打开 → 应被拒绝。
期望结果
  • 近 10MB 文件正常打开、内容完整（无截断/乱码，含中文行）、滚动无卡顿。
  • 超 10MB 文件打开被拒，提示「文件过大（超过 10MB 上限），已拒绝打开以保护内存」。
失败处置

大文件渲染异常（乱码/截断）：检查 UTF-8 边界回退逻辑（fs/mod.rs 分块读取）；超限未拒绝：检查 MAX_FILE_SIZE_BYTES 校验仍在 metadata 阶段执行。

验证 6｜S09 损坏配置 toast + 默认值兜底

6Stage 09 corrupted 契约（BE-14/FE-11）
验证什么

持久化损坏可感知：settings.json 损坏时启动 toast「配置已损坏，已回退默认值」+ 默认值兜底；.bak 恢复路径同样 toast。

前置：先备份用户配置——Copy-Item ~/.slterminal/settings.json ~/settings.json.bak-manual（验证完成后恢复）。
怎么验证
  1. 手改 ~/.slterminal/settings.json 为非法 JSON（如内容写 {invalid），保存。
  2. 启动 slterminal → 观察右下角 toast 与启动行为。
  3. 关闭应用，再测 bak 路径：删掉 settings.json（或把 .bak 改成非法 JSON），启动 → 同样应 toast 且默认值兜底。
  4. 验证完成后恢复备份文件。
期望结果
  • 启动出现 toast「配置已损坏，已回退默认值」；应用正常启动，使用默认配色/字号（无崩溃、无空白页）。
  • bak 命中时同样 toast（数据来自备份也算损坏）。
失败处置

无 toast 或启动异常：检查 load_settings 返回结构（{data, corrupted}）与前端四 store 消费；损坏文件不会抛异常（走 corrupted 通道）。

验证 7｜S12 WebGL 焦点切换 + 20 页上限

7Stage 12 前端性能（FE-34/FE-01）
验证什么

FE-34：焦点切换不再创建/释放 WebGL 上下文（addon 常驻）——多终端快速切换无白屏/无上下文压力异常；FE-01：页面总数上限 20，第 21 页拒绝并 toast。

怎么验证
  1. 打开 2-3 个终端页签，快速连续点击切换焦点，观察终端渲染。
  2. （可选）任务管理器观察 GPU 内存，或 WebView2 进程内存是否随切换稳定。
  3. 不断新建页面（终端/编辑器均可）直到第 20 个，再尝试创建第 21 个。
  4. 切换侧栏视图（导航树 ↔ 文件 ↔ Commit），观察行为。
期望结果
  • 多终端焦点快速切换：渲染正常、无白屏、无闪烁，上下文不反复创建（GPU 内存稳定）。
  • 第 21 页创建被拒 + toast「页面数已达上限」，已有页面不受影响。
  • 侧栏视图切换：旧视图卸载（组件状态丢失属 ADR-0001 已接受行为，非缺陷）。
失败处置

若实测发现多上下文压力（白屏/崩溃）：FE-34 设计留有回退——恢复「焦点切换释放」逻辑并登记（见 useXterm.ts 注释）；页数上限若失效检查 projects.ts addPage 校验。

验证 8｜S13 关窗 PTY 子进程全灭

8Stage 13 稳定性（BE-08 pty_kill_all）
验证什么

关闭窗口后无残留 pwsh/cmd 子进程：前端 Registry 快速 kill + 后端 pty_kill_all 兜底 + Job Object KILL_ON_JOB_CLOSE 三层保障。

怎么验证
  1. 启动 slterminal，打开 1-2 个终端（确认 pwsh 进程存在），其中一个运行 claude 或长时间运行的命令。
  2. 直接关闭窗口（右上角 X）。
  3. 任务管理器确认无残留 pwsh / cmd / claude 子进程（等待 3-5 秒让 kill 序列完成）。
期望结果
  • 关窗后 3-5 秒内子进程全部消失，无残留。
失败处置

有残留：检查关闭序列（App.tsx）是否调 ptyKillAll() 兜底（S13 新增）；Job Object 为最终兜底，若仍泄漏需查 spawn 侧 Job 关联。

面板崩溃隔离（FE-22 ErrorBoundary：单面板渲染抛错同页其他面板存活）由 L2 测试锁定，手工构造抛错面板较繁琐，如需要可用 DevTools 在面板组件内抛异常验证。

9Stage 15 dockview 6→8（TE-08）高风险

10Stage 16 CI 门禁（TE-13）git push

CI 新增三门禁在真实流水线中通过：npm audit --audit-level=high、npx knip --production、cargo audit。

验证 11｜S17 hooks 写入校验 + 确认弹窗

11Stage 17 hooks 安全（SEC-05）
验证什么

user 层写入 hooks 配置时二次确认弹窗；非法事件名/type/空 command 被后端拒绝（写入零副作用）。

怎么验证
  1. 打开 hooksConfig 面板，切换到 user 层（层切换按钮）。
  2. 修改配置（如加一条 hook）→ 保存 → 应弹确认框「确认写入用户级 hooks 配置 / hooks 可执行任意命令」。
  3. 点取消 → 不写盘（配置保持原样）。再保存 → 点确认 → 写入成功。
  4. 切到 project / local 层 → 保存 → 应直接写入、不弹确认。
  5. 手写非法事件名（如 Stop，不在 10 事件白名单）→ 保存 → 后端应拒绝并提示。
期望结果
  • user 层保存弹确认框；取消不写盘；project/local 层无确认。
  • 非法事件名保存被拒（Validation 错误提示），配置文件未被污染。
失败处置

未弹确认：检查 useHooksConfig save() 的 layer==="user" 分支；非法事件名未拒：检查 config.rs validate_hooks_semantics 接入点（写盘前校验）。

验证 12｜S18 万级节点目录（FileTree 虚拟化）

12Stage 18 FileTree 虚拟化（FE-30）
验证什么

手实现虚拟化（扁平化 + 固定行高 + overscan 窗口）后，万级节点目录展开/滚动/键盘导航/文件操作流畅，行为（右键菜单/选中模型/重命名）不回归。

怎么验证
  1. 打开含万级节点的目录——最现成的是展开任意项目的 node_modules（数万节点）。
  2. 展开大目录 → 首屏渲染应秒开（不再全量渲染）。
  3. 快速滚动列表（滚轮/拖动滚动条）→ 流畅无卡顿。
  4. 键盘上下键导航（需先聚焦文件树）→ 选中行随窗口移动正确。
  5. 右键文件 → 菜单正常；重命名/新建/删除 → 树刷新正确。
期望结果
  • 万级节点展开/滚动流畅，DOM 行数远小于节点总数（窗口化生效）。
  • 键盘导航、右键菜单、选中、重命名/新建/删除全部正常。
失败处置

滚动异常/空白跳变：检查窗口切片与 padding 占位计算（FileTree.tsx）；行为回归（菜单/键盘）优先对照既有 L2 用例，确认是真实回归再修。
