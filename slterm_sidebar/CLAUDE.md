# slterm_sidebar（core 层）

> 纯文件树与侧栏状态核心。

## 决策与红线

- **纯侧栏边界**：只承载文件树与侧栏状态。原因：树结构和视图状态须可独立验证。边界：文件树与侧栏状态均保持纯数据和纯转换，不得引入副作用。
- **侧栏组织单点**：可见性意图与实际可见性分离，实例创建、销毁和视图送焦只经转换效果通知宿主。原因：关闭最后视图、显式隐藏和隐藏按钮具有不同生命周期，宿主不得再次推断。边界：同槽替换才关闭旧实例，跨槽交换保留双方实例；窗口临时压缩不得回写用户宽度，各视图私有状态不由框架复制。
- **侧栏组织规范 DTO**：使用独立版本、封闭 `kind`、确定键序和精确字段集；解码后重新校验按钮注册完整性、槽位与几何不变量。原因：持久字节必须可重放，损坏与未知类型不得被静默当成有效状态。边界：严格 DTO 不过滤未知视图、不去重、不夹紧尺寸；容错恢复必须作为独立转换显式报告修复。
- **SideView 私有状态 schema**：四种视图按完整 ViewKey 分派各自精确字段集；Project／AgentRoot 分区身份与相对路径记录确定排序且禁止重复，滚动只接受非负有限逻辑像素。原因：应用级 ViewKey 下的分区和恢复字节不得发生静默覆盖或跨视图套用。边界：搜索、多选、焦点、错误等瞬态字段不得登记；缺失路径与失效根的存在性过滤属于恢复转换，不由严格 schema 伪装为损坏或默认状态。
- **强类型运行态单源**：`SideViewState` 的四种变体直接复用所属 schema 的私有 DTO，编码与恢复必须经过同一注册表并校验完整视图身份。原因：运行态不得另建字段定义或绕过规范校验。边界：字段变更与 Project／AgentRoot 分区删除只经强类型状态进入 ViewState，application 不自行拼装持久 JSON；删除缺失身份必须报告未变化，AgentFiles 被删根的当前行同时清空。

## 验收与测试

- 定向测试：`cargo test -p slterm_sidebar --test lib_tests <filter> -- --test-threads=1`；禁止 `--lib` 或裸 filter 直打默认 lib target。
