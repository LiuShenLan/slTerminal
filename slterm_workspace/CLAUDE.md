# slterm_workspace（core 层）

> 稳定 ID、`ViewKey`、`ViewState`、布局 DTO 与关闭恢复的纯状态机。

## 决策与红线

- **纯工作区边界**：只承载稳定 ID、`ViewKey`、`ViewState`、布局 DTO 与关闭恢复状态机。原因：工作区身份、布局与恢复语义须保持单一权威。边界：上述能力必须保持纯状态与纯转换。
- **ViewState 注册解码**：DTO 使用独立版本与封闭 `ViewKeyKind`；各所属视图按 `ViewKeyKind` 注册接收完整 `ViewKey` 的原始 JSON 精确解码器，框架不开放任意持久字段。原因：同一类型的不同稳定身份可有不同持久字段，且重复字段不能先经 map 合并而被掩盖。边界：未知类型、未注册 schema、版本不支持、信封损坏和状态非法分别报告；ViewState 绑定完整 `ViewKey`，同类型不同身份不得交叉写入，作用域只由该键推导且不重复序列化，瞬态字段不得登记。
- **面板身份不持久化**：`PanelId` 由 application 注入的实例纪元与分配器单调序列组成；分配器不可复制，关闭不回收，耗尽禁止回绕。原因：存活实例不得与持久 `ViewKey` 混用。边界：不提供持久文本解析，布局与恢复材料只保存 `ViewKey`。
- **项目布局单点**：`ProjectLayout` 统一维护泛型树、非空组、组内顺序与激活项；拆分必须带落点内容，原组与新组均保留 120×80 逻辑像素，空组立即移除，禁止跨项目或重复 `ViewKey`。原因：布局身份与几何必须只有一个权威，恢复不得产生孤儿组或重复视图。边界：几何操作接收根 viewport，在候选树完成空组塌缩后校验最终叶子尺寸，轴向切割只经 `slterm_split`；规范 DTO 只保存 `groups + tree`、稳定 ID、比例、视图与激活关系，树和组记录必须一一对应，不保存 `PanelId`、焦点或运行实体。
- **项目聚合单点**：`ProjectRegistry` 按导航顺序持有稳定 `ProjectId`、`CanonicalPath`、显示名与独立 `ProjectLayout`；根路径不是身份，重复根只激活既有项，存在项目时恰好一个活跃项。原因：项目关联、导航与活跃关系不得在各视图分裂维护。边界：新增不自动创建面板；重命名去除首尾空白、拒绝空白与超过 80 字符的名称但允许重名；排序不改活跃项；移除活跃项依次选择下一个、上一个；重定位只替换根关联，冲突与失败不得部分改态。真实路径查重、Hooks 草稿与状态提交守卫由 application 在调用前完成，core 不执行 I/O。
- **ViewKey 规范 DTO**：使用独立版本、BTreeMap 键序和精确字段集；文件身份的 `u128` 部分使用规范十进制字符串，非 Unicode 路径拒绝编码。原因：逐字节重放与跨机恢复不能依赖 map 遍历、JSON 数值精度或有损路径转换。边界：未知 `kind` 与结构／领域损坏分别报错；恢复时重新校验全部领域值，`PanelId` 不进入 DTO。
- **固定 Diff 绑定 DTO**：与 ViewKey 各自独立版本；仓库路径与身份只经同一 crate 内编解码转换。原因：两种持久对象可独立演进，且不得产生第二份仓库身份事实。边界：固定旧路径与仓库绑定共同恢复，未知类型、版本与结构损坏分别报告。

## 验收与测试

- 定向测试：`cargo test -p slterm_workspace --test lib_tests <filter> -- --test-threads=1`；禁止 `--lib` 或裸 filter 直打默认 lib target。
